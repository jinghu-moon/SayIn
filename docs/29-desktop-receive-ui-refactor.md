# SayIn 桌面接收页重构

> 最新手机连接页与权限恢复见 [65 · 连接页重构](65-android-connection-page-refactor.md)。电脑批准、暂停与待核对仍沿用原安全语义。

日期：2026-11-13。状态：原生实现与自动化验证完成；真实手机到目标输入框验收按文末步骤进行。

设计依据：[接收页 demo](demos/sayin-receive.html)、[接收页设计](demos/sayin-receive-design.md)、[设备显示名称](24-android-device-display-name-plan.md)、[历史记录卡片](25-desktop-history-ui-refactor.md)。本轮不改造 Android 界面。

## 目标与根因

必要事实只有三个：首次连接需要建立手机身份信任；日常接收需要可用的通信通道；输入需要独立的本地闸门及结果核对。网络分类和网卡名称既不是手机身份，也不能代替输入授权。

原实现把启动监听、网卡选择、公用网络会话许可、打开配对窗口绑定在同一路径，导致恢复网络也进入配对流程。接收页还把说明、网络参数、输入状态和最近记录堆在同一视图。隐藏旧控件不能修复调用关系，因此本次同时重构呈现、监听生命周期和接收暂停原因。

## 升级前后

| 行为 | 修改前 | 修改后 |
| --- | --- | --- |
| 首次连接 | 先选择接口、视分类授权，再开启配对 | 自动选择可用路径，原位展示二维码或配对码，保留电脑本地批准 |
| 已配对启动 | 公用网络仍依赖本次会话许可 | 自动监听；没有新的配对邀请，不要求重新批准 |
| 手机在线 | 连接、输入、教程等信息混排 | 设备名称与在线状态、独立接收操作、最近一条记录 |
| 手机离线 | 网络准备与配对关联 | 明确等待再次连接，另行显示接收开启/暂停 |
| 网络范围变化 | 关闭服务并暂停，需手动准备网络 | 停止旧服务并后台重新检测；网络暂停可恢复为新输入范围 |
| 用户暂停/待核对 | 必须保留的输入边界 | 网络恢复不解除，不补输旧记录 |
| 网络配置 | 主流程必选项 | 正常自动处理，地址/分类/备用接口收进连接帮助 |
| 待核对原文 | 本轮原接收页没有原文展示 | 独立读取确切的最近 uncertain 记录，不依赖历史当前页；已删除时不替换成其他旧原文 |

手机发送文字后仍直接交由接收核心向执行时聚焦窗口提交输入事件，不经过桌面页面确认，不抢焦点、不自动回车。`submitted` 仅表示提交了系统输入事件，不能证明任意目标应用已经接纳文字。

## 原生界面

- 新增 `ReceiveView`，负责呈现、配对方式切换、连接帮助和历史入口；`ReceptionState` 继续独占应用接收生命周期和命令任务。
- 首次连接采用单一说明/邀请面板：宽窗口左右排列，窄窗口上下排列并滚动。二维码、配对码、待批准、邀请过期共用一个区域；不存在产品内场景模拟开关。
- 配对码采用等宽数字和地址，切换保留按钮身份与焦点；新邀请自动回到二维码。原生使用即时切换，没有照搬 HTML 的 240ms 横移动画。
- 已配对场景使用真实授权设备名称；连接状态与输入闸门分别展示。待核对优先提供本地核对操作，held 提供原因帮助，存储故障阻止接收。
- 最近记录只读取一条，复用原生历史卡片及真实应用图标提取，支持复制原文和按需详情；完整筛选、删除及撤销仍在历史页。
- 沿用 Yue 组件、Tabler、neutral、既有 `#1f75db` 品牌角色及功能色；中英文和明暗主题均保留。帮助弹窗支持 Escape 和焦点恢复。
- 删除旧网络许可、网络单选流程及对应废弃文案，不保留兼容层。设备身份、账本收据和历史不因界面重构而重置。

## 网络与输入边界

`NetworkBinding` 取代 `NetworkAuthorization`：表示一个经过 Windows 实际状态核对的绑定范围，不再表示用户授予公用网络权限。范围包括网卡 GUID、IPv4、Windows 网络 GUID/类别集合。公用、专用和域网络均可建立范围；无配置文件、loopback、未指定、链路本地及多播地址仍拒绝产品监听。

自动选择先考虑物理接口，同类接口中优先上次成功路径，再使用稳定顺序。绑定失败尝试其他候选；优先端口 7788，被占用时选临时端口。监听精确地址，不绑定通配地址。成功路径只保存非敏感的接口键，不保存信任/许可。多网卡的手机可达性无法仅靠本机枚举证明，帮助中保留备用接口操作。

启动前核对实际 Windows 快照，监听期间约每 2 秒核对一次，单次查询超时上限 3 秒。范围变化、查询失败/超时或监听停止均关闭输入闸门；退出旧监听前持久保存网络暂停。桌面后台约每 2 秒尝试恢复，无需反复点击。存在 OS 采样和调度窗口，不提供网络变更与输入原子联动保证。

接收核心新增 `network_lost`：只有原本正在运行的输入被标记为 `network_unavailable`；原有显式暂停、待核对等原因保留。恢复网络后只为后续新文字建立新的输入范围，旧 held 不释放。底层暂停代次继续阻止较早的恢复越过较新的暂停。后台恢复不会打开配对窗口，也不会强制切走历史页。

Windows 防火墙、访客网络隔离和跨网段路由仍是独立条件，软件不自动修改系统网络分类或防火墙。身份认证仍使用 CPace/二维码邀请、固定主机证书 TLS 和电脑本地批准，绝不将网卡发现视为手机已受信任。

**后续现状更新（2026-11-14）：** [40 自动发现与重连](40-paired-host-discovery-and-reconnect.md) 已在有效监听接口发布 IPv4 DNS-SD，Android 先连保存端点，失败后用有界系统 NSD 找回同一固定证书身份。完整认证后才持久更新端点；发现失败仍保留手机手动地址维护。本文原阶段只完成监听恢复，完整验证范围以 40 为准。

## 测试与证据

修改前运行全工作区测试建立 **104 项通过**的基线。修改后 **108 项通过，0 失败/忽略**；保留现有配对、认证、去重、输入、崩溃恢复、托盘、撤销设备、设置和历史回归，替换旧公用网络许可预期。

主要新增/更新覆盖：

- 自动优先物理路径和记住的有效路径；Public 不增加单选/许可确认，失效或伪造的绑定仍被拒绝。
- 真实 loopback 监听停止/重建：网络暂停恢复新范围、显式暂停保留、不重开配对、不切走历史页。
- 网络中断不解除 uncertain；不自动核对、不重放 held，后续明确的新文字正常执行。
- 核对原文不受最近 30 条历史限制；删除对应历史后不借用先前已核对的原文。
- QR 使用颜色图像与静区、整数物理像素模块；缓存复用、切换焦点、新邀请重置和关闭失效。
- 中英切换、帮助弹窗 Escape/焦点恢复、历史检索/复制/筛选/删除撤销、最小窗口布局。

## 真机测试步骤

1. 从托盘完全退出旧 SayIn，再启动 `desktop/target/debug/sayin.exe`。已有配对不删除；进入接收页应显示真实手机名称及等待重连，不能要求先选网卡或确认公用网络。
2. 手机与电脑处于同一局域网，打开手机 SayIn 并连接已配对电脑。接收页显示手机在线。切到记事本并将光标放入编辑区，从手机发送唯一文本；应输入一次、不自动回车，最近记录保存同一原文和实际目标程序。
3. 在电脑暂停接收，手机发送另一段文本；不能自动落字。恢复后不能补输旧文字；若有 held 阻断，先查看原因并等待其过期，再从手机发送一条新文字验证。
4. 暂时断开并恢复电脑网络，尽量保持原 IP/端口；接收页应先提示等待网络，后台恢复后等待手机重连，不弹配对。再重复一次主动暂停后断网，恢复后仍应暂停。端点变化时按 40 验证自动发现，失败时保留原身份并使用手动地址维护。
5. 若出现待核对，先到目标程序核对原文，再在电脑弹窗勾选确认并恢复；旧文字不得重发。不要为了测试故意在重要文档中制造不确定输入。
6. 调整到 720×540 及大窗口，切换中英和明暗；验证页面可滚动、按钮可访问、原文不变，连接帮助可用 Escape 关闭且焦点返回。
7. 需要测试首次连接时使用另一台未配对手机，或先在设备页明确撤销测试手机。首次应直接展示二维码；改用配对码时同一区域展示地址和代码。两种入口择一后都必须在电脑明确批准，拒绝/关闭邀请不得产生设备授权。
