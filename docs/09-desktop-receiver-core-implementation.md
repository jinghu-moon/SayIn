## 3. 接受、去重与执行边界

- JSON 最大 64 KiB、submit 最大 32 KiB；文本最多 4000 个 Unicode scalar、16 KiB UTF-8。拒绝递归重复键、非法代理对、无效 UTF-8、过深嵌套、拼接 JSON 文档和非对象根。
- UUID 要求小写规范 v4/RFC4122；`op` 区分文字和独立 Enter。文本中的 `{ENTER}` 等内容保持字面值。
- CR/LF、Tab 转空格的规范化提供给发送方预览；未规范化的提交在接受前拒绝，避免收据后改变内容。其他 C0/DEL 拒绝。
- 验证设备/当前会话与基本字段后，先查 `(device_id,id)` 的原收据，再应用新请求目标、配额与速率限制；相同 ID 不同固定载荷拒绝。取消先到时保存 tombstone，阻止迟到提交。
- HMAC 的固定载荷含原始 target 与 op，不含 session 或 JSON 键顺序；人工释放使用单独执行目标，不改原载荷指纹。
- 只有接受事务提交后才返回 accepted/held。先做原生预检，随后在执行标记事务中再次核对暂停、目标、活动设备和单调时钟有效期；提交 executing 后才能尝试输入。
- 结果提交后才形成终态回执。终态清除待执行载荷，保留去重收据；`injected` 只表示输入事件提交，不表示目标已经显示文字。

## 4. 持久化、恢复与数据保护

专用协调线程独占 SQLite；`journal_mode=WAL`、`synchronous=FULL`、外键开启，忙等待有界。账本侧文件锁拒绝第二个所有者。接收目录含 `receiver.sqlite3`、SQLite sidecar、`receiver-key.dpapi` 和锁文件，不在项目源目录存生产凭据。

设备 token 不落明文，保存 HMAC。HMAC 密钥和待执行文字由当前 Windows 用户 DPAPI 保护；终态不保留文字原文。当前目录权限继承文件系统默认规则，尚未加入显式收紧 ACL，不能把 DPAPI 等同于完整的凭据目录加固。

首次创建初始化 schema version 1、键校验和计数触发器。已有文件只按已知结构打开；数据库与密钥不成对、密钥不匹配、关键表/计数触发器/键校验丢失或 schema 不支持时拒绝打开，不执行自动修复、清空或无声重新配对。该检查不是抵抗当前用户恶意篡改的完整性方案，也不能检测任意旧的完整备份回滚；备份恢复/显式授权撤销流程仍需后续实现。

| 重启前状态 | 恢复结果 |
| --- | --- |
| accepted / held | held，原因 restart_confirmation；重新锁定窗口后仍需明确释放 |
| executing | uncertain，清除待执行载荷，持久触发 outcome_review_required 暂停 |
| 终态 | 保留原结果，不重放 |

每次启动保持暂停并清除窗口绑定。普通远程 resume 不能清除不确定结果要求的核对；本地「已核对，恢复输入」仅允许后续操作继续，不重试 uncertain 请求。最终结果写盘失败会将核心标记为不健康并关闭输入闸门，后续接受/执行被拒绝；重启后按 executing 恢复不确定状态。

## 5. 并发、流控与性能设计

- 协调命令通道上限 64，输入工作通道上限 1；任何时刻最多一个原生任务。预检与输入不占协调线程，暂停、取消和查询不等待输入线程完成。
- 暂停采用原子代次，立即关闭闸门。恢复必须匹配其请求时的代次和持久 state_rev；旧恢复不能覆盖后来的紧急暂停。输入线程在平台检查后、SendInput 前再次查看闸门。
- 旧 held 队首阻塞后续输入。待执行有效期用 30 秒单调时钟；明确释放后重新计算，重启不会按墙上时间猜测是否可以补打。
- 新操作每设备 20 条/秒、突发 4；每设备最多 16 条/64 KiB、全局 32 条/128 KiB。重复 ID 不消耗新请求令牌。收据每设备上限 100 万，当前达到上限拒绝新操作，不清除旧 ID。
- 收据总数、未终态数量和字节数通过 SQLite 触发器与收据变更同事务维护。新接受路径按设备主键和全局单行计数读配额，不对全历史 COUNT/SUM；pending_order 部分索引只含未终态，状态索引支持恢复和控制更新。
- 本地状态通知每订阅者使用容量 1 的 futures mailbox（加单个 sender 的保留槽），最多 16 个订阅者。通知只表示重新读取最新快照；满时合并，不缓存历史快照。只读请求不再触发无限刷新。
- 本地快照最多取最近 100 条收据，界面只展示最近 20 条状态，不通过实时通道拉全历史。
- shutdown 先关闭输入闸门、停止接受新调用，等待已开始输入的持久结果后释放数据库和锁；协调队列满时通过一个受控辅助发送者排队退出，不让 UI 阻塞在同步 send。

这些是已实现的复杂度/边界约束，不是已达到延迟或吞吐指标的证明。仍需测量磁盘同步、真实输入、WSS 往返、CPU/RSS、WAL 增长以及 p50/p95/p99。

## 6. Windows 输入与界面

目标绑定保存 HWND、PID、进程创建时间、会话及随机 target 代次。每次输入核对前台与绑定一致、非自身进程、窗口有效且未最小化、同一活动 WTS 会话、Default 输入桌面、非提权目标、无按下的 Shift/Ctrl/Alt/Win。拒绝安全桌面和不活动会话，不强制抢焦点。

Unicode 按完整 UTF-16 代理对构造一次批量事件，不加逐字睡眠；Enter 为独立操作。SendInput 返回全部事件且事后检查通过才记 injected；返回 0 为 failed，部分输入/焦点变化/执行 panic 为 uncertain。Windows 的前台查询与全局输入不是原子操作，最后检查到调用之间仍有竞态；终端标签/分屏共享 HWND 也无法区分。

本次没有实现剪贴板长文本路径、目标程序适配或提权常驻。当前即便长文本在协议上合法，也只采用有界 Unicode 批量路径，不能据此宣称所有编辑器/终端兼容。

界面由应用实体持有真实核心，使用有界事件唤醒更新，不轮询数据库。点击「锁定窗口…」先暂停，切到目标应用后 3 秒捕获其顶层窗口；原按钮变为「取消」，保留焦点并支持 Enter 取消。锁定后不自动恢复，没有活动配对设备时恢复禁用。启动失败显示可恢复状态，重试不删除旧文件。关闭最后窗口等待接收核心停止与设置写入结束；尚未实现托盘后台接收。

所有新增界面状态、操作、错误和收据状态都有 English / 简体中文资源。原文、协议状态码和 UI 语言分离；界面不把输入事件提交翻译为「文字已成功显示」。

46 项工作区测试通过：桌面基础/实体/生产界面 14 项，接收核心 32 项（含崩溃子进程 helper）。重要证据包括：

- 真实 SQLite WAL/FULL、DPAPI 往返与篡改拒绝、第二所有者拒绝；接受/执行边界下以子进程 exit(23) 跳过 Drop 后恢复。
- SQLite 触发故障分别中断接受和终态提交，验证无伪成功、原 ID 可查询/保守恢复。
- 同 ID 去重、原始 target 指纹、取消 tombstone、会话替换/撤销、队首等待与明确释放、配额和执行前到期。
- 预检故意阻塞时暂停仍处理；较早恢复排在被阻塞接受之后、后到暂停仍能阻止恢复；队列满仍能有序退出。
- 1 万条终态收据下的事务计数与 pending 查询计划验证；这是结构性回归，不是端到端性能基准。
- 真实核心与生产 Yue 界面配合，验证初始暂停、恢复禁用、锁定/键盘取消焦点、启动失败保留数据并重试、初始化期间关闭和释放锁；原有中英、主题、设置失败/重试与最小窗口检查仍通过。

真实接收线程会从外部唤醒 GPUI。相关集成测试使用框架支持的 `allow_parking`，以有界实时时间等待结果，不把它称作完全确定性调度；纯状态/视图测试保留原有方法。修正过通知测试在消费者与最后一次通知并发时的错误计数假设，现先关闭 producer 再测积压，不删除资源上限断言。

## 8. 后续顺序与未完成项
