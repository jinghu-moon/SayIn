# 16 · 桌面端 UI 重构实施记录

> 接收页与网络流程已由 [29 接收页重构](29-desktop-receive-ui-refactor.md) 更新：自动选择网络，取消应用内公用网络会话许可。本文保留当时界面、策略和验收记录。

日期：2026-11-13。基于 [15 · 产品定位与 HTML 原型](15-desktop-product-purpose-and-ui-prototype.md)，已落地到 Rust / GPUI / Yue 原生程序。开发构建：`desktop/target/debug/voicelink-desktop.exe`。

## 1. 本次完成的行为

桌面端负责后台接收、当前光标输入和本机记录。配对与网络许可就绪后，手机发送即可进入接收核心，每条消息无需在桌面再次确认。输入过程不激活主窗口、不移动焦点、不自动追加 Enter。

| 项目 | 重构前 | 本次实现 |
| --- | --- | --- |
| 主窗口 | 接收、授权、配对等内容集中展示 | 接收、设备、历史记录、设置四页导航，Tabler 图标 |
| 配对 | 主界面内展开 | 临时对话框；先选网络，再用二维码或短码，最后本地批准 |
| 普通启动与配对完成 | 需要本地开启接收 | 有授权设备且网络许可有效时自动待命；显式暂停保持暂停 |
| 窗口生命周期 | 关闭窗口停止接收 | 默认询问后台/退出，可设置隐藏到托盘或退出 |
| 托盘 | 无常驻入口 | Windows 通知区图标与原生菜单：打开、暂停/恢复、退出 |
| 消息历史 | 主要是收据/状态，终态释放待执行载荷 | 接受时持久保存协议原文，终态不删除历史正文 |
| 目标归属 | 无可查阅的持久目标快照 | 输入准备阶段采集、验证、持久保存程序与窗口信息 |
| 历史操作 | 无完整查阅流程 | 搜索原文、设备名称/ID、程序和窗口；结果筛选、分页、复制原文 |
| 不确定结果 | 保守暂停 | 保留该规则，明确勾选“已核对”后仅恢复新请求，不自动补打 |

首屏只保留接收状态、手机 → 局域网 → 当前输入位置路径和最近一条消息摘要。完整原文与详细信息在历史页查看。主窗口默认 1000 × 660，最小 720 × 540；主内容滚动，侧栏与状态栏保留。

## 2. 生命周期与自动待命

`main.rs` 的应用级服务持有 `PreferencesState`、`ReceptionState` 和托盘句柄；窗口仅持有视图。使用 `QuitMode::Explicit`，因此隐藏或关闭主窗口不销毁接收核心，从托盘重新打开仍使用原有接收实例。

- 默认关闭时询问“后台接收”或“退出声达”，取消不改变接收状态。设置支持每次询问、隐藏到托盘、退出应用。
- 托盘不可用时保留/打开主窗口；关闭请求走有序退出，避免留下没有入口的后台进程。
- 真正退出会先停止网络与接收核心、等待持久关闭和偏好写入，再退出应用。
- 普通启动重新发现网络，读取上次接口标识并校验当前系统网络身份；只有匹配接口或唯一接口且许可有效才继续。网络歧义或缺少许可时显示选择流程。
- 仅保存接口 key，不保存 Public 同意。公用网络每个进程会话仍需电脑本地确认，无需改变 Windows 网络类型或自动修改防火墙。
- 配对批准后自动待命；显式暂停、网络许可失效、存储错误、`uncertain` 不被自动恢复越过。新暂停仍通过代次闸门阻断较早恢复。
- 托盘恢复遇到 `outcome_review_required` 时打开主窗口核对，不直接绕过确认。

托盘使用独立 Win32 消息线程与容量为 8 的命令通道；GPUI 每 100ms 取至多 8 条命令。Explorer 重启后响应 `TaskbarCreated` 重新注册图标。菜单动作只转为应用命令，不在托盘线程写账本或执行输入。

## 3. 历史正文与目标归属

账本协调线程独占 SQLite，输入线程独立串行执行，GUI 不读写数据库或调用 `SendInput`。

| 字段 | 本次真实语义 |
| --- | --- |
| 请求身份 | 原有设备 ID、请求 UUID、收据顺序；重传仍是一条记录 |
| 原文 | 手机提交且通过协议校验的最终正文，不翻译、不重写 |
| 收到时间 | 接受事务生成记录时的本机时间，以毫秒存储，界面以本地时间显示 |
| 执行尝试时间 | 持久执行标记时的本机时间；不代表目标应用完成渲染 |
| 来源 | 配对批准时保存的手机名称及设备 ID；目前没有设备重命名功能 |
| 目标 | 已核对输入上下文的可执行文件路径、窗口标题、PID、进程创建时间 |
| 结果 | accepted / held / executing / injected / cancelled / expired / failed / uncertain |

目标 metadata 来自输入准备阶段。读取进程路径、窗口标题后再次核对前台身份；核对失败不补造目标。之后仍在执行前及执行后核对焦点，目标信息不会放松原有权限、会话、桌面、修饰键和前台窗口守卫。标题采集最多 1023 个 UTF-16 码元；界面使用真实 exe 文件名，尚未解析产品友好名称或程序图标。

持久顺序为：

1. 校验身份、请求与去重 → 接受事务写收据、待执行载荷、历史正文与收到时间 → 提交。
2. 输入线程准备并采集经过验证的目标 → 协调线程事务写 executing、执行尝试时间、受保护的目标 → 提交。
3. 输入线程执行 → 协调线程事务保存最终结果、释放待执行载荷 → 提交后产生持久终态回执。

正文复用待执行载荷的 DPAPI 密文，不增加一次重复加密；历史读取同时核验原收据的 payload HMAC。目标使用单独的 DPAPI envelope，绑定 device/request 身份并在读取时核对，防止把另一条记录的目标替换进来。普通日志不写正文。设备名称、时间和收据等索引元数据仍在本机 SQLite 中。

`injected` 在界面称“已提交输入事件”，不能保证目标应用实际渲染。失败或 uncertain 记录的目标只是执行尝试上下文，不能解释为已成功发送到该软件。未执行/未获取目标时明确显示缺失状态。

## 4. 存储升级与有界查询

账本 schema 升级为 3。保留原有去重身份、密钥、设备令牌与收据，不清空数据库，不重新配对：

- schema 1：同事务新增 `message_history`，从仍有待执行载荷的旧收据补存正文，新增 `devices.display_name`。
- schema 2：验证已安装的历史表后新增设备名称列。
- schema 3：验证历史表和设备名称列存在；缺失时拒绝打开，检查先于崩溃恢复写入。

旧版本已释放的终态正文无法恢复；旧时间或设备名称缺失时显示缺失/通用手机名称，不用当前时间或当前前台程序补填。撤销设备不删除历史正文、来源或原始结果。

每页最多 30 条，以 `accept_order` 做 keyset 分页。每次账本查询最多解密 256 个候选；搜索需要更多候选时，异步任务分批继续，每批之间让出协调线程，直到取得本页结果或到达末尾。搜索最多 256 个字符，120ms 合并/延迟查询；查询代次阻止旧结果覆盖新条件。实时刷新只标记待刷新，不累积无限请求。接受新消息不扫描历史表。

这些是执行上界与复杂度保证，并非吞吐或延迟实测。原有容量限制、事务计数器、持久回执与 held/uncertain 规则继续生效。

## 5. 国际化、颜色与可访问性

简体中文、English、跟随系统沿用 Fluent 与 Windows 语言偏好。新增文案和无障碍名称均放入双语资源；切换语言保留搜索条件、过滤状态和原文，不触发发送。收到/执行尝试时间使用带参数的完整本地化标签。

品牌标识、接收图标及基础焦点环使用精确 `#1f75db`，其余表面、文字、边界与状态使用 neutral。继续采用本地 Yue 和内置 Tabler；没有修改相邻组件库或升级无关依赖。当前 Yue 只提供 Azure/Neutral 预设，没有完整的自定义 accent API，因此 Yue Primary 按钮仍使用 neutral 样式，尚未把整套控件状态改为精确品牌蓝。

配对、不确定核对和关闭弹窗使用原生 Yue 对话框，键盘导航、Escape、焦点恢复由组件机制处理；不确定核对必须勾选才能恢复。图标按钮均提供明确名称。托盘麦克风资产及 MIT 许可见 `desktop/assets/README.md`、`LICENSE.tabler`。

## 7. 真机测试步骤

使用 `desktop/target/debug/voicelink-desktop.exe`。这是开发 Debug 构建，不是安装包。保留现有默认数据目录；无需清空身份或重新生成凭据。以下步骤需要用户在目标应用放置光标，避免在聊天框/终端误发有意义的命令。

1. 启动电脑端，打开手机端。首次或网络变化时选择与手机连通的网卡；Public 仅勾选本次会话许可，不必改为专用网络。已有配对仍应保留。
2. 新手机可扫码或输入配对码，二选一；电脑批准后自动待命，不再额外点开启。
3. 切到普通权限的记事本，在空白文档点一下输入位置。手机发送唯一测试句，例如“声达验证一：记事本”。预期直接落字，桌面端不弹确认、不抢焦点、不追加回车。
4. 切到另一个编辑器，再发送不同测试句。打开历史，核对两条完整原文、来源手机名称、不同 exe/窗口、收到时间与执行尝试时间及实际结果。浏览历史不应把目标改成声达本身。
5. 搜索其中一段文字或 exe，切换结果筛选，复制原文；切换中英文后正文与查询条件不变。重启后历史与原结果仍在。
6. 关闭主窗口选择“后台接收”，继续在记事本输入位置从手机发送。预期仍能落字；从托盘重新打开可看到新增历史。
7. 托盘暂停后发送。预期不落字、旧请求保留待处理状态；恢复只允许新请求，旧 held 不应自动重放，继续按手机现有流程核对/取消或明确处理。
8. 显式暂停后退出并重启，预期仍暂停。选择退出后服务停止；托盘图标移除，主窗口关闭。
9. 若出现结果不确定，先在目标软件核对内容，再勾选电脑端核对声明后恢复。旧 uncertain 记录保留，不自动重试。

权限更高的目标、安全桌面、焦点变化等仍可能拒绝输入或产生 uncertain。应核对真实结果，不将拒绝记为成功。

## 8. 仍未实现或未验证的范围

- 当前协议没有手机 `sent_at`，因此不显示伪造的手机发送时间。正文是手机规范化后的最终协议正文；当前协议拒绝原始换行/控制字符，本次未改变双端载荷规则。
- 未增加独立的本地核对审计表；核对只恢复新作用域，原 uncertain 回执保持原状。
- 电脑尚未收到、未认证或未通过接受校验的消息不生成正文历史；离线未发送消息仍由手机 Outbox 保存。
- 尚无真实 LAN 到普通目标应用的本轮人工落字记录、p50/p95/p99、吞吐和续航数据。不能由单测、截图或 Debug 构建推导低延迟指标已达到。
- 历史正文留存/清理策略、exe 友好名称/程序图标、开机自启和完整自定义品牌控件主题未在本轮加入；保留用户已有数据与去重身份。
