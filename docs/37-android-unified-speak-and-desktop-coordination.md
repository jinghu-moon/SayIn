# 37 · 手机统一说话界面与桌面联动

日期：2026-11-14。参考 `refer/sayin-mobile-ui.html`、`refer/sayin-quick-entry.html` 及 [36 统一交互](36-mobile-demo-unified-interactions.md)。本轮修改实际 Android 和 Windows 软件，不仅是 HTML。

## 产品目标与边界

手机负责收音、识别、编辑并发送最终文字；电脑在后台接收，向当前焦点提交输入，记录正文与执行时目标。正常发送不要求用户打开电脑主窗口或再次确认。桌面界面只承担连接、历史、设置和必要的异常核对。

完整说话页与快捷卡只是同一会话的两种展示。不能各建一个麦克风、草稿或发送请求；断线、切入口、恢复进程都不能把旧文字当成新的输入自动发送。电脑执行结果不确定时，只有电脑本地核对能恢复接收。

## 手机界面与实现

- 草稿为主体，底部统一使用「更多 / 开始或结束说话 / 发送到电脑」。更多采用 Tabler `dots-vertical`；放弃本次录音与清空全部草稿是不同命令，后者支持撤销。
- 本地、云端、输入法共用选区与草稿。新录音以开始时选区为锚，partial 全文快照替换本轮识别内容；放弃恢复录音前原稿和选区，包括反向选区。
- 完整页提供来源分段；快捷卡把来源放入更多菜单，并提供展开到完整页和收起。极小高度下来源及自动发送开关收进更多，键盘编辑时收起完整页顶栏和底部导航，保留编辑区与发送按钮。
- 连接胶囊只展示真实连接状态，打开共用连接面板。首次扫码或短码连接仍等待电脑批准；已配对前台重连，不重复配对。协议没有电脑商品名和目标软件字段，因此手机显示通用「电脑」，不拿示例名称填充。
- 本地加载、预热、就绪来自真实引擎状态；云端准备使用连接文案。准备期间不打开麦克风。界面收起时取消尚未开始的录音意图，模型准备可以继续；不会在模型就绪后偷偷开启麦克风。
- 历史页提供搜索、全部 / 已提交 / 待处理筛选、日期分组、正文复制与详情。手机记录的是自己实际发送的文字，不虚构电脑目标软件；执行时软件及图标仍由电脑历史展示。
- 主题色 `#1f75db`；普通界面使用 Yue neutral，反馈使用 Yue success/warning/error；保留简中、English、明暗主题和系统应用语言设置。

核心状态在 `SpeakSession`；`SayInApplication` 的进程级 ViewModelStore 提供唯一 `VoiceLinkViewModel`、仓库和云配置。页面及 Activity 不再拥有识别器，切页不创建第二条录音链路。进程死亡结束录音，恢复文字与请求身份，不伪装成仍在录音。

## 发送与双端状态

「说完自动发送」默认关闭。开启后也必须同时满足：用户明确结束录音、ASR 最终结果、有效电脑输入范围、当前说话界面可见、文字合法且没有输入法组合文本；随后显示三秒倒计时。中文、英文、长短句使用同一规则。

编辑、更多、连接、切页、切换形态/入口、收起、识别来源变化和电脑输入范围变化取消旧倒计时，回到界面或重连不会恢复旧授权。后台结束录音只保留草稿，即使 final 返回前重新打开界面也不自动发送。输入法的完成键只收起键盘。

| 协议状态 | 手机与桌面表达 | 后续操作 |
| --- | --- | --- |
| `saved` | 已保存，等待回执 | 查询原 ID，不创建另一次提交 |
| `accepted` | 电脑已接收 / 已接收 | 等待结果或查询原 ID |
| `held` | 等待输入 | 原因保留；电脑就绪后显式继续原请求，不续期限 |
| `executing` | 正在提交输入 | 等待或查询，不重发 |
| `injected` | 已提交输入 | 手机清除对应草稿；不能据此证明目标框已显示文字 |
| `review` | 暂未取得回执 | 查询原 ID或显式丢弃本地待核对项，不直接重发 |
| `uncertain` | 输入结果待核对 | 保留原文及 ID；在电脑核对后恢复，不远程解除 |
| `failed` / `cancelled` / `expired` | 明确失败 / 取消 / 到期 | 保留草稿，显式再次发送分配新 ID |

手机提交后冻结当前请求；重复点击、重复回调及恢复进程不能绕过去重。终态查询允许载荷已清空的记录，并保留历史正文。`held` 在说话页可直接继续，避免为了补救而必须跳到历史；是否允许继续仍由电脑当前状态与原请求期限决定。

电脑待核对弹窗原先只保存一个勾选布尔值，本轮改为请求 ID 与 `state_rev` 的核对授权。显示内容/状态变化后清除旧勾选；核对正文的异步读取也绑定发起时版本，新版本等待对应记录读取完成后才允许核对；过期回调不能确认新状态。恢复命令把被核对的版本传给接收协调线程，线程再次检查。普通恢复不携带本地核对授权，手机任意字段也不能生成该授权。

本轮未增加通信协议字段或要求重新配对。原有固定证书、TLS、LAN 发送、30 秒请求期限、接收线程、去重账本与 Windows 当前焦点输入流程继续使用。

## 原生快捷入口与生命周期

| 入口 | 行为与权限 |
| --- | --- |
| 快捷卡 | 独立透明底部 Activity，打开当前会话；打开本身不录音 |
| 系统磁贴 | 用户添加后点击打开快捷卡；锁屏先解锁，不后台打开麦克风 |
| 悬浮球 | 默认关闭，用户显式开启并授权悬浮窗；可拖动、打开同一卡片或从通知关闭 |
| 录音通知 | 只在用户主动录音期间的 microphone 前台服务中存在，提供结束说话和返回当前会话 |

先由系统接受 microphone 前台服务，再启动录音。服务启动/权限失败保留草稿并提示，不降级为偷偷后台录音。服务 `START_NOT_STICKY`，进程终止后不自动恢复麦克风。录音时收起可继续；没有可见入口且未录音时断开 LAN，录音中保留 LAN 状态。悬浮球空闲服务不占麦克风，不发送草稿，不申请开机自启。

拒绝相机、麦克风、通知或悬浮窗权限不修改系统安全设置。悬浮球和磁贴是可选入口，配对与正常语音发送不依赖开启它们。Android 新版本的本地网络权限仍按需请求。

## 本地数据

草稿与选区、原草稿 ID、已提交请求身份使用独立 Keystore AES-GCM + AtomicFile 保存在 no-backup 目录。150ms 合并保存是草稿的写入策略，并非同步持久化承诺：突然断电/强杀可能丢失最近尚未完成的草稿写入。Outbox 的事务提交继续承担发送账本的持久性。

恢复草稿完成前禁止录音/发送；读取失败不静默覆盖坏文件，提示当前草稿仅在内存。恢复请求先以 Outbox 和电脑回执为准，不恢复录音状态或自动发送票据。

Room schema 由 1 升到 2，追加加密 `transcript` 展示正文。终态清除待执行载荷与配额字节数，历史正文独立加密保留最近 100 条终态；旧终态没有正文时显示原文不可用，不重新填造内容。升级保留当前安装的配对、密钥、收据和历史，未卸载或清数据。此变更用于保护正在使用的数据，并未增加旧协议兼容分支。

## 真机验收步骤

1. 电脑运行新版 SayIn，手机显示连接就绪。在电脑记事本输入区放置光标；手机选择原有本地或已配置云端，说一句话并结束，手动发送。检查记事本出现一次、没有自动追加 Enter，双端历史正文一致，电脑历史目标为实际记事本。
2. 打开快捷卡，继续同一草稿；说话中收起再打开或展开完整页，确认没有第二次录音、文字不重复。放弃本次录音应恢复录音前原稿；清空后撤销应恢复文字和选区。
3. 显式打开说完自动发送，结束录音后看到三秒倒计时；分别测试打开连接、打开更多、编辑、收起以及电脑暂停，确认取消且返回不自动发送。关闭自动发送恢复默认手动使用。
4. 电脑暂停或手机断线时先说话；恢复后检查旧稿仍在、未自动发送，再手动发送一次。电脑窗口处于前台无法输入时，按提示把光标移到目标输入区，显式继续原请求；过期不自动补发。
5. 手机横竖屏打开键盘、大字号和快捷卡检查：编辑区与发送按钮可见；横屏不得强制锁死方向。测试系统磁贴与悬浮球时按系统提示授权，拒绝也能使用完整说话页。

不要为了测试而在真实目标程序主动制造 `uncertain`；该分支已有隔离 fake input 和桌面核对授权测试。普通输入能否显示、真实云识别质量、OEM 后台限制、持续功耗和日常机型性能，仍以实际验收为准。
