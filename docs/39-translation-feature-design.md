# 39 · SayIn 翻译功能与 Android 本地推理设计

日期：2026-11-14。本文保留实施前设计依据；三个模型已完成 Redmi K40 独立 CPU 推理比较，并已接入统一草稿。当前默认 Hy-MT2-1.8B Q4_K_M，实际命令、性能、质量缺陷与产品回归见 [50 实施记录](50-android-local-translation-implementation.md)。REDMI K90 Pro Max 尚未连接验收；下文“未实现/未测”的描述为设计时点，不覆盖实施记录中的实际结果。

## 1. 用户目标与已知条件

用户认可“翻译后输入”，重点是中文到英文，并进一步询问本地模型、模型能否内置及所需框架。建议首版实现手机端离线中译英，原文与译文可检查，用户明确选择译文发送；多语种、反向翻译和云端服务作为后续候选，不扩大首版操作负担。

用户提供的日常设备截图显示 REDMI K90 Pro Max、第五代骁龙 8 至尊版、16GB 物理内存和额外 6GB 内存扩展、HyperOS 4.0.6.0。内存评估按 16GB 物理内存，不按 22GB 计算。截图不是 ADB/推理测试记录；仓库此前 Redmi K40 的 ASR 测试不能当作该机的翻译性能。

用户明确提供的本机输入材料：

- llama.cpp 官方 Android 示例：`D:/100_Projects/110_Daily/VoiceInput/refer/llama.cpp-master/examples/llama.android`，相对入口见[示例目录](../refer/llama.cpp-master/examples/llama.android)。
- 三个翻译模型：`D:/100_Projects/110_Daily/VoiceInput/assets/translation-model`，见[模型目录](../assets/translation-model)。

这些材料用于实施与对比，不代表用户已经确定最终模型、量化方式、分发方式或推理后端。`refer/` 被 Git 忽略，后续正式依赖需固定来源与 revision，不能把本机绝对路径作为可复现构建的唯一前提。

## 2. 当前能力与功能边界

现有三种输入来源是豆包云语音、本地 X-ASR 和手机输入法，已经共用草稿、确认、Outbox 与收据路径。翻译位于最终文字之后，不修改 ASR 权重，也不要求重录原始音频。

```text
云语音 / 本地 X-ASR / 手机输入法
                 ↓
             最终原文草稿
                 ↓ 用户调用翻译
       翻译任务 + 独立结果候选
                 ↓ 完整结束、版本仍有效
          原文/译文预览与编辑
                 ↓ 用户明确发送译文
        现有 Outbox → 电脑文字输入
```

本地翻译不上传原文、译文或音频，也不要求电脑在线。用户若选择云语音，前置 ASR 本身仍会上传音频；“本地翻译”不能被描述成整条链路都离线。电脑只接收用户明确发送的译文，不接收手机模型、云凭据或修改指令。

专用翻译模型不作为自然语言草稿改写模型使用；术语提示与翻译风格能力也不等于任意编辑能力。

### 3.2 选型依据与限制

Hy-MT2-1.8B 为翻译专用模型，官方提供 GGUF/llama.cpp 路线及默认翻译、术语、风格、上下文等提示示例。PLaMo 3 Translate 提供 0.8B/2B 等规格、官方 GGUF 及独立提示格式，可作为同题对比候选。

首选 Hy-MT2 Q4 是测试建议，不是已证实最快或最准确的结论。先用同一中译英样本比较三个本地文件，记录完整输出质量和手机资源，再确定默认单一模型；普通用户无需每次选择模型。

讨论中的“440MB”指 Hy-MT2 的特定 1.25-bit 版本，不是 1.8B 的固定大小，也不对应上述 Q4 文件。该版本需要对应 STQ 支持，本地目录当前没有该文件；不纳入首轮默认集成，不假设任意 GGUF 引擎都能直接加载。

不得把供应商汇总评测的“超越某商业服务”或“更快 1.5 倍”写成 SayIn 中译英、该量化文件及该手机的实测结论。权重体积不等于峰值内存，参数量也不能直接换算句子延迟。

- TranslateGemma 4B 可作未来电脑侧研究，不作为当前手机首版必需依赖；本轮没有下载或验证。
- 云端通用千问/豆包与专用 Qwen-MT 曾作为候选讨论。若用户以后选择云端，需独立确定 API、型号、区域、价格及凭据，不因本地失败偷偷回退云端，也不默认复用 ASR 权限。

## 4. 推理框架与本机官方示例

### 4.1 目标技术栈

| 层 | 建议技术 | 职责 |
| --- | --- | --- |
| UI/任务管理 | 现有 Kotlin、Compose、统一会话与协程 | 原稿、修订、预览、取消和明确发送 |
| Kotlin/C++ 边界 | 项目自有最小 JNI 接口 | 加载、独立翻译请求、流式预览、取消、结束原因和释放 |
| 推理 | 固定 revision 的 llama.cpp | GGUF、tokenizer、模板、prefill/decode、采样及内存管理 |
| 构建 | Android NDK + CMake | 构建 arm64-v8a 原生库，与现有 JNI 依赖一起核对打包 |
| 权重 | 从已校验的应用私有本地文件加载 | 模型和来源清单，不执行外部脚本 |

无需让用户安装 Termux、Python、Ollama 或启动手机 localhost HTTP 服务。sherpa-onnx 继续负责现有 ASR，llama.cpp 负责新增文本推理，两者各自清晰管理生命周期；不把 GGUF 改后缀为 ONNX。

首轮建立 CPU 后端基线；确认正确性和热点后再评估 Vulkan/OpenCL 等加速。不能因芯片带 NPU 就承诺 llama.cpp 自动走 NPU，不能把后端开关变成主流程必选项。

### 4.3 Native 层正确性

- 权重可在受控会话中复用，每个翻译任务必须重置/新建请求 context、KV 与采样状态；不把官方聊天示例的多轮历史带进下一次翻译。
- 模型、context、批次和采样器的创建、decode、重置与释放由同一后台所有者串行协调；取消后确认 decode 已停止才释放，避免 use-after-free。
- 取消既使 UI 结果失效，也要能通知 native 停止推理；仅取消 Kotlin Flow 不足以证明当前 native 调用已中止。设置可观察取消点，并测量取消到停止的时间。
- JNI 正确处理 UTF-8/UTF-16 边界、中文和 Emoji，token 字节不完整时有界缓冲再解码，不按单 token 强行替换为乱码。所有失败返回类型化原因。
- 自有 API 区分 EOS 正常结束、用户取消、输出到限、上下文不足及 decode 错误。示例 Flow 正常关闭不能直接视为译文完整。
- native/logcat/崩溃诊断不输出原文、译文、提示词和凭据。关闭或定向审计上游调试日志，不直接复制演示的完整日志策略。
- 与 sherpa AAR 和其他 JNI 库核对 `libc++_shared.so`、OpenMP、动态后端及 R8/JNI keep 规则；不使用无依据的 `pickFirst` 隐藏 ABI 冲突。验证原生库 16KB 页对齐与目标系统加载。

## 5. 用户操作与状态

默认目标语言为 English，源语言首版明确为中文；目标语言与界面语言、ASR 识别语言独立。未来扩展语种再记住用户选择，不要求每次选择模型、格式、线程数或后端。

1. 用户完成输入，原文草稿可编辑；“翻译成英文”位于辅助操作，不增加新的输入来源选项。
2. 首次使用根据已定分发方式准备模型，展示真实文件检查/加载进度。加载不打开麦克风、不调用云端、不发送 LAN 文本。
3. 冻结当前草稿、选区和修订版本，取消发送倒计时，启动一次翻译。
4. 流式译文可以预览，但未正常结束时不能作为完整译文发送。用户可以取消并继续编辑原文。
5. 完整结束后展示原文与英文，默认发送对象为这次明确生成的译文；按钮说明“发送译文”，另有保留原文、编辑译文或重新翻译的辅助操作。
6. 明确发送时冻结译文快照，通过现有规范化、长度及接收范围校验后持久入 Outbox。失败保留可恢复内容。

进入快捷卡时共享当前任务；长文对照可“在 SayIn 中查看”回完整页，不创建第二份草稿。首版离开说话会话或退后台取消未完成推理；已完成候选与原稿按草稿策略保留，进程重建不自动重启推理或发送。

建议内部状态为未准备、准备中、可用、翻译中、取消中、完整候选、失败；名称是设计语义，不要求把每项变成独立 UI 开关。清空、继续录音或源文变更使旧候选过期，不能因为文字改回相同就复用旧结果授权。

## 6. 任务版本、草稿与发送的一致性

每个任务最少绑定：任务 ID、草稿 ID、现有修订版本、源文/选区快照、源/目标语言、模型文件摘要、模板修订；术语表接入后增加其修订。只增加表达必要事实的字段，不重复维护来源相同的状态。

响应只有在任务仍有效且源稿版本匹配时才进入可采用候选。编辑、清空、撤销、取消、切模型、开始新识别、切语言或恢复草稿后，旧响应全部失效；销毁 UI 不得留下回调向已释放状态写入。

原文和译文属于同一草稿的两个表示，不把 partial 直接写回原文。持久化扩展 `SpeakingDraftStore` 的受保护结构，保存必要的完整原文/完整候选/请求关联；在结果未持久化前不清空原稿。恢复失败停止并解释，不把损坏密文当成空草稿重建。

Outbox 中保存用户实际选定发送的不可变正文；翻译模型或语言设置变化不能修改旧请求。提交译文成功后，只清理其对应草稿版本，保留过程中产生的新稿。UI 可保留必要原文用于本次对照；首版不强制扩展电脑协议上传原文或模型信息。

翻译、编辑及候选采用都不自动启动发送。即使用户打开“说完自动发送”，原稿的旧票据也不能在等待翻译后继续使用；首版译文明确手动发送，未来若增加自动发送需单独设计授权条件。

## 7. 模板、长度与输出约束

### 7.1 独立模型模板

Hy-MT2 按官方翻译任务示例及 GGUF 模板构造，PLaMo 按其官方专用格式构造；分别记录模板 revision。不能只替换权重路径却共用任意聊天 prompt，也不能把模板字符串重复套用两次。

首版要求只输出译文、忠实保留人名/数字/日期/否定/代码/品牌词与原有段落，不自动总结或扩写。`SayIn` 默认保留原样。术语表是后续可选功能，先用固定测试词验证模型遵循程度，不增设必填术语步骤。

输入内容中的“忽略之前指令”等文字是待译数据；模板分隔、角色处理和对抗样本应联合验证。不能以低温、固定种子或一句“只翻译”保证绝无幻觉。

### 7.2 有界推理

首轮可从 `n_ctx=4096`、源文最多 1024 tokens、生成最多 2048 tokens 开始，预留模板及特殊 token 空间；这是试验预算，非用户已确认限制或模型最大上下文。正式输入需按当前模型 tokenizer 精确计数并检查总量，不能用汉字数代替。

超限明确保留原文并提示缩短/分段，不静默截断，不丢掉最后一句。首版不自动切多段并行翻译；后续若支持长文，应保持上下文、句段边界、取消和顺序一致性再设计。

达到输出上限、上下文不足或异常结束时，将已生成内容标为未完成，不能把部分英文当完整结果提交。译文仍受当前 LAN 正文 4000 码点/16384 字节上限约束，英文扩展后超限要明确拒绝或供用户编辑，不更改旧请求。

原文中若有换行，先保留在原文和候选中。当前 LAN 双端会把换行变为空格；在完整多行输入链路实现前，发送须明确展示规范化预览，不能把“模型保持段落”描述成“电脑已保持段落”。

## 8. 模型分发、内置与许可

GGUF 支持从本地文件加载，因此可以设计安装资源交付、首次准备下载或手动导入开发测试。用户已询问内置可行性，但尚未确定最终分发路线；当前工作区拥有模型不等于它已打入 APK。

推荐先在开发/仪器化环境使用用户提供的三个文件，正式产品只交付胜出的默认模型，避免一次打包三份权重。普通用户不被迫寻找文件或选择量化格式。

| 路线 | 要点 |
| --- | --- |
| 随安装资源交付 | 安装即离线可用；必须核对 APK/AAB 渠道大小、压缩方式、复制/映射路径、峰值磁盘与更新成本 |
| 应用内准备下载 | 用户明确启用后从固定来源准备；校验后离线使用，真实进度、取消及失败恢复，不改变模型推理的离线属性 |
| 开发阶段本地导入 | 仅作评估工具；复制到应用私有目录并校验，不能依赖电脑绝对路径或长期外部 URI |

加载文件前校验来源清单的长度、SHA-256、GGUF metadata、架构及 tokenizer/template 兼容；下载临时文件与可加载文件分开，完成校验后原子替换，失败保留旧可用版本。不同模型切换先停止任务再释放，不同时常驻三份模型。模型文件是公开权重，按完整性与许可管理；用户文字仍按草稿保密要求保护。

正式接入新增与 `android/asr-artifacts.json` 同样可复现的翻译制品清单：来源仓库/revision、文件名、字节数、SHA-256、量化、模板版本、支持的 llama.cpp revision 与许可证。本文本地摘要不能替代官方来源核验。

本机 llama.cpp `LICENSE` 为 MIT；模型许可独立核对。PLaMo 官方声明 PLaMo Community License 并区分商业条件；Hy-MT 也应按选定 revision 取得完整许可并核对分发条件。不要把工程源码的 MIT 自动套用于模型、全部 native 依赖或最终分发物。许可审阅与可复现来源是发布前工作，不影响本轮规划完成。

## 9. 性能策略与目标手机验证

默认一次只执行一个翻译任务，不并行多模型。开始新录音优先取消翻译并等待 native 安全停止；首轮不让本地 ASR 和翻译同时高负载 decode。权重是否同时保留由峰值内存、热状态和重复加载数据决定，不为猜测速度引入复杂缓存。

复用已加载权重与每次清理请求上下文是两件事。低内存、后台或离开会话时先取消任务、安全释放；模型加载/释放不能阻塞主线程。首次准备和 warm 状态用真实回调显示，不以计时器伪装就绪。

| 指标 | 记录方法 |
| --- | --- |
| 冷启动 | 进程启动、模型校验/加载、首个结果和完整结果分别计时；标明页缓存条件 |
| 热启动 | 相同长度样本多次请求；记录 prefill、首 token、整句完成 p50/p95/p99 与样本量 |
| 内存 | 记录 native、PSS/RSS、峰值与 KV；单模型及 ASR 权重共存分别测量 |
| 取消 | 长输入、prefill/decode 中取消，记录到 native 停止/可重新录音的耗时 |
| 连续使用 | 固定亮度、网络、电量和温度条件，记录温升、频率/热状态及耗电，不用一次运行外推续航 |
| 设备差异 | K90 Pro Max 作为目标手机，K40 如测试则单独列出，不合并数字 |

当前没有该手机首字/整句延迟、峰值内存或耗电指标；不承诺秒级，也不以“16GB 足够”替代加载测试。性能门槛应根据首轮基线与用户可接受等待确定，再冻结产品验收标准。

## 10. 实施与验收计划

1. 固定 llama.cpp 上游版本、模型来源/摘要/许可，核对本机示例与应用工具链差异。
2. 建立独立 JNI 文件推理验证：三个本地模型逐个加载，用各自模板输出中译英，验证正常结束及取消；不访问麦克风、不发送 LAN。
3. 建立相同测试集的质量与性能对照，确定默认模型、后端、线程/上下文预算及分发路线。
4. 接入统一草稿任务、版本防护、原文/译文预览和受保护恢复；最后接入现有明确发送入口。
5. 完成 Debug、Release/R8、原生加载及真机回归，记录剩余边界。

质量样本至少覆盖日常消息、正式邮件、技术术语、中英混合、人名/品牌、日期金额单位、否定/条件/疑问、Emoji、代码、换行、引号及恶意提示文本。人工检查意义保留、无关增补、漏译、术语与格式；不能只凭 BLEU、输出非空或语言流畅判定通过。

| 关键场景 | 验收预期 |
| --- | --- |
| 取消、超时、到限、native 错误 | 保留原文，partial 不可当完整译文发送 |
| 翻译中编辑/清空/改回原文 | 旧候选不覆盖新版本，不恢复发送票据 |
| 多次请求 | 不串入上一条聊天上下文或译文 |
| 进程重建/Keystore 缺失/密文损坏 | 不重启推理/发送，明确保留或报告可恢复状态 |
| 模型缺失/损坏/不支持架构 | 明确错误，普通草稿输入仍可用，不静默换模型或上云 |
| 断网运行 | 已准备模型在不允许外网时完成翻译；用审计确认无隐式请求 |
| 翻译后断线/暂停/范围变化 | 译文保留；发送重新检查范围，旧请求只查询 |
| Release/R8/16KB 页 | JNI 正常加载和执行，资源释放及错误路径有效 |

未来代码变更运行 Android JVM、Debug/AndroidTest/Release 构建、Lint、i18n 及隔离真机测试；修改 desktop 或通信公共行为时再运行完整桌面门禁与双端回归。实际命令以项目 Wrapper 为准，JDK 通过 `./scripts/gradle.ps1 --version` 核对。付费云测试仍须 opt-in，不作为离线翻译回归的一部分。
