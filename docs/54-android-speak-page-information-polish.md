# Android 说话页信息与翻译交互微调

状态：双端原生实现与验证完成，结果见第 10 节及第 11 节图标补充。设计日期：2026-11-15；最终验证：2026-11-16。依据 [51 三区语音栏](51-android-three-zone-voice-bar.md)、[52 剪贴板与常用语设计](52-android-clipboard-and-quick-phrases-design.md)、[53 剪贴板与常用语实施](53-android-input-assist-implementation.md) 及用户本轮讨论。

主线整合校正（2026-11-16）：以下早期设计中的“顶部普通总字数”以当前实现为准——普通总数只在语音栏显示，顶部仅补充选区计数和 3600/4000 起的上限提示，空间不足时优先隐藏次级计数，避免重复。计数仍按当前显示文本的 Unicode 码点计算。实际组合回归、测试假设修正及边界见 [66 主线整合](66-main-branch-consolidation.md)。

## 1. 目标

说话页的主要任务是编辑或口述一段内容，并将它送到电脑当前焦点。当前草稿卡顶部留白较多，字数占据底部工具行；同时用户无法在手机上快速判断电脑前台应用。微调需要让卡片上下信息更平衡，优先回答“电脑当前是什么应用”和“当前草稿有多少字”，同时保持底部高频工具稳定可达。

本方案遵循既有产品原则：自动完成可推断的事情，不增加目标选择或发送确认；不把内部状态堆在常驻文本上；完整说话页与快捷卡使用同一份会话状态和交互。

## 2. 信息层级

草稿卡顶部成为紧凑的信息与编辑操作行：

```text
┌──────────────────────────────────────────┐
│  [应用] 电脑当前：Word  128 字    撤销 重做 │
│                                          │
│  草稿正文                                 │
│                                          │
│  剪贴板  图片  翻译  复制  清空             │
└──────────────────────────────────────────┘
```

| 优先级 | 内容 | 规则 |
| --- | --- | --- |
| 1 | 电脑当前应用 | 已连接且有新鲜状态时显示简短应用名；不得显示旧缓存名称冒充当前应用 |
| 2 | 字数/选区字数 | 普通草稿显示 `128 字`；有非空选区时显示 `已选 12 字`；接近 4000 码点上限时显示 `3680 / 4000` 并使用现有提示色 |
| 3 | 撤销/重做 | 保持右侧位置和原有 48dp 点击区；空间不足时优先保证这两个操作可达 |
| 按需 | 操作状态 | 只有模型准备、连接/接收异常、恢复草稿、翻译或发送状态需要解释时出现；重要阻断信息仍保留足够高度和完整文案 |

字数按协议认可的 Unicode 码点计算，不使用 Kotlin `String.length` 或 UTF-16 单元数。字数跟随当前正在编辑/显示的文本：显示译文时统计译文；存在非空选区时显示选区字数，取消选区后恢复总字数。建议达到 3600/4000 后显示已用/上限并加强提示色，进入超限状态时沿用既有拒绝规则，不截断文本。

不增加常驻日期、当前时间、上次编辑时间、电量、网速或单一来源标签。正文可能混合口述、键盘、剪贴板和常用语，给整段草稿贴一个来源标签会造成误导。模型已就绪时不常驻“已就绪”，避免状态从提示区迁移后变成永久装饰。

## 3. 电脑当前应用

### 3.1 展示语义

顶部显示的是**电脑最近确认的前台应用**，不是锁定目标，也不是对输入位置的承诺。优先采用“电脑当前：Word”这类短标签；不使用“已锁定 Word”或“保证发送到 Word”。无障碍说明可解释：实际输入位置以电脑发送时的焦点为准。

应用名过长时单行省略，不挤压撤销/重做和字数。按 2026-11-16 用户补充要求，显示实际软件图标＋应用名；提取失败回退中性电脑图标。只传缩小后的图像，不传窗口标题、文档/网页标题、完整程序路径、PID、HWND 或进程创建时间。若缺少应用元数据，显示“当前应用未知”；断开时立即清除应用名并显示“未连接电脑”；接收暂停或状态过期时优先显示相应状态，不沿用看似有效的旧名称。

2026-11-16 用户明确要求参考 Windows Terminal 示例，展示真实软件图标。本次复用桌面已有的原生图标提取库，名称与图标作为同一个有界展示快照传输，不增加软件选择、图标下载接口或持久缓存。此前“只传名称”的限制由该补充需求替代。

### 3.2 当前事实与实现边界

- Android 的 `ClientState.target` 是电脑生成的不透明接收范围标识，不包含应用名称。
- 桌面端目前在每次输入 preflight 阶段采集当前窗口的程序路径和标题，将其用于该条历史记录；没有向手机持续提供当前应用名称的状态接口。
- 因此，手机端不能从现有 `target` 推导应用名，也不能拿上一条历史的程序名当作当前前台应用。

要实现顶部提示，需要桌面端增加**仅用于展示的前台应用元数据**并在已认证控制连接内更新手机状态；Android 增加对应的可空状态字段。该字段不参与 `target` 授权、证书信任、Outbox 身份、请求摘要或收据状态。桌面端仅发送可显示的应用名，更新按当前连接代次和焦点快照关联；断连、暂停、权限/前台查询失败、应用未知时清空旧值。

状态更新不要求桌面锁定窗口，也不要求手机选择软件。元数据可能因切换窗口而短暂落后，所以标签应表达“当前应用”而不是“目标已确认”。桌面端在真正接收每条请求时仍以现有即时 foreground/focus 检查为准；元数据不能授权、释放 held、解除暂停、确认 uncertain 或改变失败语义。若应用在显示与发送之间切换，输入安全仍由现有桌面焦点检查决定。

元数据更新需有界且去重：同一应用不重复发送；连接代次变化后旧回调不得覆盖新值；无需传完整标题或定时高频广播。具体 Windows 前台变化订阅/轮询策略留给实施阶段根据现有桌面事件循环选择，并用测量确认更新及时性与资源开销。

## 4. 底部翻译按钮切换原文/译文

移除独立的「原文／译文」分段切换控件。现有底部翻译图标成为唯一入口，用户通过按钮状态辨认当前显示内容：

| 当前状态 | 按钮 | 点击结果 |
| --- | --- | --- |
| 显示原文，尚无有效译文 | 默认样式 | 开始翻译为英文 |
| 翻译进行中 | 按钮原位显示轻量进度动效，命中区尺寸不变 | 再次点击取消翻译；原文保持不变 |
| 显示完整英文译文 | 主题色浅底/主题色图标的选中态 | 恢复原文并回到默认样式 |
| 显示原文，已有有效译文 | 默认样式 | 直接显示已有译文，不重复运行模型 |
| 翻译失败、取消或结果不完整 | 默认样式 | 保持/恢复原文，不展示不完整译文 |

选中态只表示“当前草稿显示译文”，不是持续开启的翻译模式。图标、容器尺寸和底部工具位置始终稳定；不通过按钮变大、变形或移动表达状态。遵循系统减少动态效果偏好。

原文与译文均保存在现有统一草稿会话中。修改原文使旧译文失效；修改英文后保留编辑过的英文。原文/译文切换不改变发送票据、不启动自动发送、不分配新请求 ID。复制与发送使用当前显示的文本，字数也随当前显示内容更新。自动发送仍严格沿用现有授权条件，翻译完成本身不授予发送。

翻译中取消后，不留下部分结果；按钮恢复默认。已有可复用译文时再点击应立即切换，不以视觉上的“点击即重新翻译”破坏缓存复用。系统返回、页面/快捷卡切换以及草稿版本变化继续使用 `SpeakSession` 现有取消和过期规则。

## 5. 保留的状态提示

信息行不是所有提示的替代容器。按用户当前是否需要采取行动区分：

| 状态 | 展示位置与行为 |
| --- | --- |
| 模型下载、加载、预热 | 使用现有准备状态提示；真实进度和阶段，不伪造完成 |
| 草稿恢复中/存储失败 | 恢复期间禁用录音/发送；存储异常文案不能被字数或应用名覆盖 |
| 电脑断开 | 清除应用名，显示未连接并保留连接入口 |
| 电脑暂停接收 | 明示暂停原因与现有可用操作；手机不得提供越权恢复或解除 uncertain 的动作 |
| 发送待核对/不确定 | 保留现有请求级说明和核对约束，不压成可被省略的普通状态标签 |
| 录音/发送过程 | 继续由三区语音栏表达，顶行不重复时长、波形或“识别中”常驻文本 |

正常流式识别结束后直接进入草稿可编辑状态；只有 ASR 确实仍在收尾或失败时，才出现对应状态。

## 6. 空间、字体与可达性

- 底部五个既有工具（剪贴板/常用语、图片、翻译、复制、清空）保持稳定，不因译文状态隐藏常用入口。
- 不增加「当前为英文译文」常驻说明；翻译按钮选中态与无障碍名称表达当前视图。
- 普通屏幕保持卡片上下分区清晰；320dp 窄屏、横屏 IME、高字体缩放按实际可用宽高重排。不得压缩 48dp 点击目标，也不得遮挡编辑行或发送入口。
- 空间不足时按顺序隐藏非关键元信息：先隐藏字数/选区计数，再缩短应用展示名并改用“电脑已连接”的中性状态，最后按既有极小高度策略收起次级工具。撤销/重做、编辑区、录音取消/发送和接收安全提示保持可达。
- 大字体时文字允许换行或省略非关键应用名，不横向撑破卡片。应用状态、按钮选择态、翻译进度和错误必须通过 Compose semantics 暴露；仅靠颜色或动效区分状态不够。
- 完整页与快捷卡共用相同状态规则；快捷卡可因窗口尺寸采用既有 compact 布局，但不能显示不同的应用名语义或产生独立翻译状态。

## 7. 验收

### 界面

- 正常宽度下，应用名、字数和撤销/重做处于卡片顶部；底部工具位置不变。
- 存在选区时正确显示选区码点数，结束选择后恢复总数；接近上限时准确显示已用/上限，既有协议边界保持 4000 码点和 16384 UTF-8 字节。
- 320dp、360dp、横屏高 IME、至少 1.5x 字体及深浅色中，操作控件不挤压、不遮挡；完整页和快捷卡行为一致。
- 键盘导航、TalkBack 能说明当前应用/未知/离线/暂停状态，翻译图标有随状态变化的可访问名称和选中语义。

### 应用状态联动

- 同一配对电脑在 Word、浏览器、聊天应用间切换时，手机应用名随桌面当前前台状态更新；同一应用重复事件去重。
- 断连、暂停、未知程序、进程查询失败、应用切换竞态、切网重连及迟到状态回调不会留下旧应用名。
- 元数据不含窗口标题/正文/路径/PID/HWND；元数据故障不影响旧控制协议处理、连接、输入、历史和配对。
- 显示应用 A 后切到应用 B 再发送，电脑仍按发送执行时的即时焦点校验处理；手机提示不得被解释为对 A 的锁定或保证。
- 不增加窗口锁定、目标选择、发送二次确认、自动重试或重新配对。

### 翻译

- 首次点击执行翻译，成功后按钮选中；再次点击恢复原文；重复查看有效译文不重复推理。
- 翻译中点击能取消；迟到完成回调不能覆盖原文、新草稿或新翻译。
- 失败/部分结果保留原文；原文编辑使译文失效；译文手动修改后切换往返保持修改。
- 当前显示译文时复制/发送/字数均使用英文；切回原文后使用原文。翻译切换不自动发送、不复活旧自动发送票据。

## 8. 实施前后回归范围

本节为实施前确定的回归要求。现已完成桌面状态协议、Android 状态展示与翻译按钮交互；基线、实际验证和未覆盖边界记录在第 10 节。

回归包含：草稿持久化/恢复、文本撤销重做、选区局部替换、口述取消与迟到回调、翻译失败/取消/缓存复用、手动/自动发送授权、Outbox 查询不重放、held/uncertain/暂停安全、目标切换即时焦点校验、完整页/快捷卡、剪贴板/常用语/图片工具、横屏 IME/大字/国际化。

性能记录至少测量桌面前台应用状态变化到手机显示的 P50/P95 延迟、空闲更新频率与网络字节；在有结果前不承诺固定更新毫秒数。只传 UI 必需的应用名，不为降低可见延迟开启无界轮询或空闲后台常驻。

## 9. 当前不做

- 日期、时钟、上次编辑时间、网络速度、电量、单段草稿来源徽标。
- 让用户选 Word/微信/浏览器或手动锁定窗口。
- 把目标应用名当作目标输入框已聚焦或输入成功证明。
- 传输窗口标题、文档/网页标题、窗口句柄、PID、完整路径或识别正文作为状态。
- 单独的原文/译文分段控件、持续翻译开关、翻译完成自动发送。
- 为了视觉对称增加重复状态文字或装饰行。



## 10. 原生实施与验证（2026-11-15 至 2026-11-16）

### 根因与实现

旧协议只有接收范围 `target`，不能标识前台程序；旧翻译入口在任务开始时立即切换到部分结果，且底部多出独立的原文/译文选择行。此次从协议展示状态和统一会话状态机修正，没有从历史猜目标、给手机增加目标授权或新建第二份翻译会话。

- Windows `ForegroundApplication` 在后台读取交互桌面、同活动会话的前台进程与版本元数据，读取后重新核对前台身份；仅本地缓存一项身份/名称。版本资源解析移入 receiver 的 `application_name`，电脑历史图标与前台展示共用同一实现。原有 `NativeInput` 的每次输入检查、租约与历史采集未改。
- transport 在有已认证控制订阅时每 500ms 采样，单个阻塞任务串行，watch 只保留最新值。新 `foreground` 消息独立于控制修订号，名称变化才推送；新连接不复用连接建立前的采样，现有 8 秒 pong 只确认展示序号，手机校验本次 nonce 与回包时限。电脑采样 2 秒失鲜，手机 20 秒无确认清除；断连/暂停/非活动立即清除。协议见 [01](01-voicelink-protocol-v2.md)。
- Android 仓库按 socket generation/session 校验，展示序号不进入持久化、`ReceptionScope` 或 Outbox；重复/迟到消息忽略，错误展示元数据只清除名称。断连、邮箱溢出、暂停、未知和过期都不保留旧名称。
- 草稿卡顶部使用中性电脑图标、当前应用、当前显示文字/选区的码点数与 48dp 撤销/重做。3600 码点起显示已用/4000；工具区移除计数和分段切换，保留五个 48dp 工具。按实际文字测量先隐藏计数，再使用通用连接标签；极低高度收起次级工具与顶行元信息，撤销/重做移到语音栏同一行，仍保留 48dp 点击区与至少一行编辑区。模型已就绪装饰删除，实际准备/错误和请求安全说明保留。
- 翻译期间原文保持显示，按钮原位显示进度并可取消；只有完整成功才切换到选中态。原按钮切换缓存译文，不重复推理；译文编辑随缓存保留，原文编辑使缓存失效。失败/取消清空部分结果，任务 ID、草稿版本及 running 校验拒绝迟到结果。复制/发送/计数继续使用统一 `displayedDraft`，切换与完成均不授权自动发送。

### 关键行为对比

| 项目 | 修改前 | 修改后与实际验证 |
| --- | --- | --- |
| 当前应用 | 协议无名称，无法可靠展示 | 原生前台查询经认证 WSS 到真机页面；20 次真实切换均观测到对应名称 |
| 展示与授权 | 只有不透明 target | 展示名称不改变 ReceptionScope；暂停仍不可发送，实际 NativeInput 继续即时检查 |
| 字数/选区 | 底部工具附近统计总数 | 顶部统计当前视图/非空选区；补充字符、反向选区、3600/4001 码点均有断言 |
| 翻译 | 开始即展示部分译文，另有分段控件 | 部分结果不显示；完整结果选中；同按钮反复切换只调用一次引擎，编辑译文保留 |
| 取消与失败 | 可能留下部分结果视图 | 取消清空部分与任务身份；迟到成功无法恢复旧译文；截断/错误/取消/超时保留原文 |
| 小空间 | 计数与分段选择占额外工具行 | 五工具单行；窄屏、大字、快捷卡及横屏 IME 回归，撤销/重做不缩小 |
