# 手机端说话页重写

日期：2026-11-13。原生 Compose 实现，沿用 Miuix、品牌蓝与 neutral 配色。

## 目标与根因

旧版把连接卡、识别模式、大麦克风、草稿与发送按钮放在同一个页面滚动容器内；操作说明占据首屏，编辑和发送被推到下面。麦克风实际只打开输入法，也容易被理解为应用自身录音。

新版只让编辑内容滚动，说话页采用有界布局：小尺寸 SayIn 标题、连接状态行、占据剩余空间的草稿、固定操作行。其他三页继续保留各自的滚动状态。

## 实际改动

- 首次连接：显示“连接电脑，开始发送”，点击“连接电脑”进入原连接页；可以先编辑，不能离线发送。
- 已连接：显示接收就绪或当前阻断原因；“详情”进入连接页。没有虚构电脑名称，现有配对状态仍使用地址。
- 再次连接：显示断线状态和“重新连接”，明确点击才调用原有网络权限检查与 repository.connect；切页不会重连。
- 移除说话页上的识别模式和大麦克风。离线识别仍是设置页中的规划项；当前不新增 ASR、录音或自动发送。
- 使用 Compose BasicTextField 构建顶端对齐的编辑区，保留 TextFieldValue 的选区和输入法组合文本；Miuix 普通表单输入框的居中装饰不适合满高编辑器。
- 输入法按钮只聚焦草稿并打开输入法，语音输入由用户的输入法提供。
- 发送按钮固定在编辑区下方。输入法展开时隐藏底部四页导航，收起输入法后恢复；页面依可用高度简化辅助说明，避免重复计算系统栏/键盘内边距。
- 多行/制表符的转换预览按需展开，内容在有界区域滚动，不修改原草稿。超长或无效文字禁止发送并给出提示。
- 就绪判断继续使用 ClientState.ready；补齐恢复发送状态、存储异常的展示，避免显示“就绪”却禁用发送。
- 历史处理、请求身份、明确确认发送、配对授权和 Outbox 均沿用原业务链路。

## 行为对比

| 项目 | 修改前 | 修改后目标/实现 |
| --- | --- | --- |
| 草稿与发送 | 随整页滚动，可能在首屏外 | 编辑区有界，发送独立固定 |
| 输入入口 | 大麦克风实际只打开输入法 | 键盘图标明确打开输入法 |
| 识别模式 | 展示未接入的本地识别卡 | 说话页只提供已实现的输入路径 |
| 断线重连 | 前往连接页再操作 | 明确点击重连，沿用网络权限路径 |
| 草稿与切页 | 上层持有草稿 | 保留上层所有权，切页无发送副作用 |
| 接收不可用 | 就绪文案未覆盖恢复/存储状态 | 发送条件与提示一起覆盖这些状态 |
