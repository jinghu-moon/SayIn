# 32 · Android 豆包云端流式识别接入

日期：2026-11-13。阶段：开发期实现与验证记录。

后续真实服务测试发现并修复了正序号最终包误判，最新状态与 API Key 排查见 [33 结束包修复](33-doubao-final-packet-fix.md)；下文保留首轮接入时的基线与验收边界。

## 目标与范围

手机说话时直接连接云端识别，实时更新一份草稿；用户结束说话后取得最终文本，沿用既有手动发送 / 智能发送判断与 LAN Outbox。电脑端继续接收文本并向当前光标提交，无需增加云服务账户、凭据或音频协议。

首期接入 **豆包流式语音识别 2.0 小时版**。本地 X-ASR 和输入法均保留，三个来源共享草稿、选区、编辑、确认和发送入口。没有增加云端中继、服务器模式、其他供应商、Omni 整理、后台录音或自动引擎切换。

当前完成协议与界面接入、模拟服务验证、真机加密存储和本地模型回归；**尚未使用真实豆包凭据调用服务，不能声称云端实录、识别准确率、热词效果或手机到电脑落字延迟已经验收。**

## 官方依据与参考边界

2026-11-13 核对火山引擎[大模型流式语音识别 API](https://www.volcengine.com/docs/6561/1354869)。页面涵盖以下已用于实现的约束：

- 双向流式优化接口：`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`。只在识别结果变化时返回，不是一包音频对应一包响应；没有采用只在结束时集中返回结果的 `bigmodel_nostream`。
- 官方建议 100–200ms 分包；当前使用约 200ms，即 16kHz、单声道、16bit PCM 的 6400 字节。
- 2.0 小时版资源 ID：`volc.seedasr.sauc.duration`。不静默尝试并发版或其他收费资源。
- 新控制台使用 `X-Api-Key: APP Key`；旧控制台使用 `X-Api-App-Key: APP ID` 与 `X-Api-Access-Key: Access Token`。只发送用户明确配置的一组凭据，另带资源 ID、请求 UUID 和连接 UUID。
- 二进制协议为 v1、网络序长度、可选 sequence、末包标记、JSON 结果与错误帧。解析无压缩 / Gzip，处理扩展头与负数最终序号。
- `request.result_type = full`，`result.text` 为全文快照；热词通过 **`request.corpus.context` 的 JSON 字符串**传入，不放在顶层或错误的 `request.context`。
- 双向流式热词限制为 100 token，不是 100 个词。客户端目前限制最多 20 条、合计 80 个 UTF-16 代码单元，每条最多 40；这只是保守的输入预算，不能精确保证服务端 token 数，界面明确说明仍可能截断及不保证识别命中。

网络层使用现有 OkHttp **5.5.1**，依据其 [WebSocket API](https://square.github.io/okhttp/5.x/okhttp/okhttp3/-web-socket/)及监听器文档核对 `send`、`queueSize`、取消、错误与关闭语义。仅测试增加同版本 `mockwebserver3` 及 `org.json:json:20260814`；没有新增生产 SDK 或原生库，也没有改变已确认的构建工具链。

用户指定的 `refer/SayIt-main` 仅用于理解实时结果修订、结束定稿和配置流程。该工程为 AGPL-3.0；本次未复制、翻译或链接其实现代码，SayIn 的协议实现依据官方规格独立编写。参考工程不作为凭据格式、计费或准确率结论的权威来源。

## 界面与使用流程

1. 在火山引擎控制台开通豆包语音识别 2.0 **小时版**，取得 APP Key；旧版控制台则取得 APP ID 和 Access Token。
2. 打开 SayIn → 设置 → 豆包流式语音识别 2.0，填写凭据。旧版格式通过「使用 APP ID + Access Token」切换，不做凭据猜测。
3. 可选填写热词，一行一个，然后保存配置。保存不启动麦克风，也不自动上传音频。
4. 可点击「验证服务」：用已保存的配置发送 **1 秒生成的静音**，验证握手、参数、音频和最终响应。它不访问麦克风、不改草稿、不发送至电脑，可能产生少量服务费用；不替代真实语音和热词验收。服务拒绝静音时仍显示失败，不把握手成功冒充完整识别成功。
5. 回到说话页，选择「云端」→ 开始说话 → 结束说话 → 核对并发送。未配置时，按钮直接带到设置，不申请无用的麦克风权限。

云端说明在设置中直接展示，不增加重复弹窗或额外确认开关。说话页常态提示音频将发送给豆包。首次麦克风授权仍由 Android 系统处理；公网识别不依赖 LAN 权限，局域网发送仍遵守既有权限与接收状态。

简体中文与 English 均已补齐。输入来源会记住上次选择，发送方式仍默认手动。设置里的热词是当前唯一词表，豆包适配器负责传入识别；本地 X-ASR 本轮没有新增热词能力，也没有引入识别后的自动词语替换。

## 会话、错误与资源边界

`SpeechRecognition` 替代仅支持本地的页面会话所有者，统一管理加载、录音、结束、取消、麦克风所有权与草稿状态。本地模型仍使用原来的流式 decoder / 有界采集队列，云端不加载本地模型。

- 开始时冻结原草稿、选区和电脑接收范围。云端 partial 修订该选区，而非逐次追加。已显示的假设若被修订为空，恢复录音前的原稿，避免留下被服务端否定的文字。
- 用户点结束后停止采集、发送不足 200ms 的尾部及末包，最多等待 10 秒最终结果；只有末包后的最终响应才算成功。服务端提前终止、只返回 partial 后关闭或等待超时均失败，不授权自动发送。
- 成功定稿仍需通过既有 `SpeakInteraction` 判断。接收范围 / 发送模式在会话中发生变化后只允许手动核对发送；静音不为旧草稿启动倒计时。
- 切页、退后台、切来源、编辑或外部清空草稿会取消录音。保留最后可见草稿，不自动重录、切本地、重传音频或调用发送入口。
- 握手上限 12 秒；连接失败、鉴权、限流、服务拒绝、协议异常与超时均使用类型化状态和中英文提示。错误响应正文与底层请求信息不输出到日志。
- 录音直接按读取节奏发送，不缓存整段音频。PCM 使用协议支持的无压缩格式，socket 待发送队列预算 64KB，约为 2 秒音频，超过则报错停止，不能静默丢包。`queueSize` 不包含 OS / 网络中间缓冲，不能把这一预算描述为整个网络的严格延迟上限。
- 二进制帧及解压后的载荷均限制 256KB，严格检查版本、类型、标记、长度、UTF-8、压缩及序号。转写快照最多 65536 个字符；最终 LAN 文本仍通过既有长度与规范化检查。解析限制不代表能控制 OkHttp 收到帧之前的全部网络缓冲。

## 凭据与配置所有权

- 手机直连官方 WSS，使用平台证书验证；没有自定义信任所有证书、可编辑代理地址、自动跳转或请求日志拦截器。
- 配置使用 AndroidKeyStore AES-256-GCM、随机 IV、专用 AAD、独立密钥别名，存于 `noBackupFilesDir` 的原子文件。凭据、热词均加密；应用既有备份禁用规则保留。
- 与配对 / Outbox 密钥、文件完全独立。删除云端配置不会删除配对或历史。密钥丢失、认证失败或文件篡改拒绝加载，不静默生成密钥覆盖旧配置；可通过明确删除云端配置后重新设置恢复。
- Activity ViewModel 持有配置状态，在 IO 线程持久化；旋转屏幕 / 切语言不会让原子保存与新实例加载互相干扰。存储失败时停止提供云端配置，避免静默使用错误的保存状态。
- 凭据输入使用密码展示，不进入 `rememberSaveable` / Bundle；配置对象诊断字符串隐藏凭据。只在网络认证头使用密钥，不放入识别 JSON、桌面协议或仓库。SayIn 不保存音频文件；服务商的数据处理规则由其服务条款规定。

## 真实服务验收步骤

凭据只填写在手机 App 内，不需要发送到聊天或写入工程。

1. 开通小时版并保存正确凭据，验证服务；错误密钥应明确失败，不能误报成功。
2. 电脑打开一个普通输入框并聚焦。手机选择云端，口述「你好，SayIn。今天是星期三，下周一是 Monday。」观察实时修订，结束后检查标点和尾字，再手动发送并核对电脑回执。
3. 原稿前后已有文字时替换选区、继续补充；静音结束不得为旧稿启动智能发送。再试长句、中英混合和热词，分开评价连通性与准确率。
4. 录音中断网、切页、退后台、切来源，确认停止录音、保留草稿、不自动发送或重复上传。结束后断网应明确失败；恢复网络后需主动重新录音。
5. 先验证默认手动发送，再验证智能发送倒计时、取消、电脑暂停 / 离线 / 接收范围变化及 uncertain 状态。错误恢复不得绕过原有核对规则。
6. 回归本地识别与输入法、语言切换、屏幕旋转、大字号与窄屏。实际测量首字时间、结束至定稿、发送至回执的耗时，再讨论延迟目标；当前没有可信的云端性能测量结果。
