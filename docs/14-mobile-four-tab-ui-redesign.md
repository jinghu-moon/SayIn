# 14 · 手机端四页界面重设计

日期：2026-11-12。参考用户提供的 [四屏示意图](demo-mobile-app.png)。

## 2026-11-13 后续重设计方向（待实施）

用户确认手机端 UI 仍需调整。下一轮与电脑端统一按 **初次连接、已连接、再次连接** 三种场景组织体验：初次扫码/短码并在电脑批准；已连接时突出输入与发送；再次连接复用已配对电脑和凭据，以最少操作恢复连接。接收暂停与连接状态独立，重连不得越过用户暂停或结果核对。

双端场景定义见[接收页最新设计方向](demos/sayin-receive-design.md#最新设计方向双端统一三种连接场景)。当前手机页面、按钮位置和接收 demo 的三列图标教程均不是下一轮设计约束；后者已被用户否定，不能据此直接落地。设备名称同时按[商品名称方案](24-android-device-display-name-plan.md)处理，当前真机应显示 Redmi K40。本段只记录待实施方向，不表示手机 UI 已修改或验收。

## 页面结构

| 入口 | 内容与操作 |
| --- | --- |
| 说话 | 电脑连接卡片、识别方式双卡片、麦克风主入口、发送前编辑和确认、当前光标提示 |
| 记录 | 本机已有回执、时间、请求编号、待核对/释放/取消操作、不确定结果说明、空状态 |
| 连接 | 电脑与接收状态、扫码或配对码二选一、手动 IPv4/端口/短码、等待电脑批准、重连、暂停/恢复、忘记凭据确认 |
| 设置 | 输入方式、确认发送说明、前台保持亮屏开关、跟随系统/中英文语言选择、离线识别与快捷唤出后续计划 |

底部导航始终提供四个入口；页头用蓝色图标块、标题和一句说明。连接状态在页头有直达“连接”页的 Wi-Fi 图标，首页优先展示当前设备和主要输入操作。内容限制最大宽度，纵向滚动，保留各页滚动位置与同一份草稿。

## 视觉与组件

继续使用项目已固定的 Miuix 0.9.4，而不是切换组件库；NavigationBar、Card、Button、TextField、IconButton、Switch 及语言单选均使用 Miuix。布局采用 20dp 页边距、16dp 卡片内边距和至少 48dp 触摸区；适配系统栏、输入法和深色模式。

主题色为 `#1f75db`，用于页头标识、主操作、当前输入方式和选中态。其余表面、文字、描边、告警和状态都沿用 Yue neutral token，不引入红绿状态色。新增 Tabler scan/wifi/check/alert-triangle/shield-lock 五个图标，继续固定已有 v3.51.0 来源提交、MIT 许可、SVG 摘要与生成脚本。

查阅依据：[Miuix NavigationBar](https://github.com/compose-miuix-ui/miuix/blob/main/docs/components/navigationbar.md)、[Scaffold](https://github.com/compose-miuix-ui/miuix/blob/main/docs/components/scaffold.md) 及仓库内 `refer/miuix-main` 的相应源码；具体 API 以当前工程构建成功的依赖为准。

## 与参考图的功能边界

当前已实现的是**输入法语音/键盘 → 编辑确认 → 手动发送**。首页麦克风主入口会聚焦编辑框并打开输入法，提示用户点击输入法上的麦克风；没有假装本应用开始录音。离线 ASR 在双卡片及设置中标注未接入/后续计划，悬浮入口与常驻通知也标明计划，不提供无效开关。发送仍要求真实连接、当前活动设备、已建立输入范围且接收未暂停。

记录直接展示持久 Outbox 的真实状态。依照既有隐私规则，终态后正文已清除，所以不仿造示意图里的全文历史和“编辑后重发”；没有为了外观新增永久正文副本。unknown/review 的原请求重试、held 的明确释放、取消，以及 uncertain 不自动重试的规则保留。

保持亮屏开关只作用于前台 View，退出时恢复，偏好使用独立 presentation 设置保存。应用语言仍以 AppCompat/平台应用语言为唯一来源，不与识别语言、草稿或协议载荷混存。切页本身不发送、不重连、不触发历史重试。

电脑端同步采用 [13 当前光标交互](13-desktop-current-cursor-and-ui-redesign.md)：先在电脑开启接收，再点击目标文本框，手机确认发送；不再要求锁定窗口。

人工验收：

1. 打开手机新版，检查“说话/记录/连接/设置”四个入口。输入草稿后切换四页，回到说话页文字应保留，切页不会自行发送。
2. 点蓝色麦克风入口，应打开输入法；点击输入法的语音按钮进行输入。检查文字后手动发送。
3. 在连接页选择扫码或短码之一，在电脑批准；电脑开启接收后切到普通文本框，再从手机发送。
4. 在记录页查看回执；held 逐条确认，uncertain 先核对电脑，不盲目重发。
5. 在设置页切换中英文/跟随系统；草稿不变。检查深浅色、键盘展开、长文本和大字号下的滚动与底部入口。

未完成普通目标应用真实落字、物理 Wi-Fi 时延或手机光学扫码实测。构建、数据层测试和界面参考状态不能替代这些验收。

## 2026-11-13 说话页重写

原说话页的整页滚动、识别卡片与大麦克风布局已替换为有界编辑区及固定发送操作。当前实现、16 项套件的实际运行边界与用户接手真机验收记录见 [28 手机端说话页重写](28-mobile-speak-editor-redesign.md)。上文的蓝色麦克风验收步骤属于旧版，不再适用。

## 2026-11-13 统一输入来源与发送流程

说话页现提供“本地识别 / 输入法”两个来源，共用草稿和发送入口；本地 ASR 尚未接入并禁用录音入口。已实现默认手动、明确完成输入后的可选智能发送，具体流程、后台接收范围核对与验证边界见 [29 手机端统一说话交互](29-mobile-unified-speak-interaction.md)。
