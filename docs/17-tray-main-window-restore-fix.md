# 17 · 托盘打开主窗口修复

日期：2026-11-13。

## 问题与根因

用户反馈右键托盘选择“打开声达”没有显示主窗口。旧代码在窗口仍存在时仅调用 GPUI `activate_window()`；当前 Windows backend 会恢复最小化窗口，却不会显式显示已经隐藏、且未最小化的窗口。`cx.activate(true)` 在此 Windows 平台也不执行窗口显示。

上一次启动还使用了 PowerShell `Start-Process -WindowStyle Hidden`。当时只确认进程存活，未确认原生窗口可见，因此未发现该边界。后续人工启动主界面应使用普通可见启动方式；程序自身也必须能正确处理隐藏状态，不能只依赖启动参数。

## 修复

- 新建窗口和托盘重新打开均通过同一显示流程：取得该 GPUI 窗口自己的 HWND，最小化则恢复，隐藏则显式显示，然后激活。保留原有几何与最大化状态，不匹配或枚举其他应用窗口。
- 窗口已关闭时继续新建视图，应用级接收实例不变。
- 显示只发生在启动和显式打开操作，不加入手机消息接收/输入路径。
- 添加直接的 `raw-window-handle 0.6.2` 引用，用于 GPUI 到 Windows 的窗口句柄边界；复用锁文件中已有版本，未升级框架或相邻 Yue 库。
- 退出前先移除主窗口，再延迟结束 GPUI，使 Win32 销毁窗口时的焦点回调仍有存活的应用上下文；托盘事件轮询在退出时结束。

## 原生回归

新增测试使用真实 Windows 窗口、离线临时数据目录、独立托盘和生产事件队列；只隐藏/最小化/关闭测试自己创建的窗口。每一步确认操作前窗口不可见，再从同一托盘命令消费链发送 Open，确认恰有一个可见且未最小化的窗口。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 隐藏后托盘 Open | 仍不可见，复现问题 | 可见 |
| 最小化后托盘 Open | 可见 | 可见 |
| 关闭后托盘 Open | 新窗口可见 | 新窗口可见 |
| 有窗口时退出 | 原生销毁时曾触发 app released 回调错误 | 先销毁窗口后正常退出 |

## 用户验收

更新并启动程序后，最小化，再右键托盘“打开声达”；主窗口应恢复。关闭主窗口选择“后台接收”，再从托盘打开，应显示四页主界面并保留原接收状态。多次打开不应重复创建窗口。配对凭据、历史和显式暂停状态继续保留。
