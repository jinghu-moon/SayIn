# 手机端统一说话交互

日期：2026-11-13。

后续更新：本地识别已接入 X-ASR + sherpa-onnx，最新能力与验证边界见 [31 本地流式识别实施](31-x-asr-local-recognition.md)。下文“尚未接入”和对应禁用状态记录本次交互重写时的历史基线。

## 范围与实际能力

按用户确认的“两种输入来源、一套交互”重写原生说话页：本地识别、输入法输入（打字或输入法语音）共享同一份 TextFieldValue、选区、编辑区和发送入口，不分别创建结果页或草稿。

**本地 ASR 尚未接入。** 当前没有 AudioRecord、录音权限、模型文件、模型加载或识别服务；选择“本地识别”会显示不可用说明，“开始说话”禁用。仍可点击草稿编辑并发送已有文字，不播放伪录音动画，也不虚构识别结果。输入法的语音输入由输入法提供，不能承诺其音频不出手机。

## 布局与交互

- 保留小尺寸 SayIn 标题与连接状态行，标题右侧切换“手动发送 / 智能发送”，默认手动。
- 连接状态下方只有“本地识别 / 输入法”两个来源；当前会话中切页与界面重建会保留选择，草稿仍由 VoiceLinkApp 持有。
- 两种来源共用填充剩余空间的草稿区。点击正文或“编辑”调用输入法，不改变输入来源选择。
- 正在编辑时，辅助操作变成“完成输入”；完成输入先收起输入法并等待候选词提交，再判断是否进入倒计时。
- 发送始终固定在草稿下方，键盘展开后收起四页导航；同一按钮、相同接收就绪条件、相同 Outbox/历史回执适用于两种来源。
- 转换预览使用同一片正文区域，以只读文本显示换行/制表符转空格后的结果；返回编辑恢复原文和选区，不额外挤压草稿高度。
- 设置页展示当前输入来源与发送方式，与说话页保持一致。

## 智能发送状态

```text
输入中（不会因停顿或文本变化自动发送）
  → 用户明确“完成输入”
  → 等待输入法组合文本提交
  → 规则检查
      → 符合条件：3 秒倒计时 → 再核对 → 同一发送入口
      → 不符合条件：保留草稿，人工确认发送
```

首轮参数为最多 18 个 Unicode 码点、3 秒倒计时；它们是可调整的初始交互参数，不是准确率或体验实测结论。文本需有效、非空白且不处于 IME composition 中。含 ASCII 英文字母、超长、完成后又编辑过、电脑不可接收时，均转为手动确认。

点击正文/编辑、修改文字或选区、切换来源或发送方式、进入转换预览、离开说话页、Activity 暂停以及电脑接收范围变化，都会使倒计时失效。重连、恢复前台、回到页面不会重新启动旧倒计时。倒计时只存在于本页运行状态，不进入 saved instance state。

开始发送前消费倒计时票据，避免同一个票据重复触发。使用单调时钟，不受手机系统时间调整影响。手动发送也不提交尚未确认的输入法组合文本。

本地识别接入后，最终识别结果需要接入同一个“完成输入”事件；本次并未实现或声称验证该录音链路。

## 接收范围与现有链路

原先发送事件仅携带正文和草稿 ID，后台消费事件时读取当前接收范围。现在发送事件同时携带调用时的 ReceptionScope（地址、目标范围、接收状态修订号），后台协调器在入 Outbox 前与当前范围再次比较；范围变化时拒绝该次发送并保留草稿，不重新指向新范围。

VoiceLinkApp 把界面观察到的范围传入 Repository。原有调用如果直接调用 Repository.send，则在调用时捕获当前快照，后台同样核对。草稿 UUID、加密 Outbox、持久化后仅清除对应版本草稿、回执查询及 uncertain/review 处理不改变。

## 行为对比

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 输入来源 | 仅输入法入口 | 两个来源选择，共用一份草稿；本地识别如实标记未接入 |
| 发送方式 | 手动发送 | 默认手动；可选明确完成输入后的智能发送 |
| IME 组合文本 | 未单独限制发送 | 候选未确认时不发送；完成动作等待组合结束 |
| 来源切换 | 无 | 保留正文与选区，不发送、不开始录音 |
| 转换预览 | 额外展开区域 | 在相同正文区域查看，不改原文 |
| 排队期间接收范围变化 | 后台读取消费时范围 | 捕获调用时范围，后台比较后才入队 |
| 断线后倒计时 | 无 | 取消且不在重连后恢复 |
