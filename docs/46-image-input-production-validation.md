# 46 · 图片生产链路性能与验收

日期：2026-11-15。阶段 6 起始基线 `4b28edf`；历史卡片修复 `9d186a0`、压力回归发现的渲染资源释放修复 `8cf6ca5` 均已独立验证、推送并同步主工作区。首版单图阶段 6 验收完成，阶段状态见 [45](45-image-input-implementation.md)。本记录分别列出生产核心实测、fake adapter、浏览器格式补验、用户人工验收及平台测试，不将任何单项扩写成所有应用或网络环境的保证。

## 1. 测量方法

- Redmi K40 / M2012K11AC、Android 13 / API 33，隔离包 `seeyuer.sayin.imagetest`，真实 Kotlin Repository、AndroidKeyStore、Room、固定证书 TLS 1.3 与双 WSS。
- Windows 使用 Release 接收核心，独立 host/device/完整证书/DPAPI/SQLite 目录及随机 LAN 端口。无 ADB reverse、代理、网络类别或防火墙修改。当前 LAN 的 Wi-Fi 5 来自用户说明；本轮未测 AP 频道、RSSI 或链路带宽，不保证其他网络相同表现。
- 原生模式只向程序自己创建并校验 HWND/PID 的 RichEdit 子窗口输入。每张恰一图，原有 `existing|` 保留，无额外 Enter；确认后清空测试图片接受下一张。输入程序不会选择日常目标窗口。
- 手机从内容 URI 选图，完成有界读取、方向/颜色归一化、缩略图、Keystore 文件和 Room 草稿后记录准备时间，再明确发送，等待持久终态。每次检查 host/device/完整证书保持不变，终态 payload 清除。
- **原生模式的发送→终态包含测试专用 RichEdit RTF 确认**，比生产的「粘贴事件已提交」多一道目标确认。它不是纯网络耗时，也不是完整 GPUI App 或任意第三方应用的保证。
- 每个受支持样本重复 3 次，各轮 15 条测量。p50/p95/p99 使用 nearest rank；15 个混合尺寸样本的 p95/p99 都落到最大值，不能据此推断长期尾延迟。Android 使用 imageTest Debug；接收核心使用 Release，不能称双端均为发布构建。

重算：`python docs/benchmarks/2026-11-15-production-images/analyze.py`。脱敏原始数字和样本 SHA-256 已归档在[同目录](benchmarks/2026-11-15-production-images/)；用户图片原件、配对秘密、运行数据库不提交。

复现（从仓库根目录，已连接授权设备）：

```powershell
$env:CARGO_TARGET_DIR='D:/100_Projects/110_Daily/VoiceInput/desktop/target'
./scripts/verify_image_performance.ps1 -Native -Repeats 3
```

脚本只安装独立 imageTest UID。需保持手机解锁、独立 RichEdit 持续在前台约一分钟；不能同时跑其他会切换窗口的命令或操作电脑。不方便保持前台时省略 `-Native`，但得到的是 fake 输入结果，不能与原生结果混合。`-SkipBuild -SkipInstall` 只复用本轮已构建安装的隔离包。

### 中断与失败样本

三次中间原生复测未计入通过数据：一次 13 次提交只确认到 12 张，测试适配器转 `fixture_target_not_observed` / uncertain；两次明确检测到前台目标变化，分别在第 15 次及第 1 次停止。第一轮没有足够证据确定未观察到粘贴的具体原因，不能全部归因为焦点变化。没有自动重复粘贴、换新 ID 补发或解除 uncertain。用户明确保持前台后，最终独立一轮 15 次全部通过。

失败证据保留在本机忽略目录 `desktop/target/image-performance-e3280a87-...`、`...-d32f695c-...`、`...-7f2f9da0-...`；正式成功证据为 `9f256046-1986-492c-a3aa-8f55c1c017ba`（前）和 `5afd8c32-70c8-4728-9025-e125aec84960`（后）。生产协议仍只保证提交事件，无法通用确认第三方输入框是否已实际显示，这也是人工应用矩阵的必要性。

## 3. 历史与浏览器

### 真实 LAN 图片负载下的暂停

隔离 `ImagePauseInstrumentedTest` 连续 5 次通过，无 ADB reverse、无图片或文字输入。每轮约 2.50MB 的归一化图片收到第一个 48KiB ACK 后，通过测试专用 marker 触发 fixture 模拟电脑本地生产 `receiver.pause()`，验证图片意图失效、断线重连保留暂停和草稿、恢复后不自动上传或重放。没有给产品增加手机远程暂停/恢复权限。

- 手机 marker→收到 paused：97.70、106.37、134.55、108.61、95.62ms，p50/p95/p99 为 **106.37/134.55/134.55ms**。
- Windows 生产本地 pause 调用→持久完成：3.05、3.04、3.10、3.45、2.01ms，p50/p95/p99 为 **3.05/3.45/3.45ms**。
- 前一项包含控制上行、marker 接受事务、fixture 最多 50ms 轮询、本地暂停以及 pushed state 下行和 Android actor，不是单向网络延迟。5 个样本不足以推断长期尾延迟。

复现：`scripts/verify_image_performance.ps1 -PauseProbe`。原始数字见 [pause-lan.json](benchmarks/2026-11-15-production-images/pause-lan.json)，本机证据 `image-performance-c5ea70aa-6eeb-481c-92d1-51bb671ddc3c`。这一测试使用不执行的 fake adapter，不能代替 NativeInput 的目标应用验收。

### 历史、剪贴板与人工反馈

`cargo run -p voicelink-desktop --example image_history_fixture --locked -- --run` 实际通过。它只构建独立合成收据，不伪造真实输入证据；直接调用产品历史的 preview/copy/save：读取真实 DPAPI，真实系统剪贴板 PNG/DIBV5 与预期字节一致，历史/云排除标记为 0，导出与冻结资源一致。删除后复制和导出均拒绝、原导出不被覆盖；NeverInput 适配器没有被调用。普通 cargo test 不会执行这个替换剪贴板的 opt-in 主程序。

Chromium 157.0.8103.51 在本地临时 about:blank 页面读取上述真实剪贴板，paste 事件得到一张 1075 字节 PNG，contenteditable 增加一个 img，前缀保持。纯文本 textarea 粘贴后仍为 `existing|`，没有 Enter 或 form submit，也无网络提交。此项快捷键由 Playwright 驱动，**不是生产 NativeInput 到浏览器**，不代表某个网站的上传服务或附件发送通过。[原始结果](benchmarks/2026-11-15-production-images/browser-clipboard.json)。

用户在隔离手机应用完成配对后反馈「测试没有问题」，之后明确补充「测试过浏览器和word没有问题」。独立人工目录 `image-manual-7565ac0b-7b89-4e78-aee9-1bc3090fce89` 实际保留 3 条 injected / clipboard_image 收据、3 次 NativeInput 调用。随后针对「常用聊天软件草稿预览、透明 PNG 及有无误发」的补验询问，用户明确回复「已测试，没问题」，作为该范围人工验收通过记录。软件名称/精确版本未提供，不猜测；后一次反馈不虚构额外收据数，也不混入原 3 条账本。见 [manual-smoke.json](benchmarks/2026-11-15-production-images/manual-smoke.json)。

随后将已关闭的人工测试身份复制到新的独立完整 GPUI 数据目录，用户确认查看、复制图片、原生另存为功能正常，但发现 1080×2400 图像模糊且越界。此前两个 64×64 小图的布局测试没有覆盖此缺陷。修复真实元素尺寸、缩略图预算及原图弹窗后，新增横/竖/小图、1–3 列、16/20px rem、100%/200% 模拟 DPI、深浅主题与展开详情断言通过；8 张原生 D3D 渲染图检查通过。用户重新打开原 3 条记录后明确反馈「显示正常」并退出测试窗口。根因、修改前失败断言及独立修复提交见 [47](47-desktop-image-history-rendering-fix.md)。

修改后完整 Debug GPUI App 在此次 3 条真实图片历史查看期间，Windows PeakWorkingSet 为 **178970624 字节（约 170.7MiB）**，200ms 采样 411 次，用户退出后结束。这不是 30 张或长时间压力测试，不含独立 GPU 资源/VRAM，也没有控制原图弹窗等交互完全一致，不能据此前后对比宣称降低内存。

### 受控慢速链路与连续负载

新增仅测试用 TCP 限速转发器，不终止 TLS、不解析或记录载荷。手机先直连独立 LAN fixture 完成配对，然后通过产品手动地址维护 API 只改到同 IP 的随机测试端口，仍使用原完整固定证书、TLS 名、host/device 及令牌。手机测试额外断言上述身份全部保持不变，令牌断言不在失败消息中输出秘密。

每连接/方向配置 128KiB/s 上限，按最多 4KiB 读写且每次增加 10ms 延迟，实际吞吐更低；最多四个同时连接，有读写超时和总生命周期预算。控制和图片连接分别受限，这不是共享瓶颈、丢包/漫游或真实差 Wi-Fi 的模拟。未改系统代理、VPN、防火墙、路由或网络类别。

- 5 张首轮全部完成，3 张超限源图仍拒绝；同样完整生产准备/加密/双 WSS/收据链路，仅输入适配器为 fake。大图发送到终态约 30.22 秒，未延长产品期限或取消块窗口；见 [slow-link.json](benchmarks/2026-11-15-production-images/slow-link.json)。首轮工具启动预算过短，尚未启动手机测试即失败；修正显式数字 IPv4 绑定和工具启动期限后运行，未算成产品失败或通过样本。
- 随后 5 图各 5 次，共 **25 张、约 28.51MiB 最终载荷**全部完成；转发器存活约 **389.69 秒**。发送→持久终态混合 p50/p95/p99 为 **12358.35/30270.17/30273.13ms**。接收核心峰值工作集约 **64.85MiB**，手机 200ms 采样最大 PSS 约 **220.75MiB**；25 次 fake 执行、0 次 NativeInput，没有重放。[原始数字](benchmarks/2026-11-15-production-images/slow-link-soak.json)。这是约六分半的有限负载，不是数小时稳定性或原生粘贴性能。
- 慢速上传首个 48KiB ACK 后连续做 5 次显式取消，再断线重连；同一轮再做 5 次电脑本地暂停/重连。均保留图片草稿和身份，不恢复上传或旧输入意图，输入执行数为 0。手机显式取消→本地 cancelled 的 p50/max 为 **29.53/38.56ms**，不把它说成服务端持久取消确认；marker→手机收到 paused 的 p50/max 为 **126.24/196.55ms**，仍含 fixture 轮询和双向控制。[原始数字](benchmarks/2026-11-15-production-images/slow-pause-lan.json)。

复现：`scripts/verify_image_performance.ps1 -SlowLink -Repeats 5`；暂停/取消为 `-SlowLink -PauseProbe`。SlowLink 明确禁止和 Native 同用，不能将受控转发测试冒充真实目标软件验收。源图和转发连接原始数据留在忽略目录，归档仅含脱敏计数/耗时。

### 30 张历史与原图资源回收

`scripts/verify_image_history.ps1` 实际以 30 条独立受保护合成图片收据启动生产 HistoryView，在原生 D3D 窗口通过菜单/关闭事件反复查看横竖原图 60 次。首轮约 228 秒，虽然 CPU 弱引用会释放、工作集稳定，Private Bytes 却持续增长。直接渲染资源尚留在 GPUI atlas 是根因，新增 atlas key 断言在修改前失败。

已在原图关闭/替换、缩略图淘汰和视图销毁时用既有 GPUI API 释放资源。相同 60 轮重跑约 229 秒通过，关闭态首/末十轮中位私有内存由修改前 **300.47→803.22MiB**，变为 **262.48→254.51MiB**；修改后进程峰值工作集约 **195.60MiB**。满页 CPU 纹理预算、关闭后 CPU 引用和 atlas key 消失、过滤后缩略图 key 消失均有可执行断言。

完整数字、独立提交和限制见 [48](48-desktop-image-render-resource-lifecycle.md)。这些是 2.59MP 合成图、固定 60 轮的结果，不覆盖 16MP 满页、数小时负载或独立 GPU/VRAM 测量。先前仅用「工作集稳定」或「弱引用释放」作为充分证据的判断已被这次测试纠正。

3. 真实多网卡切换、真实 LAN 换 IPv4、API 37 OEM 真机以及进程存活时的授权撤销时序。API 37 系统授权界面已有模拟器实测，不再列为全部未验收。最低版本已明确改为 Android 10/API 29，以符合系统 TLS 1.3 前提；API 26 修改前测试确认缺少该能力，新包实际被系统拒绝安装，API 26–28 不在产品支持范围。旧回退解码器已删除，没有降级 TLS 或放松固定证书，详见 49。

Windows Computer Use 的 native pipe 当前不可用，未改用其他桌面自动化绕过；原生 fixture、GPUI 布局测试和用户人工验收各自记证。缺少环境的测试不记为通过。相关脱敏汇总见 [platform-validation.json](benchmarks/2026-11-15-production-images/platform-validation.json) 和 [manual-smoke.json](benchmarks/2026-11-15-production-images/manual-smoke.json)。

### 独立人工验收入口

先构建本轮 `imageTest` 包并通过隔离脚本安装。然后运行 `scripts/start_image_acceptance.ps1`：打开已安装的 `seeyuer.sayin.imagetest`，启动新 host/device/目录、随机 LAN 端口的接收核心，显示独立地址/端口和 **2 分钟有效的配对码**；测试服务本身存活 10 分钟。只对这个测试身份自动批准；不会打开或替换日常配对。没有自动生成上传或输入。测试者只有在手机明确点击发送时才触发生产 NativeInput，仍执行真实焦点、权限、会话、暂停检查，不追加 Enter。

1. 在已打开的隔离手机应用里用本次地址/端口/码配对；不要进入日常应用或删除日常配对。
2. 选择一张不含敏感信息的 PNG/JPEG，在电脑空白 Word/WPS 文档中放好光标，再点手机发送。记录图片数量、位置、原文是否保留，以及软件完整版本。
3. 在常用聊天软件的安全草稿区域放光标后发送测试图，只检查附件预览，**不要发送给联系人**。确认没有自动回车/发出消息，再丢弃草稿；记录应用和版本。
4. 选透明 PNG 验证透明度；切到纯文本编辑器重复一次，确认不额外输入文字/Enter或打开其他程序。目标不支持图片时，不要求它显示图片，手机也不能承诺已经显示。
5. 后续用独立 GPUI 测试实例检查查看、复制和另存为。人工入口接收核心不带 GPUI，不能冒充这项已经通过。

服务 10 分钟到期退出；提前结束可写入口返回的 stop_file。证据在它返回的忽略目录，含独立身份和收据，不提交。入口只证明工具启动，人工结果必须另外记录。

人工入口初次错误地把 10 分钟服务存活期显示为配对码有效期；用户在两分钟后配对失败。已核对生产配对窗口确为 120 秒，并修正入口分别显示两个期限，未延长窗口或弱化认证。首次未成功配对，不记为人工图片验收；重新启动独立服务并明确两分钟期限后，用户反馈「配对成功」以及上述浏览器/Word 和历史操作结果；后续针对聊天草稿、透明 PNG 及无误发的问题回复「已测试，没问题」。没有虚构后续执行次数或软件版本，保留第 4 节的证据边界。
