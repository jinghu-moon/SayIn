# SayIn 多设备验证计划

更新：2026-11-25。  
状态：验证计划，不构成已通过的结果。规范见 [多设备设计](86-multi-host-multi-device-design.md)。

## 1. 基线与产物冻结

阶段 0 必须先冻结不可变输入，不能只在口头记录“跑过”：

- 固定 v2 代码提交、构建命令、Debug/Release APK 的 SHA-256；
- 独立测试包名与数据目录，不碰日常配对；
- Windows 原用户 DPAPI 数据快照、Android Keystore 可解密样本和旧数据库/账本副本；
- 旧协议黄金向量、真实 v2 双端日志、测试清单与结果目录；
- 生成脚本和校验脚本的版本/哈希；
- 所有基线产物只读保存，修改必须产生新基线编号。

先修复并复现 v2 的 `foreground` 图标超限断线：固定应用名、图标样本、实际字节数、关闭原因和日志；修复后的确定性边界测试必须覆盖恰好 8,192 字节、8,193 字节、超长应用名和超限图标。

已记录的基线事实：在 `0aa9dc4` 运行 receiver/transport/pairing 测试时首轮 112 通过、1 失败，单测复跑仍失败，整组复跑 113 通过；隔离诊断中 `foreground` 帧为 8,885 字节，超过 8,192 上限导致会话关闭。该证据只用于定位，正式修复和确定性回归必须重新执行，不能把“整组复跑通过”当作已修复。

## 2. 升级场景

| 场景 | 必须断言 |
| --- | --- |
| 手机先升、电脑仍 v2 | 不显示为成功；不清空旧配对/草稿；不降级、不自动重配；失败原因可解释 |
| 电脑先升、手机仍 v2 | 旧客户端被明确拒绝或按网络失败提示，不发送凭据；不自动重配 |
| 两端升完、原地升级 | 原 `pair_id`（原 `device_id`）、token、证书/SAN、Outbox、草稿、历史、图片引用、回执可查；旧请求不重放 |
| 升级中止后重开 | 迁移可重入；已提交事务不重复输入；旧数据不丢；失败保留旧入口 |
| 密钥/存储损坏 | 不生成新身份、不发送；保留原数据并阻断；错误可诊断 |
| 证书过期/更换 | 明确重新配对；旧授权失效；旧请求不自动改挂；未决请求按 2.3 规则处理 |
| 主动重配含未决请求 | 有 `accepted/held/executing/uncertain` 时拒绝替换并返回 `PAIR_REPLACE_BLOCKED`；`uncertain` 先本地核对成 `uncertain_acknowledged`；终态后事务转移快照，旧 token 立即失效 |
| 主动重配仅终态 | 新 pair 只能读转移快照；不能 submit/cancel/release/上传；旧接口失效；新请求正常 |
| 旧凭据丢失/重装 | 旧请求只在电脑本地可见；新 pair 不能查询/补发；不误认领旧配对 |

## 3. 单对单回归

复用现有 v2 测试用例，逐项对比：

- 扫码与短码、首次批准、已有身份重连、地址恢复；
- 手动文本、自动文本、显式 Enter、文字不附带 Enter；
- 单图、双图（若独立增量启用）、路径/粘贴、失败阶段；
- 手动/自动发送倒计时、编辑撤销、离页/切目标/前台变化；
- 暂停、恢复、撤销、`uncertain` 核对；
- 历史、草稿、Outbox、回执恢复；
- Android 前后台、网络权限、录音前台服务、真机发现；
- Windows 原生 EDIT/RichEdit 的实际内容与输入次数。

每次断言都必须区分：

```text
已入 Outbox / 电脑 accepted / 系统输入已提交 / 目标实际显示
```

## 4. 多设备与竞态

| 编号 | 用例 | 断言 |
| --- | --- | --- |
| M1 | 2 手机 × 2 电脑交叉并发 | 请求/回执不串；目标切换不误发；A 离线 B 继续 |
| M2 | 同 UUID 在两个 pair | 两个独立请求；作用域隔离；不能互相查询 |
| M3 | 旧 session 迟到提交/查询/图片回调 | 全部丢弃；不影响新 session；不产生第二次副作用 |
| M4 | A `held`，B 提交 | A 只挡自己的配对队列；B 可执行；A 放行后不越过自己的队首 |
| M5 | A 纯文字 `uncertain`，B/C 提交 | 仅 A 的配对被阻塞；B/C 继续；电脑提示 A 的待核对 |
| M6 | A 按键/图片/部分输入 `uncertain` | 整机输入闸门关闭；其他手机被阻断；核对后不重放 |
| M7 | 8 手机接入，1 台 `uncertain` | 文字范围只阻断该 pair；按键/图片范围阻断全部；不因未认证/已撤销连接占用控制槽 |
| M8 | 撤销执行前/预检中/执行标记后/部分输入 | 边界行为符合规范；已产生副作用不重试；未开始请求取消 |
| M9 | 暂停、恢复、再暂停 | 旧恢复不能越过较晚暂停；暂停期间不执行 |
| M10 | 3 台电脑同时有未决请求，只有 2 条控制连接 | 当前+上一目标热连接；其余按需；最坏收尾时间有界；不丢 Outbox |
| M11 | 同一 host 通用添加入口二次配对 | 手机和电脑都返回 `PAIR_ALREADY_EXISTS`；不能产生第二段可发送配对 |
| M12 | 两对手机同时等待批准 | 全机一个邀请/一个待批准；第二请求 `PAIRING_BUSY`；不会互相覆盖 |
| M13 | A 未决时 B 新草稿 | B 可编辑和发送；A 迟到回执不清 B 正文；A 不自动改发 |
| M14 | 图片一批后文字 | 文字期限从成为可执行队首时开始，不因前面图片而提前 `expired` |
| M15 | 图片槽被一对占满 | 另一对按公平策略获得槽位或明确排队，不能长期饿死 |
| M16 | 撤销后连接 | token 快速拒绝；未认证槽不被长期占用；其他 pair 正常 |
| M17 | 短码失败洪泛 | 来源桶与邀请/已认证桶分开；NAT 后不互相耗尽；不锁死已授权会话 |
| M18 | 8,192 帧边界 | 恰好通过；超一字节拒绝/降级；图标超限省略；应用名超 96 字符拒绝或截短规则一致 |
| M19 | `request_rev` 边界 | 单调；`u64::MAX` 拒绝前进；旧 rev 不覆盖新 rev；终态不倒退 |
| M20 | 主动重配旧请求 | 未决拒绝替换；终态快照转移；`uncertain_acknowledged` 不再变化；旧 token 立即失效 |
| M21 | `held` 与期限 | `held` 持有超过 30 秒仍不自动失效；放行后从可执行时刻起算 30 秒；队列中排在图片后的文字不提前过期；`accepted` 在可执行队首 30 秒后过期 |

## 5. 图片与资源

- 单图：手机准备、上传、电脑落盘、目标实际粘贴/路径；
- 旧图片引用、历史、取消和晚到块；
- 双图（独立增量启用后）：顺序、整批/逐张模型、失败后不重复副作用；
- 跨 pair 资源拒绝；控制断开、图片授权失效、撤销、暂停；
- 10 MiB、1600 万像素、8192 单边、48 KiB 块边界；
- 临时文件/资源清理、进程崩溃恢复、配额释放。

图片“已保存文件但粘贴失败”必须通过回执 `st=failed`、`execution.stage=file_saved` 和 `reason` 表达，不能只写 `injected`。

## 6. 性能门槛

阶段 1 结束时必须将下列每项填入具体 p95 毫秒上限、允许超时率和样本数；空门槛禁止进入阶段 2：

1. 热连接点击 → 持久 accepted；
2. 冷连接切目标 → 可发送；
3. accepted → 开始执行；
4. 执行 → 终态；
5. 暂停 → 本地闸门关闭；
6. 暂停 → 手机可见状态；
7. 图片准备/上传/原生粘贴；
8. 2×2 并发下的 p50/p95/p99。

使用同硬件、同 Wi-Fi、同构建、同目标应用、同图片集合和同初始剪贴板；每项报告样本数、失败率、超时率、CPU、Windows 私有内存、Android PSS、连接数、磁盘和空闲功耗。现有 v2 证据只作复跑参考，不能当作 v3 已达成。

## 7. 退出条件

每个阶段只有满足以下条件才能进入下一阶段：

- 该阶段所有新功能用例通过；
- 上一阶段和单对单回归无退化；
- 升级/迁移用例通过；
- 8,192 帧边界、配额和故障注入通过；
- 性能门槛已冻结并有数据；
- 没有未决 `uncertain` 被当作终态；
- 没有跨 pair 数据泄漏；
- 不在测试脚本开始时清空需要保留的升级数据。

真实 2×2 真机、真实 LAN、Android 权限和 Windows 原生控件必须单独留证；假输入、loopback 或测试构建不能替代。

现有 Android 传输套件（隔离 `imageTest` 包 + 回环假输入）可作为单对单和生命周期回归输入，但升级专用测试必须保留包数据，不能复用脚本开头的清空数据步骤。

## 8. 二维码、图标与多图增量

这些增量在 [独立增量](88-multi-device-increment-design.md) 中定义，分别验收，不作为核心 v3 退出条件：

- 二维码：114 个 ASCII 字符，Version 5、纠错 M、37×37 模块；库升级后必须重新断言，防止静默变大。
- 图标：48×48 无损 WebP；8,192 恰好通过、8,193 拒绝/省略；超长应用名与图标同帧；手机真机解码。
- 多图：原型证明整批或逐图；真实目标内容与顺序；整批失败位置；逐图退化文案与顺序。
