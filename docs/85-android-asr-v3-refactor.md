# SayIn Android 语音识别 V3 重构实施方案

状态：本地 V3 已实施，验证见第 7 节。本轮覆盖本地录音、VAD、ASR、ITN 与 CT 标点。云端沿用原有连接、判停和定稿策略。历史行为与实测见 84 号文档。V3 图中的约 2 秒为设计起点，本文将产品默认值定为 **2.5 秒**，允许在 2–3 秒内选择。 [V3 流程图](images/asr-flow-v3.svg) · [84 号方案与实测](84-android-vad-design.md) · [工程规则](../AGENTS.md)

## 1. 用户可见行为

| 用户动作 | 预期行为 |
| --- | --- |
| 进入说话页或快捷卡 | 有已选且已导入的本地模型时，按内存和当前任务状态准备一次。同一模型在相邻录音间复用。 |
| 点按说话 | 先处理麦克风授权和前台服务启动。麦克风实际开始采集后显示「正在听」。引擎尚在准备时暂存从开麦起的 PCM，准备完成后自动识别，无需再点一次。 |
| 开始说话 | 流式引擎有结果就更新当前草稿。窗口式引擎按可用预览更新。非流式引擎在完整句段可解码时尽快上屏。 |
| 短暂停顿 | 当前输入仍可继续。离线引擎可接收分段建议，流式引擎按自身端点或服务回包提交句段。 |
| 暂停 2–3 秒 | 普通点按录音在确认有过有效语音后，按所选时长自动停麦。期限前续说会重置。已出现的文本继续可见。 |
| 点结束或长按松手 | 即时发起停麦，保留已采集的完整尾字，排空必要工作，再提交最终稿。长按和连续听写遵循各自的结束方式。 |
| 定稿 | 允许以最终结果替换本次尚未确认的文本尾部。默认进入可编辑草稿。自动发送仅由成功定稿和现有发送策略共同触发。 |

全页和快捷卡共用会话及草稿。「正在听」对应开麦，「正在收尾」对应停麦后的定稿。继续沿用现有语音栏状态和音量反馈。若静音进度提示经真机验证有助于续说，可在现有录音控件中承载，首轮工程不依赖提示动画。

## 2. 当前实现与改动边界

| 基本事实 | 当前实现 | V3 改动 |
| --- | --- | --- |
| 抢说是否丢字取决于麦克风是否已经采集 | `SpeakSession.start` 等翻译释放及本地模型就绪后才请求录音。云端适配器握手后才打开音源。 | 用户授权后立即采集，所选引擎准备和采集并行。 |
| 录音与识别推进速度不同 | X-ASR、R2T2、离线及云端在不同入口消费 PCM，启动的缓冲时序各异。 | 同一次录音有一个麦克风所有者、一条按样本顺序消费的 PCM 通路和一个选定引擎。 |
| 静音可以提示句段或停麦，句段完成还需要识别结果 | VAD 约 600 ms 报分段，普通点按按 0.8／1.2／1.5 秒停录。 | 共用一个有效语音时间轴，分段门槛与整场停录期限各自独立。 |
| 模型只能对尚未消费的音频做裁剪 | VAD 标记分段和停录，采集块仍交给引擎。Fun-ASR 的现有修复跳过已确认分段后无续说的独立尾音。 | 从 PCM 样本位置决定保留范围，在音频进入相应推理或发送路径前处理。保留 Fun-ASR 已验证的保护。 |
| 模型输出的结果边界和可修订范围不同 | `StreamingTranscript` 合并部分本地结果，云端按协议合并，`SpeakSession` 写入冻结选区。 | 统一草稿接收契约，保留各引擎原有句段语义。 |

直接重构 `RecognitionEngine`、`SpeechRecognition`、`PcmSource` 与调用方。删去被取代的开麦前等待、固定停录分档和重复的麦克风生命周期分支。工程处于开发期，接口及内部数据结构允许破坏性调整，无需为旧接口增加适配层或迁移。原生模型格式、云端协议、草稿持久化和 Outbox 继续复用项目现有实现。 [会话入口](../android/app/src/main/java/seeyuer/sayin/ui/SpeakSession.kt) · [采集与引擎](../android/app/src/main/java/seeyuer/sayin/asr/SpeechRecognition.kt) · [离线分段](../android/app/src/main/java/seeyuer/sayin/asr/OfflineSegmentRecognition.kt)

## 3. 开麦、准备和资源管理

1. **会话一次创建。** 点按时由 `SpeakSession` 冻结录音模式、语音来源、本地静音档位及草稿插入范围，立即请求麦克风前台服务。服务获系统接受后由 `SpeechRecognition` 启动 `AndroidMicrophone`。页面收起可继续已有录音，取消准备或入口失效时禁止迟到的服务回调开麦。
2. **仅准备已选模型。** 说话入口可见且有已安装模型时触发已存在的 `prepareLocal`。由一份准备任务和一个模型实例服务完整页、快捷卡及下一段录音。切换、删除模型或开始本地翻译时由现有资源所有者释放。旧模型仍在 native 调用时，先让调用退出，再释放实例。预热使用内部音频，同时独立于麦克风、云端请求和发送。
3. **冷启动先收音。** 采集线程将 PCM 顺序放入有界通路。首块已采集 PCM 触发 VAD 初始化，随后从该块的首样本开始计算。已进入稳态后避免额外复制或为同一段常驻两份音频。模型仍在准备时，麦克风按真实状态显示「正在听」，文字保持为空直至有识别结果。云端继续在协议就绪之后开麦。
4. **缓冲可量化。** 采集队列限制为 120 个、每个最多 100 ms 的块，16 kHz 单声道 Float32 PCM 上限为 12 秒、约 768 KB。K40 上 Qwen3-ASR 1.7B 加载约 9.4 秒，因此由设计初期的 8 秒增加到 12 秒。队列满后停止采集并将这次录音标为失败，保留已有草稿，避免静默覆盖最早音频或用截短的结果触发自动发送。引擎接管后继续使用同一有界队列，离线和窗口引擎仍受各自句段容量限制。
5. **短会话也能排空。** 开麦后在引擎准备期间即停录时，将本次已收音频连同结束原因封存，待该引擎就绪后只消费一次。本地引擎就绪的墙钟上限为 12 秒。停麦不会延长截止时间。准备失败、取消或超时立即作废本次缓冲和发送资格。网络失败后按现有恢复流程保留草稿。

复用现有状态，收敛为未开麦准备、采集中、停麦收尾、终态四类。模型准备状态与录音状态分别表达真实资源和录音事实。采集生产者负责递增样本位置及物理停麦，识别任务负责消费、排空及报告成功或失败，`SpeakSession` 负责展示与草稿。模型就绪、停麦与取消事件带会话 ID，过期结果不能进入新会话。

## 4. 识别与上屏

| 引擎 | 录音期间 | 收尾 |
| --- | --- | --- |
| X-ASR 480 ms | 复用原生识别流，随帧供音频，立即展示部分结果，以模型端点确认句段。 | 对未送入的尾音应用保留策略，沿用经验证的模型补尾和排空，定稿阶段有界补标点。 |
| Confucius4-R2T2 | 复用现有 1.2 秒首轮及按窗口更新逻辑，保留前填、投影和生成分项计时。 | 取消过时预览，按顺序完成剩余段。按实测决定是否能开放更多可修订尾部。 |
| Qwen3-ASR 0.6B | 保留有界预览及实时率约束。自然停顿建议分段，合并短段保护中英混说。 | 优先处理已就绪段和最后的有效音频。 |
| Qwen3-ASR 1.7B、Fun-ASR-Nano 2512 | 自然停顿后尽早提交段并继续收音。持续讲话时由有界窗口推进，缩短窗口需同时证明语义、数字和中英混说准确性。 | 按序完成未确认尾段，已确认段无需重解。 |

在已有文本合并点收敛输出语义。一次识别更新包含已确认前缀和当前可替换尾部，或等价的完整转写快照。相同文本去重，旧预测不得覆盖新定稿。引擎出现真实重复语句时保留原话。UI 将当前快照替换到本次冻结的草稿范围，保护原稿两端、选区与会话身份。完整稿只提交一次。本次原始定稿先经过有限范围的中文 ITN，再尝试 CT 补标点；两步只处理本次录音文本。具体约束见第 7 节。过期或失败的后处理不可修改用户后来编辑的草稿。

## 5. 停顿计时与尾音

### 5.1 一个时间轴，两种决策

- **分段建议**从最后一次有效语音开始，使用 600 ms 的独立门槛。对离线及窗口引擎，这是提交候选边界。X-ASR 的文本端点由模型确认。
- **自动停麦**从同一个语音位置起算。设置「静音后结束」，选项 **2 秒／2.5 秒／3 秒**，默认 **2.5 秒**。放在「设置 → 语音识别」，复用 miuix `WindowDropdownPreference`，使用双语资源。保存一个毫秒值，每次点按录音开始时读取一次，缺值或非法值使用默认档。分段发生或文字出现均不会改变这段计时。配置只影响普通点按录音，长按由松手结束，连续听写由用户结束。
- VAD 在采集侧标记最后一个有效语音帧的音频样本位置。对续说使用现有最低有效语音时长及底噪自适应作为基线，通过轻声、短词和脉冲噪声验证。疑似续说的帧先保留，跨越截止点的候选按有界判定窗口确认。只有确认的续说才能重置计时，孤立噪声不能反复延长。实测报告候选确认带来的停麦偏差。
- 空会话、采集故障与 120 秒上限继续独立处理。VAD 失败时切回手动停录并给出已有状态提示，保守保留音频。手动与自动事件按会话串行仲裁，截止前已收到的手动结束意图优先，已关闭的采集只收尾一次。

### 5.2 在音频仍可处理的地方保护尾字

1. 采集侧保留绝对样本位置和最后有效语音位置。段内自然停顿原样保留。识别提交时保护尾字，保留 **约 200 ms** 加一个 32 ms VAD 窗口的真实语音上下文。边界不确定时保留实际音频。
2. 非流式和窗口模式在最后一段提交前裁剪已确认的多余静音或尾噪，手动及自动停止共用此处理。已确认句段后没有有效续说时，不为尾噪单独生成一个新解码任务。复用已经通过 K40 用户实测的 Fun-ASR 分段保护。有效续说恢复其音频范围及必要前文边界上下文。
3. X-ASR 暂存最多约 600 ms 的已判静音尾部。检测到续说时按序补喂近期原始 PCM。静音持续时，将超出暂存窗口的块替换为等长静音，维持原生端点时钟。停麦时丢弃仍未送入的已判静音，并沿用原生补尾。VAD 降级时按序释放暂存音频。
4. VAD 能估计有没有语音。背景人声可能仍被判有声，语音和噪声叠在一起时也不能靠裁剪完全分开。对随机尾字保留同一 PCM 的原尾、等长静音和裁剪三路对照，并比对录音中预览与最终输出。若干净结尾仍出现随机字符，继续定位该引擎的结束解码。真实说出的「对」「嗯」和用户口述的符号、路径需要保留。 [现有判停器](../android/app/src/main/java/seeyuer/sayin/asr/VadEndpointTimer.kt) · [X-ASR 补尾](../android/app/src/main/java/seeyuer/sayin/asr/XAsrDecoder.kt)

### 6.1 自动化与真机矩阵

- **JVM**。复用 `VadEndpointTimerTest`、`StreamingRecognitionTest`、`OfflineSegmentRecognitionTest`、`PunctuationGuardTest`、`DoubaoRecognitionTest`、`QwenRecognitionTest`。补充任意分块与尾帧、2／2.5／3 秒边界、恰在截止前后的续说、噪声脉冲、VAD 故障、缓冲达到上限、停录与就绪同时抵达、前一会话迟到回调。需要证明 PCM 的样本范围和顺序。
- **隔离真机**。复用 `AudioSourceInstrumentedTest`、`UnifiedSpeakInstrumentedTest`、`ImportedAsrInstrumentedTest` 和各非流式夹具。新增真实节奏供帧的回归，覆盖短句紧接停止、约 20 秒连续讲话、0.5／1／2 秒自然停顿、轻声尾字、尾随键盘声／风扇声／旁人说话、蓝牙和短时间反复录音。麦克风实录与 PCM 回放分别报告。
- **原功能**。完整页、快捷卡、磁贴、悬浮球、长按和连续听写共用一个录音会话。回归识别期间编辑入口、自动发送与取消、电脑掉线或换目标、等待回执保留草稿、翻译资源竞争、云端末包，以及 X-ASR 标点结构保护。使用现有隔离通信套件核对零重放和预期假输入次数。

### 6.2 度量与放行

| 指标 | 首轮验收门槛 |
| --- | --- |
| 点按到开麦 | 对比冷／热启动。已有授权的普通点按，K40 热启动目标 p95 ≤ 500 ms。冷启动记录模型尚未就绪时的首音频完整性。 |
| 开口到首字与持续更新 | X-ASR 目标 p95 ≤ 1.8 秒。流式引擎用不补长静音的连续语料，另报可见文本最长更新间隔。R2T2 单独报告实际延迟。 |
| 说完到停麦、停麦到定稿 | 两项独立计时。确定性夹具按配置阈值及实际 VAD 步长对齐。真机单列 VAD 判决偏差。对 ≤10 秒非流式样本，停麦到定稿以 p50 ≤ 2 秒、p95 ≤ 3 秒为目标，报告未达标模型。 |
| 文本质量 | 对相同标注集比较 CER／WER、首尾字保留率、无语音尾部误出字次数、重复率及误停率。可复现的尾噪回归用例应无多余尾字，真实尾词须保留。 |
| 稳定性与资源 | 同条件记录模型预热、队列峰值、内存、长时发热和停录后资源释放。单列空会话、取消、超时、失败与发送次数。 |

指标是本轮目标。每个设备、模型及路由分别报告样本数、p50、p95、失败和跳过原因。对核心用例用同一输入做前后对照，先确认旧缺陷能复现，再确认新行为及原链路通过。K40 是当前主验证机，K90 Pro Max 数据按设备另列。未完成的真机或付费用例在结果中如实登记。识别与发送判定不得通过放宽断言提前放行。

从仓库根目录运行 `scripts/gradle.ps1 :app:testDebugUnitTest :translation:testDebugUnitTest :app:lintDebug :app:assembleDebug`、`python scripts/check_i18n.py` 和 `git diff --check`。隔离套件用 `scripts/verify_android_transport.ps1 -DeviceSerial <序列号> -FullSuite`，模型实测按需单独执行，套件清理只作用于隔离包。日常包使用 `adb -s <序列号> install -r android/app/build/outputs/apk/debug/app-debug.apk`，再核对安装输出、首次安装时间与前台 Activity。

## 7. 实施记录

| 环节 | 实施 |
| --- | --- |
| 启动 | 可见说话入口预热所选已导入模型。点按后由系统前台服务许可开麦，与模型准备并行。服务回调验证请求代次。模型未就绪时原样暂存 PCM，允许先停麦再排空。 |

### 7.3 静音、短段出字与时长 ITN 复查

- K40 反馈时选择了 Fun-ASR-Nano，并启用了连续听写。此模式的 VAD 仍提供分段，整个录音由用户手动停止。设置页明确说明「静音时继续录音」，录音栏显示「手动结束」。关闭连续听写后，点按录音按所选时长停麦。
- 本地 VAD 用 5 个 32 ms 帧中的 4 个有声帧确认短句，允许中间漏判一帧。续说用 4 帧中的 3 个有声帧确认，单次噪声脉冲不重置静音期限。普通点按的 10 秒无语音等待独立于首次有效语音后的停麦期限。
- Fun-ASR-Nano 和 Qwen3-ASR 1.7B 在约 600 ms 的自然停顿处提交句段。Qwen3-ASR 0.6B 遇到较短句段时立即排入可替换的预览，并保留后续合并所需语境。离线模型连续说话的解码窗口从 20 秒缩为 10 秒，使长段可以提前上屏。
