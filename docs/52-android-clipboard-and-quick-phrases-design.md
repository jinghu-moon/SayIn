# Android 剪贴板与常用语组合面板设计

状态：设计与交互 demo；原生实现、验证与差异记录见 [53 实施记录](53-android-input-assist-implementation.md)。日期：2026-11-15。修订 2：清除全部、常用语拖拽排序、两个列表的复制/粘贴菜单。

后续边界确认（2026-11-15）：**非 Root 手机保持本文单条剪贴板现状；Root 手机通过模块独立采集，计划由 SayIn 在同一剪贴板标签读取和管理模块历史**，不靠保活 SayIn 采集。见 [55 调研及已确认方向](55-android-clipboard-projects-research.md#7-对-sayin-的落地方向)。模块侧限定采集及加密历史已实现，见 [60](60-root-helper-native-clipboard-collection.md)；App 面板读取尚未接入，以下首版范围和验证不包含该增强。

原生现状以 [51 三区语音栏](51-android-three-zone-voice-bar.md)、当前 `SpeakPage.kt` / `SpeakSession.kt` 为准。评审原型：仓库根 `refer/SayIn 底部控制区对比.html`；它是被 Git 忽略的本机参考文件，仓库内保留相同内容的评审快照 [组合面板 demo](demos/sayin-input-assist.html)。本设计不代替现有协议说明。

## 1. 目标、事实与边界

用户目标是快速复用一段文字，放入正在编辑的草稿，再通过既有方式输入电脑。两种来源共用一个高频入口：剪贴板代表临时内容，常用语代表用户明确保存的内容；它们都是草稿编辑操作。

当前完整页与快捷卡共享 Application 级 `SpeakSession`，有原文/完整译文、选区、有限撤销历史和独立的提交请求。接收端按最终焦点执行，手机不能撤回电脑输入。新增功能应进入该唯一草稿所有者，不能另建一份草稿、Outbox 或发送路径。

当前 `Protocol.kt::normalizedText` 校验合法 Unicode，发送前将 CRLF、CR、LF、Tab 规整为空格，拒绝其他 C0 控制字符及 DEL，并要求规整后不超过 4000 个 Unicode 码点、UTF-8 不超过 16384 字节。这里的“4000 字符”不是 Kotlin `String.length`，也不是字素数。草稿可保留换行和 Tab；本功能不承诺向电脑输入多行，不改变规整/预览/发送语义。

首版范围：手机当前剪贴板中的文字、手动维护和拖拽排序的本地常用语、光标插入/选区替换、撤销重做、列表复制/粘贴、按当前标签确认清除全部、完整页/快捷卡统一行为。排除后台剪贴板采集、剪贴板历史、电脑剪贴板同步、云同步、模板变量、分组/搜索、长按发送、自动发送新来源内容。使用中文和 English，跟随当前应用语言；不翻译用户保存的正文。

## 2. 主界面入口与布局

沿用用户截图中的布局，不把复制、清空迁移到顶部，也不再常驻增加短语标签行：

```text
草稿卡顶部                                      撤销  重做

草稿正文

字数                   剪贴板  图片  翻译  复制  清空
                       └组合入口：剪贴板 / 常用语

键盘键                  固定 56dp 三区语音栏
```

- 组合入口在图片图标左侧，Tabler `clipboard-text`，无常驻文字；无障碍/长按提示为「剪贴板与常用语 / Clipboard and phrases」。
- 五个底部工具都保留最小 48×48dp 点击区，内部图标约 21–22dp。字数使用剩余宽度，不压缩图标命中区。
- 普通宽度无译文切换时保持单行；原文/译文切换出现时独占上一行，工具与字数在下一行。约 320dp 的极窄屏把字数移到工具上一行，与译文切换共用左右空间，避免压成不可读数字。避免把 5 个工具和双标签硬塞入 320–360dp 宽度。正文高度自适应减少，不让工具覆盖正文。
- 正常 320dp 起可用；极小横屏/高 IME 按 51 的可用高度策略收起次级工具，顶部「更多」提供同一个组合入口作为后备。后备不建立第二套面板状态。
- 非主题颜色沿用 Yue neutral。品牌/选中/主操作色 `#1f75db`；错误使用现有 Yue 功能色，不引入新配色。暗色面板 neutral-900、页底 neutral-950，分隔/悬停使用 neutral 系列。

## 3. 面板形态与打开/关闭

采用 Miuix 的原生底部浮层，距左右与底部安全边 8–12dp、圆角约 26dp；不是依附光标的小弹出菜单。正常高度约可用高度的 55%–60%，可见 4–6 条，列表独立滚动；大字、短屏、横屏允许扩展至安全高度，关闭入口始终可达。

```text
╭────────────────────────────────╮
│              ━                 │
│   剪贴板      常用语      ＋  ×  │
│────────────────────────────────│
│ ⠿ 收到，我稍后回复你。        ⋮ │
│ ⠿ 我正在开会，结束后联系你。  ⋮ │
│ ⠿ 这部分已确认，可以继续。    ⋮ │
│                                │
│            清除全部            │
╰────────────────────────────────╯
```

「＋」和左侧拖拽手柄只在常用语标签出现。剪贴板标签最多显示一条当前文字，不伪装成系统剪贴板历史。列表底部固定一个「清除全部」按钮，只作用于当前标签；编辑、单条删除放到条目菜单，不另加「设置」大按钮。列表可滚动，底部按钮不随列表滚走；空列表时禁用，编辑短语时隐藏。

打开步骤：先记录当前显示表示及选区 → 撤销自动发送/结束发送意图 → 收起 IME → 展开面板。原生关闭 IME 不等于让应用失去窗口焦点；等待面板与当前 Activity 获得输入焦点后，再执行本次用户授权的剪贴板读取。面板期间不能继续编辑背后正文或启动录音。

- 首次默认剪贴板；随后记住上次使用标签，完整页/快捷卡一致。只保存这个 UI 偏好，不保存剪贴板内容。
- 点条目：插入成功后关闭，软键盘保持收起，光标移到插入末尾；不主动拉起键盘，可继续说话或手动发送。此规则同时适用于剪贴板和常用语。
- 点关闭、遮罩或系统返回：关闭面板，草稿不变。原生支持返回手势；无障碍焦点回到组合入口。
- 切页、离开应用、入口形态切换、请求冻结：关闭本入口的面板，使打开票据失效。回来后不恢复剪贴板快照或未完成插入。
- 切到别的面板时先关闭当前面板；识别设置、连接、图片预览与本面板互斥，不能叠放多层。
- 常用语编辑器有未保存修改时，系统返回/关闭先显示保留与放弃选项；单纯插入与保存正常流程不增加确认。demo 用提示和「返回列表」显式放弃表示该路径。

## 4. 剪贴板标签

### 4.1 读取与展示

进入该标签时读取一次当前 primary clip；切到常用语后再返回可重新读取。面板不订阅常驻变化，不定时轮询，不在应用启动、页面重组或后台读。当前标签离开/面板关闭/生命周期失焦时清掉快照和读取任务；迟到读取结果必须经过 generation、窗口焦点及当前标签校验。

仅接受第一项明确的 `ClipData.Item.text`，转为普通字符串；有样式的文字去格式、保留文字。URI、Intent、图片不解析为文字，不调用会读取 URI 的 `coerceToText()`，不通过 ContentResolver 打开剪贴板文件；多个项目首版只处理首项并给出简短说明。Android 无法读取时不能伪报为空或再创建“授权剪贴板”的假权限步骤。

读取上限先检查 UTF-16 长度，超过 64000 个单元不复制到第二份业务缓冲区，直接显示「内容过长」。随后检查正文合法性、规整后码点与字节上限；不可插入内容不展示为可操作正文。4000 码点或 16KiB 仅是最终插入预算，不能把整个大剪贴板先无界读入应用自建历史。

### 4.2 状态与动作

| 状态 | 展示 | 可做什么 |
| --- | --- | --- |
| 有合法文字 | 最多两行预览，保留换行语义；长文可展开只读预览 | 点正文插入并关闭；⋮ → 复制 / 粘贴 / 保存为常用语 |
| 空或只有空白 | 「剪贴板暂无文字」 | 复制后重新进入标签 |
| 只有图片/URI/Intent | 「剪贴板中没有文字」 | 使用外部已有图片入口；不误插入路径 |
| 无焦点、系统返回 null、读取异常 | 「暂时无法读取剪贴板」 | 在应用前台点重试；不改草稿 |
| 超限/非法控制字符 | 显示对应原因，不截取部分后插入 | 用户到原处缩短或使用系统选区复制 |
| Android 标记敏感 | 遮住正文，明确点「显示」后才预览；禁止一键保存为常用语 | 用户明确显示后可插入，不加入任何历史缓存 |

「清除全部」在此标签清除当前系统 primary clip（含当前图片类条目），不清常用语、草稿或输入历史。无焦点、无法取得当前剪贴板状态时禁用。原生调用 `ClipboardManager.clearPrimaryClip()` 前后验证当前窗口/面板 generation，并在确认期间内容变化时拒绝清除新内容，请用户重新确认；不自动清除后续复制的内容。原有草稿复制按钮仍按原逻辑工作。

### 4.3 两个列表共用的复制 / 粘贴

用户已确认下表。两个列表的菜单文案统一为「粘贴」；其目标为当前草稿，而不是修改常用语或再次读取系统剪贴板。

| 操作 | 内容来源和目标 | 面板 | 草稿撤销 |
| --- | --- | --- | --- |
| 点列表正文 | 将该条正文插入当前草稿/替换选区 | 成功后关闭 | 一次独立事务 |
| ⋮ → 复制 | 将该条正文复制到系统剪贴板 | 保持打开，菜单收起 | 不修改草稿 |
| ⋮ → 粘贴 | 将该条正文插入当前草稿/替换选区 | 保持打开，菜单收起 | 一次独立事务 |

两种插入使用相同验证、选区和发送安全规则。菜单「粘贴」成功后，必须把面板插入票据更新到新修订和插入末尾的折叠光标；后续粘贴紧接其后，每次可单独撤销，不使用第一次打开时的旧范围。若插入被拒绝，面板保持，草稿与票据不变。菜单「复制」在系统写入成功后提示「已复制」，失败则说明原因，均保持面板和原稿；不因为复制触发发送、删除条目或自动保存为常用语。两个列表的菜单均同时具备复制和粘贴。

### 4.4 保存为常用语

条目 ⋮ → 保存为常用语 → 同一面板内的编辑器，预填本次显示的文字 → 保存成功 → 留在常用语标签。**保存本身不插入、不发送**。若内容已存在，提示「这条常用语已存在」，保留编辑器内容。

## 5. 常用语标签

### 5.1 列表

每条只保存正文，不强迫起标题。正文最多预览两行，保留多行内容，长内容通过条目菜单只读预览完整内容。点条目正文插入一次并关闭；⋮ 菜单包含「复制」「粘贴」「编辑」「删除」。右侧 48dp dots-vertical 与左侧 48dp `grip-vertical` 各自独立，不能冒泡导致插入。首版不采用长按发送，长按最多作为打开同一管理菜单的辅助方式。

新条目放列表末尾，原位置编辑不重排，重新打开保持稳定顺序；不自动按最近使用重排。上限 100 条，每条非空、合法 Unicode，规整后不超过 4000 码点/16384 字节；列表摘要只在展示时裁剪，保存正文不截断。不预置「收到」等示例到真实用户库，demo 示例须明确标注。

### 5.2 拖拽排序

手指按住手柄后拖动；未超过位移阈值时不启动排序。正文区域仍用于点选插入和列表滚动，不把整行长按绑定为拖拽。开始拖动给予轻触觉反馈，浮起当前行并显示当前位置；靠近列表上下边缘自动滚动。放手后一次提交完整 ID 顺序，刷新或重新打开保留用户顺序。原生复用现有列表与指针机制，不为此引入另一套列表状态。

拖动过程中不插入、不复制、不发送。系统取消、Escape、离开面板或失焦撤销未提交的排序；保存失败恢复原顺序并提示，不提前声称保存成功。提交绑定库 revision 和 ID 全集，其他入口增删后旧排序不得覆盖新列表。顺序只改变已有列表的数组位置，ID 和正文不变，不另建排序表。

无障碍提供上移/下移动作与位置播报，键盘焦点在手柄时用上下方向键移动。首尾边界不越界，也不把焦点转到正文造成插入。demo 支持手柄指针拖动、边缘移动滚动及上下键；真实触觉和持续边缘滚动由原生阶段验收。

### 5.3 新增/编辑/删除

- 「＋」打开同面板编辑器，空正文开始，不自动读取草稿或剪贴板。用户无需理解来源猜测。
- 编辑器只有正文、计数、返回和保存。空白/超限/重复时保存不可用，同时解释原因；验证不改变正文空白。
- 保存时先验证并原子落盘，成功后更新列表。失败保留编辑内容与旧库，显示「保存失败，请重试」，不提前显示成功。
- 重复判断：同正文按 CRLF/CR 统一为 LF 后逐字符比较，大小写、其他空白、Unicode 组合形式均不擅自合并。
- ⋮ → 编辑：保留 ID 与列表位置；⋮ → 删除：提交删除后显示 6 秒「已删除常用语 · 撤销」。撤销失败或库已满时明确说明，不能显示已恢复；不复用草稿撤销栈。
- 无条目时显示「还没有常用语」与「添加常用语」。有条目时不增加常驻说明文字。

### 5.4 清除全部与确认

两个标签的底部都显示「清除全部」，作用域取决于打开确认时的标签，不跨标签清空。点击后在面板之上显示确认框，默认焦点在「取消」，背景面板暂不可操作。

| 当前标签 | 标题与说明 | 确认后 |
| --- | --- | --- |
| 剪贴板 | 「清除剪贴板？」；清除当前剪贴板内容，草稿和常用语不会改变 | 保持面板打开，显示剪贴板空状态 |
| 常用语 | 「清除全部常用语？」；删除全部 N 条、无法撤销，草稿和剪贴板不会改变 | 原子提交空库，保持面板打开，显示常用语空状态 |

按钮为「取消」「清除」。返回/Escape 只取消确认、不关闭面板；确认前不能执行删除。库/剪贴板在确认期间发生变化时，拒绝使用旧确认重新清空，提示「内容已变化，请重新确认」。短语清除提交需检查 revision，失败保留旧库，不显示清除成功。此批量操作已经要求明确确认，首版不再提供整库撤销；单条删除的 6 秒撤销继续保留，清空后旧单条撤销不能恢复内容。

## 6. 统一插入事务

### 6.1 目标票据

打开时捕获 `draftId + displayedRepresentation(original/translation) + displayedContentRevision + selection + panelGeneration`。译文需要独立的可观测内容修订：当前 `changeDisplayedDraft` 不随译文编辑更新原文的 `interaction.version`，不能直接把原文 version 当译文版本。原生实施应补齐表示层修订与统一插入操作，而非在 Composable 里拼接字符串或用临时 hash 绕过。

返回数据必须同时满足：同一会话、同一表示和修订、同一面板 generation、当前可见及可编辑。若不满足，保留草稿并提示「草稿已变化，请重新选择插入位置」，不静默改成追加，也不把旧 Activity 的任务写入新会话。

选区使用 Kotlin UTF-16 下标，插入前检查起止合法且不位于代理对中间；反向选区按 min/max 替换。已有合法光标就在那里插入；没有有效编辑位置时，**在打开时**确定为末尾。不能在提交时因旧选区失效猜测新位置。

### 6.2 执行

1. 校验打开票据与当前状态。
2. 拼出完整结果：前缀 + 文字 + 后缀；不自动加空格、标点或换行。
3. 以最终完整结果调用与协议一致的验证；超限整次不插入、不截断，原稿和选区保持不变。
4. 在 `SpeakSession` 中执行一个独立编辑事务，前后切断连续键入合并组；原文编辑使旧译文失效，完整译文编辑保留原文和有效译文来源。
5. 取消当前自动发送与明确结束发送票据，清掉可编辑终态的旧 submitted 关联；不改变自动发送偏好，不授权新倒计时。
6. 更新光标、持久草稿与撤销栈；点条目则关闭面板，菜单「粘贴」则保留面板并轮换插入票据，给轻量成功反馈。

撤销一次回到插入前的文本、选区、完整译文及录音时长；重做恢复插入结果。读取、保存常用语、切标签、取消面板不产生草稿历史步骤。不能调用整页 `restore()` 重置会话，不能复活旧请求身份。

### 6.3 状态矩阵

| 草稿/链路状态 | 打开及插入 | 说明 |
| --- | --- | --- |
| 空稿/普通草稿、未连接或电脑暂停 | 允许 | 草稿编辑不要求电脑在线；真正发送仍由现有闸门决定 |
| 完整译文已显示 | 允许 | 插入译文，原文保留；只显示 partial 时不允许 |
| 录音准备/录音/收尾、IME composition | 禁止 | 不与流式写入/组合文字争抢选区 |
| 翻译运行/安全停止/模型准备 | 禁止 | 等实际任务完成，不隐式取消后强行插入 |
| 草稿恢复、草稿存储故障 | 禁止 | 保留故障提示，不用临时草稿绕过 |
| saved/accepted/held/executing/review/uncertain | 禁止 | 冻结请求不可修改；不释放 held、不补发、不解除待核对 |
| 已确认 failed/expired 等现有可编辑终态 | 按现有规则允许 | 新编辑不等同于重试旧请求；提交仍走现有 Outbox |

## 7. 技术落点、存储与双端关系

以下为待实施建议，不表示这些类已经存在：

| 责任 | 落点 |
| --- | --- |
| 插入票据、表示层修订、单事务撤销 | 共享 `SpeakSession`；复用 `DraftHistory`，抽出明确的插入命令而不是伪装连续键入 |
| 当前剪贴板一次读取 | Activity/平台适配层；结果带任务代次，不把 Context/ClipboardManager 放进持久状态 |
| 面板与管理 UI | `SpeakPage` 及独立组合面板 Composable；Miuix 公共组件、Tabler 现有生成链 |
| 短语库 | Application 级唯一持有者串行 I/O；列表是状态流，完整页/快捷卡观察同一份 |
| UI 偏好 | 现有 presentation 设置里仅保存 lastTab |

短语数据最小结构为 schema version、revision、列表 `[id: UUID, text: String]`；列表顺序就是拖拽后的持久顺序，不增加独立排序表、标签、使用计数或文本索引。排序和清除全部与增删共用串行所有者及库 revision，不能各持一份列表。短语正文与草稿一样属于用户内容：复用现有 Keystore AES-GCM + AtomicFile 方法，使用独立 alias/AAD 和 `noBackupFilesDir` 文件，不拷贝配对密钥或把正文写进 SharedPreferences。100 条×每条预算的编码总量设 2MiB 上限，读写前核对长度与结构；存储损坏拒绝静默覆盖，数据故障不影响原有语音/手工编辑草稿。

短语加载失败时仍可使用当前剪贴板；短语写入串行，写成功才发布新库修订，避免完整页/快捷卡覆盖彼此。坏库不当空库保存。无需为 100 条简单列表增加数据库依赖、同步服务或后台服务。取消页面读取不撤销已经原子提交的用户保存操作。

电脑端与协议无需新增消息。电脑只接收用户最终提交的文字，不需要知道文字来自剪贴板还是常用语。正常接收、范围认证、旧请求先查询、不重放、uncertain、held、主动暂停和存储阻断均保持不变。不在手机展示无法保证的“下一次会输入到某软件”目标承诺。

剪贴板内容只在可见标签的临时内存中存在，不落盘、不写日志、不上传；保存常用语必须由用户明确操作。用户选择插入后，内容进入已有草稿/历史的既有存储流程，这一点不描述成“永不保存”。本项目当前禁止 Android backup；首版不新增导出或云同步。
