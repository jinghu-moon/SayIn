# Android 说话页与双端连接联动重构

日期：2026-11-14。设计依据：[手机 Demo](demos/sayin-mobile-speak.html)、[Demo 说明](demos/sayin-mobile-speak-design.md)、[桌面接收页重构](29-desktop-receive-ui-refactor.md)。

## 目标与实际范围

手机负责采集、编辑、发送，电脑在后台把明确发送的文字输入当前光标。日常发送不增加桌面确认步骤；首次建立信任和不确定输入结果的核对仍必须由电脑明确授权。

本次修改 Android 原生界面、前台连接恢复、地址维护及本地模型生命周期。继续使用 Miuix、Tabler、品牌色 `#1f75db` 与 Yue neutral；没有照搬 HTML 评审开关、模拟识别或延时准备。桌面产品协议已包含 `pause_reason`，手机直接接入；桌面测试例程补充不确定输入刺激，不改变真实产品输入实现。

## 升级前后

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 说话主操作 | 识别来源在草稿上方，输入与发送是并排文字按钮 | 草稿优先；来源贴近底部，中央主按钮，两侧清空/发送 |
| 连接入口 | 草稿上方独立信息行，点击可能直接重连 | 顶栏状态入口，点开原生底部面板，正常连接不会断开 |
| 接收暂停 | 手机提供暂停/恢复电脑输入按钮 | 手机只解释真实原因，恢复与核对去电脑完成 |
| 暂停原因 | 只读取 paused 布尔值 | 同时读取真实 `pause_reason`，区分主动暂停、待核对、未选中设备、未准备好与收据恢复 |
| 已配对掉线 | 主要靠显式连接或重新进入前台 | 前台使用原身份自动重连，间隔 1/2/5/10 秒，最多 10 秒；后台取消 |
| 电脑地址改变 | 没有维护入口 | 连接帮助内更新 IPv4:端口，保存并重连，保留证书/主机/设备/令牌与 Outbox |
| 本地模型 | 每次录音重新加载并释放权重 | 选本地时真实加载、静音预热、就绪；页面生命周期内复用权重，每次录音新建识别流 |
| 发送受阻 | 按钮禁用，需自行找原因 | 有有效草稿时允许点击发送查看连接原因，未就绪不入 Outbox、不清草稿 |
| 很小的窗口/键盘 | 原有紧凑布局 | 紧凑布局缩小辅助控件，将自动发送开关移到操作区，保留至少一整行编辑与可见发送入口 |

## 界面与生命周期

- 草稿直接编辑，不再固定显示“编辑”按钮；只有换行/制表符会在协议归一化时变化时才提供预览，原文不被预览覆盖。字数使用 Unicode code point 计数与复数资源。
- 默认手动发送，保留原有智能发送条件与 3 秒可取消窗口。只有明确完成输入或明确结束并拿到 ASR final 才能授权；长文本、英文、编辑后的文本仍提示人工发送，不扩大自动发送权限。
- 查看连接面板、修改、清空、切换来源、离开页面、进入后台和接收范围改变均取消尚未执行的自动发送。恢复连接不会重新授权。
- `ReceptionScope` 加入连接代次及端口；即使同地址、同 target、同 revision 快速恢复，旧自动发送票据或排队发送也不能进入新连接。
- 顶栏与连接页共用状态呈现，底部面板与连接页共用配对操作。扫码/短码是首次连接的备选路径，均调用原生安全流程并等待电脑批准。短码与邀请不写入 saved instance state。
- 正常连接时无重复“知道了”按钮；帮助按需展开。删除配对保留明确确认，避免误删身份。重连过程中不会清除正在编辑的地址。
- 连接面板为标题与关闭入口保留独立空间，内容可滚动，并避开底部系统手势区。来源选择根据可用宽度与系统字号省略辅助图标，让文字优先；英文 150% 字号检查来源标签不被拆成多行。
- 当前协议没有经过认证的电脑显示名称，因此顶栏显示本地化“电脑”，而不是虚构工作电脑名称；保存地址留在帮助里。桌面显示手机商品名仍沿用 `DeviceDisplayName`。

## 双端与持久化边界

`VoiceLinkRepository` 的有界 mailbox 继续独占连接代次、凭据维护和 Outbox 写入。自动重连只恢复 TLS/认证并查询旧收据，绝不重发文本。状态恢复完成前不能发送新请求；旧 unknown 的人工重试仍复用原请求 ID，uncertain 没有自动重试。

地址更新只复制现有加密身份 JSON 并替换规范 IPv4 与端口。主机 UUID、设备 UUID、token、TLS 主机名和固定叶证书保持不变；错误地址不能让客户端信任另一台电脑。存储失败仍停止发送，不能通过重建身份绕开历史去重。

桌面 `outcome_review_required` 高于普通暂停呈现。手机重连后从桌面重新获取真实状态，不能把网络恢复映射成 resume，更不能发送 `locally_reviewed`。电脑网络分类与防火墙保持原策略：不要求改成专用网络，也不自动修改系统策略。本阶段未包含 mDNS；后续 [40 自动发现与重连](40-paired-host-discovery-and-reconnect.md) 已实现原身份的 IPv4 有界发现与认证后路由提交，手动地址维护继续保留。没有空闲后台保活。

## 本地模型准备

加载与预热在后台工作线程执行。预热使用独立静音识别流，不打开麦克风、不修改草稿、不触发云服务或 LAN 发送。准备期间主录音入口禁用，真正就绪后再由用户点按录音。

模型权重和录音推理由同一互斥锁保护。单段结束/取消后替换流，避免已调用 inputFinished 的流被复用或污染下一段；离开页面取消任务并等待推理结束再释放模型。本轮验证功能正确性，没有测量端到端 p50/p95、长期功耗或作出延迟提升数值承诺。

## 验证记录

升级前 Debug 构建及 **39 项 JVM 测试通过**。原 23 项设备基线中，前 11 项数据/模型/通信测试完成，随后 MIUI 拦截后台启动测试 Activity，运行中断，不能声称全套基线通过。

测试宿主现通过 shell 显式打开 debug-only 空 Activity，再让 ActivityScenario 管理测试页面，不修改手机后台启动权限；宿主与正式 Activity 一样开启 edge-to-edge/adjustResize。UI 偏好使用独立命名空间；语言预览显式保留 ActivityResultRegistryOwner，避免配置 Context 替换破坏权限 launcher。测试先等待输入法真实显示，再清除编辑焦点并收起，避免异步弹出与关闭请求竞争；导航、草稿与发送入口的可见性断言保持不变。

修改后 JVM 增至 **42 项**，设备常规套件增至 **27 项**，不含 3 项 opt-in 付费云服务测试。真实 JNI 测试覆盖预热不录音、同权重更换流后中英识别与静音隔离；UI 覆盖 14 项测试，包括连接面板、配对码、草稿、自动发送取消、键盘、大字号、明暗与双语。

通信验收使用隔离的 Room/凭据与 `adb reverse -> loopback`：真实 CPace、固定证书 TLS、Outbox、收据推送、held 到期、前台自动重试、原身份更新地址、进程重建及不确定状态跨重连。桌面 fake adapter 预期恰好两次执行（一次 injected、一次 uncertain），不允许重连导致第三次执行。此测试不代表手机经真实 Wi-Fi 到任意目标程序落字或延迟验收。

## 用户真机验收

1. 电脑运行 SayIn，手机打开已配对的 App。应自行重连；右上角点击只展开状态，不断开。电脑保持后台，在记事本点击输入区。
2. 手机选择本地，等待“加载 → 预热 → 就绪”，确认没有自动录音。点按说话、明确结束，修改草稿后发送；记事本应输入一次，不追加回车，双端历史保留对应结果。
3. 使用原有豆包配置重复云端识别；本轮自动化未调用付费云 API，也未替换凭据。
4. 在电脑暂停接收；手机应显示暂停，点发送解释原因并保留草稿。恢复电脑接收后草稿仍需明确发送。
5. 临时断开网络或退出再启动电脑 SayIn；手机保持前台应重连，不重发历史。若电脑端出现待核对，必须先在目标软件核对并在电脑确认，手机不能解除。
6. 电脑地址改变时，先验证 40 的自动发现；发现不可用时从电脑连接帮助取当前地址，在手机“连接帮助 → 电脑地址变了？”更新。无需重新批准，旧历史保留；错误地址不得成功连接另一主机。
7. 手机打开输入法，检查草稿与发送均可见；切换横竖屏、English、深色与大字号，检查关键操作可达，文字不因切换发送。

首次扫码/配对码验收使用测试设备或明确撤销后的配对，不要为测界面随意删除日常身份。
