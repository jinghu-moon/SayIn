# Android 设备显示名称：商品名称优先

日期：2026-11-13  
状态：**设备名称逻辑、双端认证刷新及历史名称快照已实施**，2026-11-13 在当前手机的普通应用 UID 下实际读到 `Redmi K40`。实施范围、测试与边界见 [26 历史去向与设备商品名称](26-history-route-and-device-display-name.md)。本文其余章节保留需求分析及实施前基线，不代表仍待编码。

## 需求与实测基线

电脑接收页、配对批准及设备列表中，这台手机应显示 **Redmi K40**，而不是型号编号 `M2012K11AC` 或设备代号 `alioth`。名称来自手机实际信息，不在 UI 中硬编码该机型。

本次通过已连接手机的 ADB 只读查询得到：

| 属性 | 实际值 | 含义 |
| --- | --- | --- |
| `ro.product.marketname` | `Redmi K40` | 商品名称，目标显示值 |
| `ro.product.vendor.marketname` | `Redmi K40` | 厂商分区的商品名称 |
| `ro.product.odm.marketname` | `Redmi K40` | ODM 分区的商品名称 |
| `ro.product.model` | `M2012K11AC` | 产品型号，当前 `Build.MODEL` 来源 |
| `ro.product.device` | `alioth` | 设备代号，不作为商品名称 |

另执行以下命令，两次均返回 `Redmi K40`：

```powershell
adb -s dc39c31d shell run-as seeyuer.sayin /system/bin/getprop ro.product.marketname
adb -s dc39c31d shell run-as seeyuer.sayin /system/bin/getprop ro.product.vendor.marketname
```

这证明当前 ROM 下以该应用 UID 执行的属性查询可读；**不等同于已完成应用内属性读取实现、Release 验证或跨厂商适配**。未使用 root，未改变设置、配对或手机数据。

## 根因与影响范围

`android/app/src/main/java/seeyuer/sayin/data/VoiceLinkRepository.kt` 的 `Event.Open` 在首次配对时直接取 `Build.MODEL`，移除控制字符并截断后写入 `pair.name`。该字段本身不是商品名称 API，所以这台设备上报 `M2012K11AC`。

桌面端在批准配对时将名称保存到设备账本，历史再记录来源名称。普通重连的 `hello` 当前只有 `device_id` 和 `token`，没有名称刷新字段。因此仅替换首次配对表达式，不能修正用户已经配对的手机名称。

后续必须同时处理：手机名称解析、首次配对上报、已认证重连刷新、桌面设备名称持久化及新记录来源展示。历史记录中的来源名称保持当时快照，不因设备名称刷新而回写全部历史。

## 目标逻辑

1. 在手机端集中实现设备显示名称解析，由配对和已认证连接流程复用，UI 不自行猜测型号。
2. 按顺序选择可读且清理后非空的 `ro.product.marketname`、`ro.product.vendor.marketname`、`ro.product.odm.marketname`。
3. 商品名称不可读、属性不存在或值无效时回退到清理后的 `Build.MODEL`；仍为空时用稳定通用名称 `Android`。`Build.DEVICE`、`Build.PRODUCT` 和分区镜像名称不能拿来冒充商品名称。
4. 统一去除控制字符、清理首尾空白，并按 Unicode 码点限制为最多 64 个字符，与桌面 `chars().count()` 的限制一致；不能截断 UTF-16 代理对。
5. 不修改商品名大小写，不追加重复的品牌前缀，不随应用语言切换翻译或重算设备身份，不维护臆测的型号编号映射表。
6. 属性读取在普通应用权限下完成，不依赖 root、ADB 或隐藏 Java API 反射。具体入口在实现时验证，可评估现有 JNI 中的系统属性读取；本次 `getprop` 命令仅作取证，不能直接认定为产品实现。读取失败只影响名称回退，不能阻止连接和发送，也不能在 UI 线程阻塞等待外部命令。

## 已配对设备刷新

后续在协议权威文档中定义经过设备令牌认证后的名称更新语义，再同步修改双端。可在认证握手携带解析后的显示名称；服务端完成身份验证后，使用协调线程更新相同 `device_id` 的名称并发布快照，不在认证前写入设备元数据。

名称只是显示元数据，不能参与身份验证、设备去重或 HMAC 身份计算。更新应保留既有 device/host 身份、令牌、配对批准、Outbox 范围、历史记录和接收闸门；不能要求用户删除数据、撤销再配对，也不能以改名触发发送、重试或自动恢复暂停。当前开发阶段直接统一协议与调用链，不引入双版本兼容层。
