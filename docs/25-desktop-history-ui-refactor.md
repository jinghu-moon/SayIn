# 25 · 桌面历史记录界面重构

日期：2026-11-13。

2026-11-16 补充：手机记录卡片及执行目标回执联动见 [67](67-android-history-card-refactor.md)。电脑在执行准备时额外持久化显示名称/图标快照，只向原认证设备披露最小展示字段；不将当前前台应用作为历史目标，不改变原生输入门禁。

## 目标与范围

参考 [历史卡片 HTML demo](demos/sayin-history-card.html)，重构实际 GPUI 桌面端的历史记录页。目标应用使用 `win-icon-extractor` 提取图标；卡片随内容区域宽度排列为一至三列。此次没有修改参考 demo，也没有改变手机到当前光标的输入方式。

历史是发送记录的查看与整理入口。查看、搜索、复制、切换语言、删除记录均不会重发文字或重新执行输入；不为失败或不确定记录增加隐式重试。

## 界面与交互

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 列表结构 | 单列记录与分散操作 | 按日期分组的响应式卡片 |
| 定位记录 | 原有搜索与状态下拉 | 搜索框、正文关键词高亮、常用状态筛选与更多状态菜单 |
| 目标应用 | 文字描述 | 实际应用图标与进程名，详情展示历史执行目标 |
| 卡片层级 | 信息与按钮集中平铺 | 时间/状态、正文、异常提示、来源/目标、复制分层展示 |
| 更多操作 | 持续显示辅助信息 | 右上角 Tabler `DotsVertical` 菜单提供详情与删除 |
| 记录管理 | 无单条删除及保留策略 | 删除、8 秒撤销、保存开关与保留期限 |

- 常用筛选为全部、已提交、未输入、待核对、已过期；已接收、执行中、已阻止、已取消放在“更多状态”。筛选展示真实收据状态，不将提交成功描述为目标软件已保存文字。
- 日期分组为今天、昨天、具体日期；缺少时间的历史记录有独立分组。时间按本机时区显示。
- 正文保留原文，长内容默认收起为三行，可展开；搜索支持 Unicode 高亮。可搜索正文、设备、目标路径和窗口标题。
- 卡片底部显示手机来源、执行时记录的目标与复制原文操作。没有目标信息时不推断软件归属，不读取当前前台程序来填充旧记录。
- 页面区分加载、读取失败、没有历史、搜索无结果及筛选无结果。沿用每页最多 30 条和分页，搜索分批读取加密历史并让出协调线程。
- `Ctrl+K` 聚焦搜索；菜单和隐私弹窗使用 Yue 组件自身的键盘与焦点处理。删除后撤销按钮可获得焦点，撤销结束后按需返回搜索。
- 界面完整支持简体中文、English、明暗主题。应用主题色继续为 `#1f75db`，表面和文字使用 neutral；状态使用 demo 对应的 Yue success/error/warning 语义 token。

## 响应式布局

历史页拥有独立纵向滚动区域，标题与操作允许换行，卡片内容允许收缩与换行。

列数按当前窗口宽度除以实际 `rem_size`，减去侧边栏及页面左右内边距后计算，避免把物理截图像素直接当成布局断点。可用内容宽度为 `W` 时：

```text
columns = clamp(floor((W + 0.75rem) / 24.75rem), 1, 3)
```

卡片间距为 `0.75rem`；可用宽度小于 `48.75rem` 为一列，达到 `48.75rem` 为两列，达到 `73.5rem` 为三列。宽窗口限制最多三列以维持阅读宽度；更窄的单列允许卡片继续缩小。断点同时考虑现有侧边栏宽度与应用字号。

## 应用图标

Windows 目标依赖固定为：

```toml
win-icon-extractor = { version = "=0.3.0", default-features = false, features = ["png", "resize"] }
```

`application_icon.rs` 通过 `extract_icon_best(path, 32)` 提取图标并编码为 PNG，再以 GPUI `Image` 显示，保留原图颜色。文件访问和提取放在后台 executor；`HistoryView` 持有任务与当前页缓存，相同路径且修改时间未变时复用图像，合并刷新期间的重复请求。

输入为收据执行时保存的 exe 路径，不执行目标文件、不解析快捷方式或 URL。相对路径、UNC/网络路径、文件缺失或提取失败时显示 neutral 通用应用图标。此方案反映历史 exe 对应的图标：应用卸载后可能无法获取，通用宿主进程也可能显示宿主图标，不宣称已覆盖所有打包应用的独立身份。

官方资料：[crates.io 0.3.0](https://crates.io/crates/win-icon-extractor/0.3.0)、[API 文档](https://docs.rs/win-icon-extractor/0.3.0/win_icon_extractor/)、[源码](https://github.com/jinghu-moon/win-icon-extractor)。

## 数据与线程边界

- 历史页从 `shell.rs` 拆为持久 `HistoryView` entity，拥有搜索、展开状态、弹窗、焦点和图标任务；接收状态与账本仍由原模块拥有。
- 账本 schema 为 **4**，增加历史删除时间、相关索引和单例保留策略。已有配对、收据和去重身份继续使用，未另建生产账本。
- 删除先隐藏记录并提供 8 秒撤销。撤销期结束后，由账本协调线程删除展示历史副本。删除不撤回已经输入的文字，不取消待执行操作，也不删除协议收据或去重指纹。
- 默认启用保存，保留期限为永久；可明确选择 7 天或 30 天。缩短期限会清理超过期限的历史，不能当作仅影响新记录的设置。
- 关闭保存后不再为新请求建立历史正文副本；现有历史仍按所选期限处理，输入队列与协议回执继续正常工作。
- 清理由账本 owner 定期主动处理，不依赖窗口是否打开。每轮对删除到期、保留到期分别限制最多 256 条，避免一次处理无限记录。
- 原文与目标 metadata 继续用当前 Windows 用户的 DPAPI 保护。删除展示历史不等于对数据库、备份或仍待执行载荷进行安全擦除。
- UI 不做 SQLite 或 Win32 输入工作。异步查询按 generation 丢弃过时结果，防止删除或策略命令完成后旧读取覆盖最新状态。
