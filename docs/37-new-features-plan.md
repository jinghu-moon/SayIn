# 37 · SayIn 新功能规划

日期：2026-11-14。状态：需求整理与实施规划，非实施完成记录。

## 1. 范围与决策依据

本文件记录本轮对话中的快捷入口、草稿语音编辑、多段落输入、自动找到已配对电脑四个方向。电脑选文后交给手机改写已被用户明确排除。其他曾被助手提出、但用户未继续确认的功能不自动纳入开发承诺。

用户已确认：快捷入口已有三种形态的规划；自动找到已配对电脑可以做。草稿语音编辑与多段落仍处于可行性讨论，本文提出目标设计，不能把助手推荐的模型、实现顺序或性能目标当作用户已经确定的技术选型。

共同目标是减少唤出、纠错、排版和地址维护的操作负担。首次配对、本地核对不确定输入、必要系统授权继续保留；正常使用不增加逐条电脑确认、网卡必选项或重复配对。

## 3. 快捷入口与统一会话

### 3.1 交互依据

用户指定的本地参考是 [sayin-quick-entry.html](../refer/sayin-quick-entry.html)，完整页参考为 [sayin-mobile-ui.html](../refer/sayin-mobile-ui.html)。最新统一规则见文档 36；`refer/` 是被 Git 忽略的本机参考，其他检出环境不保证拥有这些文件。

| 入口 | 主要用途 | 目标行为 |
| --- | --- | --- |
| 悬浮球 | 在其他应用中快速唤出 | 展开快捷卡；已有会话回到当前会话；拖动、贴边与收起不创建第二次录音 |
| 控制中心磁贴 | 通过系统快捷面板唤出 | 打开或恢复同一会话；系统控制磁贴外观，不把 demo 的双宽样式当作原生保证 |
| 通知中心通知 | 找回当前状态与结束正在进行的录音 | 正文恢复会话，录音中提供结束说话；通知不是第二套编辑与发送界面 |

### 3.2 目标实现与边界

- 完整页、快捷卡、磁贴和通知共用一个 `SpeakSession`，音频采集及最终稿只有一个所有者；Activity 的创建、销毁或展示切换不隐式新建会话。
- 入口权限按实际能力申请：麦克风、通知、悬浮窗和前台服务分别处理。拒绝悬浮窗不能阻止用户从主界面使用；空闲入口不打开麦克风。
- 用户主动启动录音后，录音前台服务负责系统要求的持续可见状态。退后台是否允许继续采集，要按系统版本和服务启动条件验证，不能以绘制悬浮球绕过权限。
- 默认手动发送。可选“说完自动发送”只在用户明确结束、成功定稿、当前说话界面可见且接收范围有效时进入三秒倒计时；按文档 36 不再按中文、英文或长短句分别猜测意图。
- 收起、切入口、编辑、清空、打开连接/更多、离开页面及连接范围变化取消本轮倒计时。通知在不可见界面结束录音不授权后台发送；恢复可见也不补建旧票据。
- 进程重建恢复草稿和待查询请求，不恢复麦克风或自动发送授权。草稿只有其版本成功持久入 Outbox 后才能清空。

### 3.3 验收

覆盖三入口与完整页互相切换、已有录音恢复、后台结束、权限拒绝/撤销、锁屏、横竖屏、进程终止、重复点击、断线及待核对。检查同时只存在一个音频采集源、一个当前请求，没有双重定稿或重复发送。简体中文、English、大字号与明暗主题均检查可达性。

## 4. 草稿语音编辑

### 4.1 能力拆分

ASR 负责把声音变成文字；自然语言修改由识别后的文本处理完成，不修改 ASR 权重或重放原始音频。三种输入来源都能产生被编辑的原草稿，修改要求可由用户选用的语音来源转写；手机输入法只提交最终文字，不接管其内部麦克风。

| 类型 | 示例 | 建议实现 |
| --- | --- | --- |
| 确定性操作 | 撤销本次修改、在当前选区插入内容 | 直接使用编辑状态，不调用语言模型 |
| 精确指令 | 把“三点”替换为“四点” | 可规则解析；多处同词需明确范围，不能默认全替换 |
| 自然语言改写 | 第二句客气一点、删掉重复内容、保留数字并缩短 | 通用 LLM 根据原稿及明确指令产生候选稿 |

云端千问 Plus、豆包文本模型等只是对话中的候选。具体型号、价格、上下文、非思考模式和结构化输出能力应在接入时重新核实；现有豆包 ASR 凭据和接口不能直接视为已开通通用文本编辑。没有确定的本地编辑模型，不能把专用任务模型当作任意改写引擎。

### 4.2 用户流程

1. 有草稿时从辅助操作进入“语音修改”；无需新增主导航页面。
2. 冻结原稿、选区及修订版本。这次录音明确表示修改要求，识别文字进入指令区，不直接插入原草稿。
3. 用户明确结束并取得指令 final 后，提交原稿、目标范围和指令，显示处理状态并允许取消。
4. 返回候选稿，显示修改前后内容，提供采用、放弃与采用后的撤销。短而确定的操作不要求额外重复确认。
5. 采用结果是一次草稿编辑，取消旧发送倒计时。用户再明确发送；模型输出及 partial 不直接调用 LAN 发送。

当指代不清、目标词多次出现且指令未给范围，或“删掉它”缺少可识别对象时，保留原稿，给出直接的补充指令入口。不能伪装模型已经可靠理解了意图。

### 4.3 数据与生命周期

任务最少绑定任务 ID、草稿 ID、修订版本、原文/选区快照及指令。用户继续编辑、开始新录音、清空、取消或恢复另一份草稿后，旧响应不得覆盖新状态。沿用现有修订状态表达事实，不额外维护彼此矛盾的版本号。

只有完整、合法、未过期的候选能被采用；网络中断、超时、截断、空结果及解析失败保留原稿。输入文字即使包含“忽略规则”等语句，也只是任务数据；指令隔离和恶意样例必须测试，提示词本身不是安全保证。

云端方式在首次启用时说明会上传本次原稿及指令文字，凭据采用独立 Keystore 加密配置，不写日志或传至电脑；关闭云端后不静默回退。尚未采用的候选与撤销副本按草稿保护级别保存，不回写已提交的 Outbox 或历史原文。

### 4.4 验收样例

| 原稿与指令 | 预期 |
| --- | --- |
| “明天三点开会，小王准备资料”；“改成四点，其他不变” | 只改变时间，保留日期、人名和后半句 |
| 多处“三点”；“把三点改成四点” | 不猜测修改范围 |
| “不需要提交”；“改得简洁一些” | 不丢失否定含义 |
| 任务执行中用户又改了草稿 | 旧结果不得覆盖，也不得启动发送 |
| 原稿或指令包含提示注入、引号、代码、Emoji | 正确保留文本边界，无工具调用或系统操作 |

质量评审同时记录误改、漏改、无关扩写；不能仅凭输出流畅就认为编辑正确。

## 5. 多段落输入

### 5.1 先解决文本语义

当前手机 `normalizedText` 与电脑 `normalize_text` 把换行和制表符替换为空格。这是发送语义约束，不能只调整编辑框或换一个识别模型解决。

建议统一把 CRLF/CR 规范为 LF，并允许正文包含 LF；其他控制字符仍明确拒绝，Tab 是否支持另行定义，不自动转成按键指令。手机预览、Outbox、指纹、桌面账本、历史及实际输入必须使用同一份规范文本。4000 码点与 16384 字节的现有正文上限在有证据前不扩大。

### 5.2 三种输入来源

| 来源 | 基础行为 | 可选自动处理 |
| --- | --- | --- |
| 云语音 | 保留标点；若接入分句及时间信息，单独解析，不把分句当成段落 | 最终稿之后按语义建议分段 |
| 本地 X-ASR | endpoint 提交片段，继续录音；现有片段拼接不自动插入段落 | 提供手动段落边界，或定稿后建议分段 |
| 手机输入法 | 保留实际提交的换行与用户手工排版 | 与其他来源共用最终稿处理，不依赖输入法内部能力 |

基础版先支持用户手工换段、继续输入以及保留已有换行，无需 LLM。自然语言“下一段”只在明确的排版指令状态下解释；普通听写中的同名短语保留为正文。

可选语义分段采用最终文本处理。如果动作只叫“分段”，只允许调整换行位置，不顺带润色或更改词句；实施时可比较去除规范换行后的原文与结果，拒绝未经授权的词句变化。停顿时长仅能提供辅助信号，不能作为必然换段规则。

### 5.3 电脑端换行

不能把每个正文 LF 无条件转换为 `VK_RETURN`：聊天软件可能将 Enter 当作发送。应评估将完整多行文本通过 `CF_UNICODETEXT` 一次粘贴，并在独立执行策略中明确剪贴板副作用、焦点核对、权限、失败回执与最多一次尝试。

剪贴板不是已存在的产品输入通道。需要为多行内容建立真实目标应用兼容矩阵；若目标不支持多行粘贴，保留正文并提示直接恢复方式，不能静默压成一行，也不能自动发送多条消息。原有单行输入仍需回归。

## 6. 自动找到已配对电脑

实施状态（2026-11-14）：已完成首版 IPv4 有界发现与原身份认证后路由提交，见 [40 实施与验证](40-paired-host-discovery-and-reconnect.md)。下文保留设计要求，实际验收范围及旧系统 API 限制以实施记录为准。

### 6.1 目标流程

1. 前台优先使用记住的已认证端点；连接失败或收到网络变化时启动有界的局域网发现。
2. Windows 在当前有效、精确绑定的监听接口发布 DNS-SD/mDNS 服务；沿用协议已有的 `_voicelink._tcp` 规划，不因品牌改名另建第二套服务。
3. Android NSD 解析少量候选 IPv4/端口；发现记录中的 host ID、名称和版本都只是可伪造线索。
4. 按已保存的 `tls_name`、完整固定证书和 host/device 凭据进行 TLS 与令牌认证。认证成功后才更新同一主机的路由信息。
5. 查询旧收据并恢复当前会话，保持草稿。主动暂停、存储阻断及 `uncertain` 不被发现或重连解除。

只针对当前已保存的配对身份恢复连接，不引入新的多电脑选择流程。错误证书、未知主机、发现记录冒充、认证失败都不得更新持久端点；不在验证证书前发送设备令牌。

### 6.2 资源、网络与授权

- 复用现有前台重连退避，发现不能另起无限重试循环；同一时刻只保留一个有界恢复任务。停止、取消、退后台或切网时回收 NSD 监听及候选连接。
- 首版保持 IPv4，与现有协议范围一致；双栈发现过滤无支持的地址，不顺带宣称实现 IPv6。
- 服务发布必须遵守当前网卡 GUID、IPv4、Windows 网络 GUID/类别集合的绑定。旧网络停止监听时撤销发布，恢复只发布新范围，不监听全部网卡或自动修改防火墙。
- Android 工程当前 `targetSdk=37`。实现前按运行系统及官方规则核对 `ACCESS_LOCAL_NETWORK` 与 NSD 权限；已有 Manifest 声明不代表运行时已获授权。必要授权只申请一次并解释用途，不借自动发现绕过系统许可。
- 多播受阻、访客隔离、跨网段或发现失败时保留手动更新地址作为恢复入口，不能要求删除身份重新配对，不能回退明文或任意证书。

### 6.3 验收

覆盖同主机换 IP/端口、错误证书、同名实例、伪造 host ID、多网卡、局域网权限拒绝/撤销、多播被阻断、发现风暴、切网、后台取消和设备撤销。检查身份/Outbox 不变、端点只在认证成功后提交、旧请求只查询、`uncertain` 不重放。真实局域网测试与回环测试分别记录。

## 7. 建议实施顺序与回归门禁

顺序是建议，不是用户已承诺的排期：先完成快捷入口统一与真机验收，再做已配对发现；多段落先修正文本协议与真实输入，再增加可选语义排版；自然语言编辑在候选模型质量评估后接入。每个方向独立交付，不为了共享抽象先建设通用插件平台。

| 行为 | 当前基线 | 实施后应验证 |
| --- | --- | --- |
| 唤出 | 已有 demo 与部分工作区代码 | 三入口复用会话，权限与生命周期正确 |
| 草稿修改 | 手工编辑、选区录入 | 自然语言修改可检查、可撤销、不会覆盖新稿 |
| 换行 | 双端变为空格 | 保存、传输和目标应用中的正文一致 |
| 地址变化 | 已实现有界发现与手动保底，见 40 | 自动找回同一身份，无法发现时仍可手动恢复 |
| 旧请求 | 查询、去重、不确定结果人工核对 | 所有新增入口及网络恢复均不破坏该约束 |

实现前运行当前测试建立基线；实现后运行相关 JVM、协议、持久化、仪器化和真实目标应用测试。常用门禁如下，均为后续实施要求，不是本文编写时执行的测试：

设备测试使用隔离数据与已明确的设备授权；不重置日常配对、账本或 Outbox。报告命令、设备、实际结果、失败及未覆盖范围；模型/网络/界面速度需实际采样，不能用构建或 demo 通过代替产品验收。
