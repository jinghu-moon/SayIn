# Android 文本分享、历史导出、语音指令、悬浮球与本地模型管理

日期：2026-11-18。范围：手机端为主；桌面端协议与历史实现未改动。

本轮实现用户选定的五项功能：

1. 其他应用分享文本到 SayIn 草稿；
2. 历史记录按目标应用、状态、日期筛选，导出与批量/按时间清理；
3. 可开关的语音编辑指令；
4. 悬浮球尺寸、透明度、双击动作和长按菜单；
5. 本地翻译模型管理与离线 ASR 模型信息。

## 1. 文本分享入口

- `MainActivity` 增加 `ACTION_SEND` + `text/*` 入口。文本从 `EXTRA_TEXT` 读取；缺失时回退到第一个 `ClipData` 项的 `coerceToText`，首尾空白会被裁剪。图片分享路径保持原行为。
- 分享文本进入说话页：
  - 草稿为空且没有冻结请求/恢复/录音：直接替换草稿并提示；
  - 已有草稿：底部面板提供“替换草稿 / 追加到草稿 / 取消”，不静默覆盖；
  - 请求冻结、正在录音或正在恢复草稿：只提示稍后重试，不写草稿。
- 分享文本属于显式文本导入，不设置自动发送票据，不触发发送、翻译或重连。`handledShare` 使用 `rememberSaveable`，旋转后不会重复载入同一 Intent。

## 2. 历史记录

`MobileHistoryPage` 在原有全文搜索和状态筛选上增加：

> 筛选区后续已按 [71 记录页筛选区重设计](71-android-history-filter-redesign.md) 使用 Miuix 组件重构；本节的数据与导出语义不变。

- 目标应用筛选：按接收时保存的应用名称快照；未记录应用只出现在“全部应用”。
- 日期筛选：不限日期、今天、7 天、30 天。
- 批量管理：选择/取消选择、全选、确认后批量隐藏；只改 `historyHidden`，不取消请求、不删除回执、不改变 pending 查询。
- 按时间清理：7/30/90 天以前或全部显示记录；同样只影响历史展示。
- 导出当前筛选结果（最多本机保留的 100 条）：
  - Markdown；
  - JSON（`format=sayin-history`, `version=1`）；
  - 口令加密备份：PBKDF2-HMAC-SHA256（120,000 次）+ AES-256-GCM，文件头为 `SAYINBK1`，仅导出不导入。
- 导出只包含文字和元数据，图片以尺寸/字节数记录，不把图片二进制嵌入 Markdown/JSON/加密文件；图片原件仍可从记录中复制。该限制在导出面板内明确说明。

仓库层只增加 `hideAll(ids)`、`hideBefore(before)` 两个展示操作；它们不触碰 `payload`、`state`、请求 UUID 或 Image 资源引用。设备测试验证批量隐藏/按时间清理后 pending 行仍完整。

## 3. 语音编辑指令

> 2026-11-21 已完整移除：用户要求删除该功能，见 [83 移除语音编辑指令](83-remove-spoken-editing-commands.md)。以下为当时的实现记录，不再代表当前行为。

- 默认关闭，设置 → 语音识别页新增“语音编辑指令”开关（持久化 `voice_commands`）。
- 只在**明确结束录音且收到 final** 时处理；partial、取消、错误、尾包超时都不执行指令。
- 命令必须是一个完整的、由标点/换行分隔的片段，避免把句子中的词当命令：
  - 换行：`换行`、`换一行`、`另起一行`、`newline`、`new line`；
  - 删除上一句：`删除上一句`、`删除上一条`、`删掉上一句`、`delete previous sentence`、`delete last sentence`；
  - 清空：`清空`、`全部清空`、`clear`、`clear all`；
  - 翻译：`翻译`、`translate`；
  - 发送：`发送`、`发送出去`、`send`。
- “清空”丢弃当前草稿（包括选区外内容）；“删除上一句”删除插入点之前最后一个句子边界之后的内容；“换行”写入 `\n`；命令文本本身不进入草稿。
- “翻译”在 final 后调用现有本地翻译；“发送”复用现有 `onSendReady` → `markSubmitted` → Outbox 链路，要求页面可见、连接就绪；未就绪时退回手动检查，不绕过请求身份或自动发送授权。
- 同时出现“翻译”和“发送”时只执行翻译，发送仍由用户确认译文后触发。
- 命令处理器是纯 Kotlin `VoiceCommands`，JVM 测试覆盖选区、无命令原样保留、行内同名词不生效、清除、删除和英文命令。

## 4. 悬浮球

- 悬浮球页合并为三张卡：行为（开关、双击动作、指定应用隐藏）、预览、外观（颜色、尺寸/露出/图标/可见度、保持图标完整）。
- 设置入口统一为“快捷入口 → 悬浮球”，根页不再单独放开关；页内顶部为开启开关，下面是预览、颜色和尺寸。
- 悬浮球页设置项：
  - 尺寸 44–72 dp；
  - 贴边露出 30%–70%，但至少保留 24dp 可见宽度；滑杆显示百分比与实际可见 dp；
  - 图标大小 40%–70%，展开与贴边共用同一比例；
  - 贴边时保持图标完整：开启后图标缩放到可见条内，最小 16dp；关闭则保持当前“移到可见区中心、可能裁切”的效果；
  - 贴边可见度 35%–100%（100% 最清楚，不是全透明）；
  - 背景颜色与图标颜色：预设米白 / 深灰 / 品牌蓝，图标另可选白色；末位“+”打开 Miuix `ColorPicker`，可自定义任意颜色（HSV 与透明度）；
  - 双击动作：打开快捷卡 / 在快捷卡直接录音。
- 设置页顶部提供实时预览：中间为展开态，右侧为贴边态（按当前可见度、并被预览边界裁切），颜色、尺寸和可见度随控件即时变化。实际悬浮球通过 `presentation` 偏好监听立即重绘，预览不创建第二个悬浮窗。
- 左右贴边使用同一可见宽度（`peekWidth`），左侧窗口偏移为 `peekWidth - width`；拖拽时图标临时回到中心，松手吸附后回到贴边位置。
- “重置位置”入口在预览标题右侧，点击后将悬浮球吸附回右侧边缘并垂直居中；服务启动时的默认位置同样为右侧垂直居中。
- “在指定应用中隐藏”的应用列表支持按名称、最近使用、安装时间、已选择优先排序，选择存 `presentation.quick_ball_hidden_apps_sort`。
- “在指定应用中隐藏”需要用户在系统设置中授予“使用情况访问”；选择的应用在前台时，服务将悬浮窗设为不可见且不可触摸，离开后恢复。读取仅用于判断当前前台应用，不保存使用历史；偏好存 `quick_ball_hidden_apps`。应用选择表通过 Manifest `<queries>` 的 MAIN/LAUNCHER intent 获取全部可启动应用，排除 SayIn 自身。
- 贴边、图标与完整模式存 `quick_ball_peek`、`quick_ball_icon`、`quick_ball_keep_icon`；`BallGeometry` 统一计算有效露出比例、可见宽度和图标尺寸，JVM 测试覆盖 44/56/72dp 与边界组合。
- 颜色存 `quick_ball_bg` / `quick_ball_fg`（ARGB），默认 `#F3F3F1` / `#252525`；`BallView` 用背景色绘制圆形、用 tint 绘制言字标，展开态使用完整背景色，贴边态由窗口 alpha 控制透明度。
- 服务读取偏好并监听变化，尺寸、可见度和窗口参数即时更新；设置页通过 `QuickEntryService` 的公开 setter 写入，服务未运行时不会自行启动。
- 手势调整：
  - 单击：收起时展开；展开后单击打开快捷卡；
  - 双击：执行所选动作；直接录音会把一次性 `auto_record` extra 传给 `QuickActivity`，由说话页在可见、无冻结请求时开麦；
  - 拖动：越过 touch slop 后立即移动并吸附边缘，不再依赖长按；
  - 长按：弹出菜单，提供打开快捷卡、暂停/恢复电脑接收、关闭悬浮球。
- 暂停/恢复使用协议中已有的 `control` pause/resume（活动设备 + `expected_rev`）；不解除 held、不复用旧请求、不切换目标。协议规定手机不能指定 Windows 窗口句柄，因此没有“切换目标”菜单项。
- 未启用“全屏视频/游戏自动隐藏”：不申请无障碍或使用情况访问权限时，Android 不向悬浮窗提供可靠的前台/全屏信号。设置页与本文都明确标注，未用猜测或轮询伪装该能力。

## 5. 本地模型管理

- 模型列表右侧只保留进入详情的箭头；元信息行先显示状态图标和“使用中／已导入／未导入”，再显示精度与大小；使用中图标为蓝色，已导入为灰色对勾，未导入为虚线图标和下载符号。未导入行内容置灰，但箭头保持可点击。
- 翻译页改为模型管理：
  - 从 `translation-artifacts.json` 列出三个固定模型；
  - 显示当前模型文件名、大小、revision 前 12 位、状态；
  - 下载/重新下载并校验固定 SHA-256；
  - 删除当前模型文件（需确认），保留草稿、历史、配对身份和已完成的译文；
  - 切换模型只影响之后的翻译；已完成的译文仍可查看和发送；录音、翻译、准备或删除期间禁止切换。
- 模型版本仍是构建固定的 artifact；没有远端“检查更新”接口。“重新下载并校验”是当前受支持的更新/修复路径。
- 离线模型页展示内置 X-ASR 480ms 规格、四个文件、占用、版本与运行状态。当前只打包并验证这一种 ASR 规格，因此没有提供虚假的可选规格；页面明确说明尚未接入其他可下载规格。480ms 是分块规格，不是首字或端到端延迟。
- 存储页新增翻译模型与离线 ASR 模型占用；仍只清理缓存，不删除模型、草稿、历史或配对数据。

## 6. 已知边界

- 历史导出不包含图片二进制，也不提供导入；加密备份只保证导出文件的机密性，口令丢失不可恢复。
- 桌面历史页本轮未增加导出；桌面端已有搜索、状态筛选、保留策略和删除撤销。
- 悬浮球全屏自动隐藏未实现，原因见上；长按菜单不提供目标应用切换。
- 语音指令是简单、精确的片段匹配，不做语义理解；不同 ASR 服务的标点/分词差异可能影响可识别形式。
- 本地 ASR 仅有内置规格；其他规格需要新的固定 artifact、摘要、加载配置与验证，不能只加一个下拉选项。
