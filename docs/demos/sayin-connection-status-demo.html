统一后的连接状态按钮

  • 结构：状态图标 + 2–4 字；36dp 高、18dp 圆角，热区 48dp。连接页只读（role=status、无箭头），说话页点按打开面板（箭头朝下）。
  • 图标：统一用单层 Tabler 图标：device-desktop-check / pause / exclamation / x / minus / plus、arrows-left-right、loader-2、radar、refresh、dots、hourglass；不再用“电脑底座 + 右下角角标”叠加，避免 18dp 下两层线条互相干扰。
  • 层级与颜色：就绪最安静；进行中蓝；可恢复的问题（含需要授权）琥珀；红色只给不会自愈、需用户处理的数据或安全问题；灰色是离线 / 初始化 / 首次入口。
  • 动效：只表达“正在进行”：初始化 / 连接 / 配对共用轻量旋转，查找用雷达涟漪，核对状态用双向箭头，待批准是静态沙漏。
  • 恢复顺序：先连保存的地址；失败才查找电脑，再连候选地址。只有存在旧请求才出现“核对状态”。末尾按电脑实际状态展示（已连接 / 已暂停 / 未选中 / 待核对），不固定落到已连接。左侧勾选“已保存地址失效”“有旧请求”对比。
  • 已暂停：仅 pause_reason=paused 时才说电脑已暂停、请在电脑恢复。启动准备、网络恢复、接收范围变化等自动处理阶段，顶栏跟随真实恢复任务，不引导用户去电脑点击；outcome_review_required 一律归入待核对。
  • 核对与受阻并存：已确认的具体阻断（存储异常、待核对、已暂停、未选中）作主状态，面板补一句“正在核对此前发送结果”；没有明确阻断但查询未完成，显示“核对状态”；不因顶栏显示已暂停就提前结束旧请求查询；全部满足才显示绿色已连接。不新增组合状态。
  • 连接恢复 ≠ 旧请求已处理：断线只表示结果待确认，查询后才能确定是否暂存。held 表示暂存、未执行，接收条件满足后顶栏可为已连接；uncertain 表示结果不确定，电脑核对闸门未解除时顶栏必须为待核对。两条演示分别展示，不混成一种状态；记录卡片只提供“查看记录”。文字暂存可在手机详情明确释放或取消，图片暂存不支持释放，不确定结果需在电脑核对。
  • 暂不可用：只是兜底，面板必须按真实原因给下一步。草稿顶部应用图标缺失只是实时提示，不是接收授权，不触发它。
  • 初始化 / 无局域网 / 重连：初始化只对应真实加载，结束即离开；无局域网时顶栏仍为“未连接”，面板写“网络恢复后自动连接”，不播查找动画（没有互联网不等于局域网不可用）；顶栏跟随真实连接任务的结束与退避，不设 UI 倒计时，也不要求手动重试。
  • 不放顶栏：配对码过期、配对被拒、未发现电脑、地址连接失败（配对表单 / 连接面板）；发送中、图片上传中（发送区域）。
  • 大字号与无障碍：放大后先隐藏箭头再放宽最大宽度；状态变化走 polite live region，颜色与角标只是冗余提示。

受阻状态：双端各自做什么

手机显示电脑实际情况手机面板告诉用户

手机负责展示和引导；恢复接收、选择设备和核对结果在电脑上完成。手机不为这些状态提供通用“修复 / 恢复”按钮。

仍缺双端数据支撑（列表里标了“需双端数据”）

  • 电脑存储异常：现有 welcome/state 没带 storage_healthy，不能由普通断线推断。
  • 授权失效：手机目前分不清撤销授权与普通连接失败，需要可靠的认证错误处理。
  • 无法验证：仅在实际发生证书或身份校验失败时说明“发现的地址未通过身份验证”；没有候选、超时或拒绝连接仍为未连接，不能因所有候选连接失败就推断身份异常。单个候选不符时继续其他候选，不据此断言原电脑身份已变化，不引导换证书或自动重新配对。

优先级（按有效事实判断）

尚未认证在线：已确认存储异常（手机端）> 初始化 > 需要授权 > 授权失效 / 无法验证 > 配对中 / 待批准 > 查找电脑 / 连接中 > 未连接 / 连接电脑。加载中一旦确认存储或密钥异常，立即结束初始化并显示异常。

认证在线且状态有效：存储异常（电脑端）> 待核对 > 已暂停 > 未选中 > 核对状态 > 暂不可用（兜底）> 已连接

断线后不沿用旧会话的“已暂停 / 未选中”。
