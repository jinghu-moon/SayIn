# SayIn 接收页：三种连接场景

入口：[sayin-receive.html](sayin-receive.html)。直接在浏览器打开，顶部可切换初次连接、已连接、再次连接，以及相应的状态、中英文和明暗主题。顶部场景选择与页面下方的「交互演示」用于原型评审，不是生产界面的功能。

## 最新设计方向：双端统一三种连接场景

本次按用户确认的三类使用场景重写 HTML，移除未被认可的三列图标教程。三类场景共享页头、设备名称和历史样式，但不共用一套教程布局。

| 场景 | 电脑端设计 | 手机端协作意图 |
| --- | --- | --- |
| 初次连接 | 左侧说明扫码与电脑批准，右侧直接展示邀请；二维码/配对码在同一区域横向切换；待批准时原位显示 Redmi K40 和拒绝/批准操作 | 手机发起配对，等待电脑本地明确批准 |
| 已连接 | 紧凑设备行、独立接收开关、最近记录；没有连接教程或重复配对按钮 | 重点转向输入与发送 |
| 再次连接 | 展示已保存授权的设备、等待手机连接及简短说明；仅在需要时打开连接帮助；接收待命单独控制 | 使用已配对电脑恢复连接，无需再次扫码或批准 |

初次连接从建立信任开始；再次连接复用现有信任。三类是使用场景，不要求生产应用拆成三个页面。手机 UI 将在后续重新设计，本 demo 不写死当前手机页面名称和按钮位置。

## 状态与交互

### 网络流程简化（2026-11-13 更新）

用户确认项目遵循第一性原理、奥卡姆剃刀，并要求软件尽可能减少用户选择。接收页的必要任务是建立手机身份信任、接收文字、向当前光标输入；网络接口和 Windows 网络分类是实现条件，不应默认成为用户的配置任务。

因此取消上一轮拟议的「选择网卡 → 勾选公用网络许可 → 开始连接」流程。新的原型方向：

- 正常路径自动选择局域网；公用、专用网络使用相同界面，不额外要求应用内公用网络授权。
- 首次使用直接显示邀请，手机扫码或改用配对码后，在电脑本地批准；已有设备等待重连，不重复配对。
- 常态页面不增加独立网络卡片、网络设置开关或网卡选择器。网络详情收进已有的连接帮助/使用说明，Windows 分类只作详情信息。
- 切换网络后等待手机自动重连，不询问是否信任新网卡，也不清空设备身份。用户主动暂停、待核对和存储等输入阻断保持原样。
- 无可用网络时显示简短原因与「重新检测」。demo 中检测按钮不会假装联网；通过单独标记为演示的「网络恢复」按钮改变示例状态。首次使用恢复后显示邀请，已有设备恢复后等待重连。
- Windows 防火墙是独立系统条件。软件不能绕过它，也不自动修改系统网络分类或防火墙。手机的加密认证与电脑本地配对批准仍需保留。

顶部「网络」下拉仅为评审控件，提供专用、公用、网络切换与无网络四种示例；不会进入原生产品主流程。网络状态独立于接收开关和输入问题，连接恢复不会清除待核对状态或自动补输历史文字。

**原生实施：** 电脑端已按此方向重构，见 [29 接收页重构](../29-desktop-receive-ui-refactor.md)。自动选择、监听启动、范围监测和恢复均同步调整，11 的会话许可流程已删除。手机端尚无 mDNS，自动恢复监听不代表手机能发现变化后的 IP/端口。

### 接收与配对

原型用 `stage` 表达三种场景，`phase` 表达初次配对的邀请/批准/过期，`paused` 表达接收闸门，`issue` 表达输入阻断，`network` 表达网络示例；接收记录单独保留结果。这些维度分别管理，避免以连接成功替代输入授权。

- 初次连接：二维码与配对码通过 240ms 横向平移切换；二维码向左退出、配对码从右侧进入，返回时反向。配对码使用无边框、无白底的数字与地址排版，不套用二维码方框。分别标明「8 位配对码」和「电脑地址与端口」，两项值均使用 Consolas/Cascadia Mono 等宽字体，标签沿用界面字体。切换保留同一视口与面板高度，不再向下展开；操作按钮保持焦点。非当前面板使用 inert 和 aria-hidden 排除键盘与辅助技术访问；减少动态效果模式立即切换。扫码/配对码 → 手机发起申请 → 电脑拒绝或批准。演示按钮明确位于原型操作区，不把打开教程当作连接成功。批准后显示已连接及空记录，不生成虚假的接收消息。
- 已连接：接收开启/暂停可切换。held、uncertain、网络及存储问题按原因提供操作，不提供绕过阻断的普通开启按钮。
- 再次连接：默认展示已待命，也可提前暂停。点击明确标记的重连演示后保留暂停、uncertain、held 和存储阻断；无网络时先演示网络恢复，再演示手机重连，不直接重置为可输入。
- uncertain：必须在电脑弹窗勾选已核对原文后才能恢复新文字接收，原记录仍为待核对，不重发旧文字。
- held：过期演示保留原文与原始原因，不补输，并将接收保持暂停；过期记录明确未执行输入。
- 语言和主题切换不改变原文、连接场景、接收开关或记录状态。弹窗支持 Tab、Escape 及关闭后的焦点恢复。

场景与状态控件专门用于评审。选择无网络或网络切换后，已连接场景回到等待重连，界面显示实际示例状态；不把顶部评审控件当作产品设置。

## 视觉与设备名称

沿用 `sayin-history-card.html` 的品牌色 `#1f75db`、neutral、间距、圆角及 Yue 明暗反馈颜色值。图标继续使用本地 Yue 的 Tabler outline。原型设备示例改为 **Redmi K40**；它是已经实测确认的商品名称，但 HTML 使用示例数据，不直接读取手机。真实名称获取与已有配对名称刷新见[设备显示名称方案](../24-android-device-display-name-plan.md)。

初次连接采用单一分栏面板，让说明与邀请形成清楚的操作关系。常态接收及再次连接采用较紧凑的设备卡，不使用横向图标流程图。邀请以外的状态不显示二维码。

二维码为完整 PNG，内容是保留域名 `https://example.invalid/sayin-design-preview`，不包含配对密钥或真实邀请；界面明确标记示例。41 个模块（含四模块静区）×5px，原图和默认 DPR 1 显示均为 205×205，使用最近邻像素显示。不能将本示例接入真实配对；原生实现仍需按物理像素/DPI计算整数模块。

最近记录延续正文、收据状态、元数据和复制操作的层级；详情按需展开。`submitted` 只表述已提交输入事件，不声称目标应用已落字。历史中的目标来自示例执行记录，不代表下一条消息的输入位置。

详情入口统一为 Tabler `dots-vertical`。Windows Terminal 示例使用 `terminal-2` 表达目标应用；这是原型示意图标，不是从系统 exe 提取的真实图标。原生历史继续使用既定的 `win-icon-extractor`。

## 验证

执行命令：

```powershell
python scripts/verify_sayin_receive_demo.py
```

需本机 Python Playwright 与 Chromium。验证脚本已保存到仓库，结果见 [verification JSON](sayin-receive.verification.json)，包含被验证 HTML 的 SHA-256。

- 90 项检查：原有配对、接收、键盘、语言及原文保护回归，加上公用网络无额外决策、首次无网络隐藏邀请、网络恢复不重复配对、保留暂停/待核对/held/存储阻断，以及详情入口焦点恢复。
- 324 组布局：原有 180 组场景状态布局，加上 144 组网络状态及详情弹窗（3 场景 ×4 网络示例 ×2 语言 ×2 主题 ×3 尺寸）。窗口尺寸为 1280×860、800×640、480×760，检查横向溢出、文案、图片、图标及按钮名称。
- 英文 20px 根字号下额外验证三种场景；浏览器运行错误为 0。已查看实际 Chromium 的初次连接、已连接、再次连接及英文深色窄窗口渲染。
